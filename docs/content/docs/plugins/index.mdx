---
title: "Everything is a plugin"
description: "One registry, one manifest shape and one picker for every pane kind"
---

Every pane kind comes from one plugin registry, with one manifest shape and
one picker. Some plugins are native code inside the app; the rest are small
web pages ([Plugin UI](/docs/plugins/plugin-ui)).

| Plugin | Kind | UI | JavaScript | How herdr marks the pane |
|---|---|---|---|---|
| `terminal` | core | native terminal (libghostty) | none | none (the default) |
| `agent` | core | native terminal + chat view ([Chat view](/docs/chat-view)) | none | none (herdr sets `pane.agent`) |
| `web` | core | native web view | none (only the page's own) | label `web:<url>` |
| `git-history`, `diff`, `markdown` | core | a web page in a native web view ([Plugin UI](/docs/plugins/plugin-ui)) | yes, the public API | label `oriel:…` ([Labels and instance ids](/docs/plugins/labels)) |
| your plugins | installed | a web page in a native web view | yes, the public API | label `oriel:…` |

- Core native plugins have a manifest in the app bundle with a `native` field
  (`terminal`, `agent`, `web`) instead of an HTML entry. The picker reads their
  title, icon and argument prompt like any plugin. A terminal costs no
  JavaScript.
- Core plugins ship with the app. The three web core plugins use exactly the
  public API and are reference code for plugin authors.
- A web or plugin pane is a real herdr pane with a label. In herdr it runs a
  quiet placeholder command, so herdr TUI users see what the pane is. The
  placeholder is cosmetic: the label is the truth
  ([Labels and instance ids](/docs/plugins/labels)).
- herdr's own TUI plugins are not part of this system. A pane that a herdr
  plugin opened shows as a terminal, because it is one.
