---
title: "Pane kinds and plugins"
description: "Terminal, agent and web page are built in; every other pane kind is a plugin"
---

One picker makes every pane kind. Terminal, Agent and Web page are built into
the app. Every other pane kind is a plugin: a small web page
([Plugin UI](/docs/plugins/plugin-ui)) from one plugin registry.

| Pane kind | Kind | UI | JavaScript | How herdr marks the pane |
|---|---|---|---|---|
| Terminal | built in | native terminal (libghostty) | none | none (the default) |
| Agent | built in | native terminal + chat view ([Chat view](/docs/chat-view)) | none | none (herdr sets `pane.agent`) |
| Web page | built in | native web view | none (only the page's own) | label `oriel:web#<iid> <url>` |
| `git-history`, `diff`, `markdown` | core | a web page in a native web view ([Plugin UI](/docs/plugins/plugin-ui)) | yes, the public API | label `oriel:…` ([Labels and instance ids](/docs/plugins/labels)) |
| your plugins | installed | a web page in a native web view | yes, the public API | label `oriel:…` |

- The picker shows Terminal, Agent ▸ and Web page as fixed rows, then one row
  per plugin manifest: core plugins first, then linked and installed ones.
- Core plugins ship with the app. They use exactly the
  public API and are reference code for plugin authors.
- A web or plugin pane is a real herdr pane with a label. In herdr it runs a
  quiet placeholder command, so herdr TUI users see what the pane is. The
  placeholder is cosmetic: the label is the truth
  ([Labels and instance ids](/docs/plugins/labels)).
- herdr's own TUI plugins are not part of this system. A pane that a herdr
  plugin opened shows as a terminal, because it is one.
