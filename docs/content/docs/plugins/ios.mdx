---
title: "Plugins on iOS"
description: "The same plugins run on iOS; v1 ships the core ones"
---

- Plugins are web pages, and WebKit is on iOS, so the same plugin runs on the
  iPhone and iPad from day one.
- v1 ships the core plugins on iOS (Terminal, Agent, Web page, Git history,
  Diff, Markdown), inside the app. That is ordinary code shipped with the app.
- A label for any other plugin shows the missing-plugin card with **Show
  placeholder** (switch the card to the pane's terminal)
  ([State and restore](/docs/plugins/state)).
- Later, behind a setting that is off by default: the phone reads the plugins
  from the Mac over the SSH connection it already has, keeps them in memory,
  and asks for consent again. App Store guideline 2.5.2 makes downloaded code
  a review risk (guideline 4.7 allows HTML5 and JavaScript plug-ins, with
  conditions), so this waits until v1 has shipped.
