title: "File Explorer and Git"
description: "The two default plugins: packages the app installs on first launch, each one card with Back and Forward"
---

Two plugins come with the app. **File Explorer** browses a folder
and shows its files: the tree, a text editor (File), a viewer for images,
PDF, audio and video (Preview), and Markdown (read, edit, source, side by side). **Git** shows a
repository: its changes with Stage, Unstage and Commit, Fetch, Pull and
Push, the history of every branch, and the diff of any change or commit.
One card moves between these places, with Back and Forward as in a browser.
Each is a herdr pane that runs a placeholder, as a browser pane is
([Browser](/docs/ui/browser)), and the app draws the card.

Both are plugin packages, `explorer` and `git`, that the app installs in
`~/.config/ovvi/plugins/` on first launch
([The default plugins](/docs/plugins/packages#the-default-plugins)). The
user or an agent can edit them and press Reload Plugin. They use only the
public [plugin API](/docs/plugins/api): the app draws the header rows from
their manifests, and the toast, the menus and Open With natively, and it
reads and writes files and runs git for them
([How the cards are built](#how-the-cards-are-built)). They work the same on
This Mac and on remote machines, with the limits in
[Remote machines](#remote-machines).

## The label

A plugin pane's herdr label is `ovvi:<plugin>#<iid> <arg>`
([Labels and instance ids](/docs/plugins/labels)). The argument is the place
the card shows, and it picks the card's page. A relaunch, a cold restart of
herdr or another device makes the card at that place. The instance state
file on the pane's machine keeps the rest: Git's commit message, the diff's
Side by Side, Word Wrap and its file list ([State](/docs/plugins/api#state)).

| Plugin | Label argument | Page | Title | Tab |
|---|---|---|---|---|
| `explorer` | a folder's absolute path, ending in `/` | the tree, rooted there | the folder's name | `File Explorer ovvi` |
| `explorer` | a file's absolute path | File, Preview or Markdown, by the file's name | the file's name | `File Explorer main.swift` |
| `git` | the repository's root, ending in `/` | the Git home | the root's name | `Git ovvi` |
| `git` | the root with its `/`, a space, then `uncommitted` or a commit hash | a diff | `Working Tree`, or the commit's subject (the short hash until the page has read it) | `Git Working Tree` |

- The tab and the floating window read "‹name› ‹title›", the title in
  secondary text, as a terminal tab's "zsh ovvi"
  ([Tab bar](/docs/ui/window#tab-bar)). A path with a control character, or
  over 1024 characters, makes no label, so nothing opens.
- The words of the kinds before the plugin system still open: `file`,
  `preview`, `markdown` and `files` open a File Explorer, and `diff` opens
  Git. An old `files` label names its root without the `/`, and it still
  opens the tree. An old `diff` label (`<root> <source>`) still opens its
  diff. The root's `/` keeps a root whose last word looks like a hash
  (`My Project abcdef0`) a home.
- The placeholder prints the plugin's name, the argument and "Shown in Ovvi"
  in the middle of the pane in herdr's TUI, and follows the label when it
  changes
  ([In herdr's TUI](/docs/ui/browser#in-herdrs-tui)).
- Each move in the card renames the pane to the new place, so a reload or a
  card made again comes back there. A new argument from elsewhere (an
  agent's `herdr pane rename`) is a new place in the card, after the one it
  shows. A name that breaks the label turns the card back into a terminal.
  Reset Pane Name is disabled.
- The card's program icon is an SF Symbol on the neutral tile. A File
  Explorer's follows its page: `folder` (the tree), `doc.text` (File),
  `photo` (Preview) or `doc.richtext` (Markdown). Git's is
  `source.branch`, the app's own symbol: Material Design Icons'
  `source-branch`, the shape of pi-footer's branch. The sidebar's branch
  uses it too.

## Ways in

- **File Explorer and Git** are rows of the [New pane](/docs/ui/new-pane)
  chooser, under Browser (their manifests' `chooser`), and the commands **Open File Explorer Here** and
  **Open Git Here** (File menu, the card's menu, the palette). Both take the
  root of the git repository that the pane's folder is in (`git rev-parse
  --show-toplevel`), else the folder. File Explorer opens on the tree, and
  Git on its home. They replace the pane with Replace Pane's steps, as
  Browser does ([Create](/docs/ui/browser#create)).
- Everything else opens from inside a card: a file from the tree, a diff
  from the Git home, a file from a diff or from a Markdown link
  ([Opening](#opening)).

## Opening

Everywhere a plugin card opens a file, a folder or a diff, the same gestures
apply:

| Gesture | Where it opens |
|---|---|
| a click, or a double-click or ⌘O in the tree | in the card itself, as its next place ([Back and Forward](#back-and-forward)) |
| ⌘-click | in a new herdr tab at the end of the card's workspace, in the background |
| ⌥-click | in a pane to the side of the card, in the background |

- A right click on a row of the tree or of the Git home shows the app's own
  menu: **Open** (**Open as Root** on a folder), **Open in New Tab** and
  **Open to the Side**.
- **In the background** means that the selected tab and the keyboard stay
  where they are: a ⌘-click or ⌥-click on one file after another opens each
  one, and the card keeps the keyboard. The right-click menu's **Open in New
  Tab** and **Open to the Side** open in the background too. Any other open in
  a new tab (a Git diff's **Open File**) selects it.
- **A new tab** opens at the end of the card's workspace, on the same
  machine, also from a floating window. Unless it opens in the background,
  the app selects the new tab and gives its card the keyboard. The call is
  `layout.apply` for a new tab with the labeled pane. herdr adds the tab last
  ([Writes are herdr calls](/docs/talking-to-herdr#writes-are-herdr-calls)).
- **To the side** makes the pane in a new tab, then moves it beside the
  card (`pane.move`), as Replace Pane does, because herdr's split runs no
  command. The new tab can show for one snapshot.
- A place of the other plugin (a file from a Git diff) always opens in a new
  tab or to the side, never in the card.

| From | Gesture | Opens |
|---|---|---|
| the tree: a file | double-click, ⌘O or ⌘↓ | the file, with its page |
| the tree: a folder | double-click, ⌘O, ⌘↓, ⌘-click, ⌥-click, or Open as Root | the tree rooted there |
| a file's **Show in File Explorer** | click | the tree of the file's folder, with the file selected |
| the Git home: a change | click | the Working Tree diff, scrolled to that file |
| the Git home: **Working Tree** | click | the Working Tree diff |
| a commit's page: a parent | click (⌘: a new tab, ⌥: to the side) | that parent's diff |
| the Git home: a commit | double-click or Return (a click selects it) | the diff of that commit |
| a diff's **Git Home** | click | the Git home |
| a diff: a file header's **Open File** | click (⌥: to the side) | the file in a File Explorer, in a new tab |
| a diff: a line | ⌘-click (⌥: to the side) | the file in a File Explorer, with the caret on that line |
| Markdown (Read): a relative link or image | click | the file, with its page |
| Markdown (Read): an `http` or `https` link | click (⌥: to the side) | a browser pane in a new tab |

- **Which page opens a file**, by its name alone (a remote file is not read
  first), from the lists in the plugin's `places.json`: `.md`, `.markdown`
  and `.mdx` open Markdown. Images, PDF, audio and video open Preview. Known
  kinds that are not text (archives, Office documents, fonts, disk images)
  open Preview's info view. Everything else opens File: a name with no
  extension (`Makefile`), a name the system does not know (`.rs`), `.ts`
  (TypeScript, not an MPEG-2 stream) and `.plist`. File shows the info view
  for a file that is not UTF-8.
- Another plugin with a pattern for a file takes it from File Explorer,
  whose pattern is `*` ([Which plugin opens a file](/docs/plugins/manifest#which-plugin-opens-a-file)).
- A landing (a line, a diff's file, the row to reveal) is used once, by the
  page's first load. It is not in the label, so a relaunch opens at the top.
- A browser pane opened from Markdown follows the browser's load rule: a page
  that is not approved or on the safe list asks **Open this page?** first
  ([When a page loads by itself](/docs/ui/browser#when-a-page-loads-by-itself)).

## Back and Forward

- **Back** (`chevron.left`, ⌘[) and **Forward** (`chevron.right`, ⌘]) sit at
  the left of row 2 on every page. The app draws them and keeps the list,
  because both manifests say `"history": true`
  ([One plugin, many places](/docs/plugins/api#one-plugin-many-places)).
  They walk the card's own list of places, as a browser's history does. A
  new place clears the places after the current one.
- **Kept pages.** Each card keeps the last five places it showed as pages
  ([One plugin, many places](/docs/plugins/api#one-plugin-many-places)). So
  Back and Forward show a place at once, as the user left it: its scroll, its
  open folders, its selection, its filter, its file list and its row 2. A kept page reads
  again only what changed on the machine while it was hidden, after it
  shows. A place not kept draws in a new page while the old one stays on
  screen.
- Back to the tree shows the row of the file it opened, and scrolls only when
  that row is out of view.
- A Git home drawn anew (not kept) lands at the change or the commit that
  the card came back from.
- ⌘[ and ⌘] move the card only while it has a place that way. Otherwise
  they select the pane to the left or right, as elsewhere. ⌘← and ⌘→ also
  go Back and Forward, as in a browser, except in a text field such as the
  editor, where they move the caret. A card made from
  its label (after a relaunch, or a dropped card shown again) has no list
  yet.
- **Unsaved edits ask first.** Back, Forward, an open in the card or a close
  (of the pane, its tab or its workspace) from a file with unsaved edits
  shows its tab and the toast "‹name› has unsaved edits." with
  Discard and **Keep Editing**. A new place from elsewhere drops the edits
  without a question.

## The card

- **Row 1** (36 pt), as on a terminal card: the page's symbol (16 pt,
  secondary), the title (cut in the middle when it does not fit), the
  Edited dot when there are unsaved edits, then the card buttons on the
  keyboard card and on a hovered card ([Pane card](/docs/ui/window#pane-card)).
- **Row 2** (32 pt) holds Back and Forward, then the page's controls,
  described per page below. The app draws it from the manifest's `header`
  ([Header](/docs/plugins/manifest#header)): every place's controls start
  hidden, and the page shows its place's. So a new card shows only Back and
  Forward until its page runs, a moment. It starts at the row's left edge
  and ends where row 1 does. Its buttons are 22 × 22 pt in the card buttons'
  color.
- **Content.** The page fills the card under the header, 10 pt in from the
  card's sides and bottom. The card's own fill shows through the page.
- **The loader.** Until the page drew its first rows or its file
  (`card.ready()`), the app's small spinner shows in the middle of the card,
  from 150 ms on. On first launch, while the app installs the plugin, the
  card shows "Installing ‹name›…".
- **The card's menu** adds **Reload Plugin** (⌥⌘R), **Show Web Inspector**
  and **Show Log** ([Build a plugin](/docs/plugins/building#debug-it)).
- **A floated plugin pane** keeps row 2 under the floating window's title
  row, from its left edge. The title row shows "‹name› ‹title›" and the
  Edited dot ([Floating pane](/docs/ui/window#floating-pane)).
- **Overview tile.** The tile shows the card's last picture
  ([Overview](/docs/ui/window#overview)). A tile watches no file. The card
  catches up on what changed when it shows again.
- **Kept and dropped.** The window's `PaneViewRegistry` keeps each card by
  terminal id, so a card scrolled away or moved keeps its page, its edits,
  its scroll and its Back and Forward. Out of view, the 25 most recently
  shown web cards stay (plugins and browsers together). An older one is
  dropped, keeps its last picture, and is made again from its label and its
  state file when it shows
  ([What stays in memory](/docs/ui/browser#what-stays-in-memory)). A
  card with unsaved edits and a floated card are never dropped.
- A plugin card takes the keyboard as a browser card does. Its page cannot
  take the keyboard by itself, also on a refresh or when its tab shows again
  ([What each part does](/docs/plugins/api#what-each-part-does)).

## Edits, saves and reloads

File and Markdown edit the file. Both use the same editor and the same rules.
The caret has the text's color: white in dark, black in light.

- **The Edited dot.** A 7 pt dot in secondary after the title, centered on
  the title's x-height as in a document window, while the text differs from
  the text on disk. Its tooltip and VoiceOver say "Edited". Undo back to the
  disk's text removes it.
- **⌘S** saves. It writes nothing when there are no edits. The save checks
  the file's hash (`cksum`) from the last read or save. If the file on disk
  did not change since, the app writes a new file beside it and moves it over
  the old one, so a save is never half written. A link is written through and
  stays a link. A CRLF file saves as CRLF.
- **A change on disk** while the card shows: a clean file reloads in place.
  Only the changed middle of the text is replaced, so the caret and the
  scroll stay. A dirty file keeps the user's text and shows the toast.
- **The toast** is one line on a glass capsule at the top of the card, 6 pt
  under the header, with two small round buttons. The buttons sit 7 pt
  inside the capsule's top, bottom and right edge, so their curves follow
  its curve. The second button is the default. It slides in over 0.15 s. A
  button's action ends it. A button that deletes or discards work is red:
  the main button with the toast's `destructive` option in the plugin API.

  | When | Text | Buttons |
  |---|---|---|
  | the file changed on disk and the card is dirty | "‹name› changed on disk." | Reload, **Keep Mine** |
  | ⌘S, and the file changed on disk since the last read | "‹name› changed on disk since you opened it." | Overwrite, **Reload** |
  | the save failed | "‹name› was not saved: ‹reason›" | Cancel, **Try Again** |
  | Back, Forward, an open in the card or a close with unsaved edits | "‹name› has unsaved edits." | Discard (red), **Keep Editing** |
  | a Git write failed | git's message, on one line | Copy, **OK** |
  | Git's Revert or Revert All | the question (see Writes) | Cancel, **Revert** (red) |

  Keep Mine takes the disk's new hash, so the next ⌘S writes over that
  version without a question. Reload drops the edits.
- **Read only.** A file over 4 MiB on a remote machine opens read only.
- **Not text, too large.** A file that is not UTF-8, or one over 16 MB,
  shows the info view: the system's icon for its type, its name, its kind
  and its size.
- Preview reloads its file on a change too. The tree, the Git home and an
  Working Tree diff follow their folder.

## Open With

File, Preview and Markdown have **Open With** at the right end of row 2 (the
manifest's `openWith` control). It is a button with the icon and the name of
the file's default app: a click opens the file in that app. Its menu lists the default
app first, then a divider, then the other apps that open the file, each with
its icon (`NSWorkspace`), then the other plugins that open the file. A pick
of a plugin turns the card into that plugin's card. A file with no default
app shows a plain "Open With" menu. The Mac's apps show on This Mac only: on
a remote machine, Open With shows only when another plugin opens the file.
Before it (and before Markdown's mode), **Show in File Explorer**
(`list.bullet.indent`) shows the tree with the file's folder as its root, the
file selected and scrolled into view.
Back returns to the file.

## A file's row 2

File, Preview and Markdown share one row 2, with the same order, spacing and
22 pt buttons:

- **On the left:** Back and Forward, the outline toggle (Markdown only, and
  only while the file has a heading), then the breadcrumbs.
- **On the right:** Preview's page and zoom, Show in File Explorer, the mode
  (Markdown only), then Open With.
- **The breadcrumbs** are the file's path, its parts with `›` between them
  and the first part in secondary text. Inside a Git repository the path
  starts at the repository's root, with the root's name first
  (`ovvi › Ovvi › App › OvviApp.swift`). Outside one, it starts at the home
  folder (`~ › Downloads › photo.png`), else at `/`. The breadcrumbs are cut
  in the middle when the row is narrow.

## File Explorer

### The tree

The tree of the root (`@pierre/trees`), in the style of Finder's list and
Xcode's navigator: a thin disclosure chevron, folders in the Finder's folder
blue (the same in light and dark), files with an icon for their type in its
color (TypeScript, Swift, Markdown, JSON, images, and so on), 24 pt rows, the
selection in the accent at 24 %. A 6 pt gap sits under the header.
- **Row 2:** Back and Forward, the root (it takes the rest of the row), then
  three icon buttons: **Filter** (`magnifyingglass`, in the accent while the
  find bar shows), **Collapse All** and **Show Hidden Files** (`eye`).
- **The root** is a path field, like the browser's address. At rest it shows
  the root's path with the home as `~`, cut at the start when it is long
  (`…ode/ovvi`). A click shows the whole path, selected. Return goes there,
  with `.`, `..` and `//` resolved: the tree rooted at that folder becomes the
  card's next place. A path that is no folder makes the field shake (a beep
  with Reduce Motion); the typed path stays. Esc puts the root back. A path
  that does not start with `/` (or `~` on This Mac) goes from the root, so
  `src` or `..` works, and an empty one is the root. The folder icon before the path is **Choose Folder…**: the folder
  panel on This Mac, a "Go to Folder" field on a remote machine (`~` is the
  home folder there). A folder's own menu has **Open as Root**.
- **`..`** is the tree's first row, except at `/`. It is a folder row like
  the others: a click selects it, a double-click (or ⌘O, or a VoiceOver press)
  makes the parent folder the root, and its menu has **Open as Root**. It
  scrolls away with the rows, and hides while the filter has text.
- **Sticky folders.** When the tree scrolls, each open folder above the view
  stays at its top, nested, until its last row scrolls past, as in Xcode's
  navigator. So the folders the rows are in always show.
- **The tree** shows the root's listing first and lists a folder only when
  it opens. `.git` is hidden, and links to folders are folders. Files and
  folders whose name starts with `.` show only while Show Hidden Files is on.
  Its value stays with the card. Git's letters come after the first rows,
  from one `git status`, so a folder never opened still shows a dot for a
  change inside. A folder shows the dot only for a change in `git status`
  under it, never for the files git ignores. A listing asks git only which
  of its own names git ignores (`git check-ignore`), and those are dimmed.
  Modified is the needs-you color, added, untracked and renamed the finished
  color, and deleted the error color. A root inside a repository, but not its
  root, shows no letters.
- **An empty folder** shows a folder icon and "This folder is empty" in the middle of the card.
- **The find bar** floats at the tree's top right, as the terminal's ⌘F bar
  and the editor's do: a capsule with the field ("Filter"), the number of
  matches and a close button. The rows do not move under it. It
  opens with row 2's Filter, with ⌘F, or when the user types a letter in the
  tree, which goes into the field. Esc, the close button or a second click on
  Filter closes it and clears the filter. Return or ↓ in the field moves the
  keyboard to the matches.
- **The filter** matches file names, case blind, and shows the matches with
  their folders open, at most 5,000. The first letter loads every path under
  the root: in a repository the files git does not ignore (`git ls-files`),
  else every file, up to 8 MB of names. When none match, the middle of the
  card shows a magnifying glass and "No matching files". A tree that draws
  anew starts with no filter. A kept one keeps its find bar and filter, and
  when it shows again the field does not take the keyboard.
- **Opening.** A double-click on a file shows it in the card. As in
  the Finder, a click on a folder's name only selects it, and a click on its
  chevron opens or closes it. So a double-click on a folder makes it the root,
  and the folder does not open first. ⌘ and ⌥ open as in
  [Opening](#opening).
- **The selection.** A click on no row clears the selection, and so does a
  click on a row 2 button. While the tree does not have the keyboard (the
  path field, the find bar or another card has it), the selection shows in
  gray, as in the Finder.
- **Keys.** The tree has the keyboard when the card opens or gets the
  keyboard, never by itself (a refresh, a tab shown again). The row with the
  keyboard has a ring in the accent from the first arrow key on. A click
  hides the ring again. The keys follow Finder's list view:

  | Key | Does | Finder |
  |---|---|---|
  | ↑ ↓ | move; the first ↓ on a tree with no selected row goes to the first row, the first ↑ to the last | the same |
  | → ← | open and close a folder; ← on a closed row goes to its folder | the same |
  | Return | renames the selected row in place, its name selected without the extension: Return saves, Esc cancels. A name in use, an empty one or one with `/` keeps the old name and says why in a toast | the same |
  | ⌘O, ⌘↓ | open the selected row: a folder becomes the root, a file shows in the card | the same |
  | ⌘↑ | the parent folder becomes the root | the same |
  | ⌘← ⌘→, ⌘[ ⌘] | Back and Forward | ⌘[ ⌘] |
  | a letter | opens the find bar with that letter | jumps to the first name with it |
  | Space | nothing: there is no preview card | Quick Look |
  | ⌘⌫ | nothing: the plugin API has no Trash | Move to Trash |
  | ⌘D | Split Right, the app's key | Duplicate |
  | Esc | closes the find bar | the same in the search field |
  | ⇧↑ ⇧↓ | extend the selection | the same |
  | ⌘-click | opens in a new tab ([Opening](#opening)) | adds to the selection |

- The tree and the letters update after each change under the root while
  the card shows. The open folders list again. A root that cannot be listed
  shows "Can't list ‹root›" in the middle of the card, under a folder icon.
- **The Git status bar.** A one-line bar under the tree, only while the root
  is inside a Git repository: the branch, the number of changes in the
  repository (in the needs-you color, none when it has none), then ↑2 ↓1 when
  the branch is ahead of or behind its upstream. At its right end, **Open in
  Git** (`source.branch`) opens Git's home on that repository in a new tab at
  the end of the workspace. It updates with the tree's letters, after each
  change under the root, with no polling of its own. A folder outside a
  repository has no bar.

### File

An editable text view (CodeMirror 6).
- **Row 2** ([A file's row 2](#a-files-row-2)): the breadcrumbs end with the
  scopes around the caret, outermost first, after a `curlybraces` glyph
  (`ovvi › Ovvi › App › OvviApp.swift › {} OvviApp`).
- **Text:** line numbers, the current line lit, bracket matching, the other
  matches of the selection marked, undo and redo, and Tab to indent. Lines
  wrap, because cards are often narrow. A wrapped line goes on at its own
  indent.
- **Colors** for Swift, TypeScript, JavaScript, Python, Go, Rust, C, C++,
  Java, Kotlin, Ruby, shell, JSON, YAML, TOML, HTML and CSS, by extension.
  The colors are the diff's: Pierre Light and Pierre Dark, the default
  Shiki themes of `@pierre/diffs` (`@pierre/theme`). Each
  language loads the first time a card needs it.
- **Symbols** come from the language's syntax tree (functions, classes,
  types, methods, JSON and YAML keys, CSS rules). Swift, Kotlin, Ruby, shell
  and TOML have no syntax tree in CodeMirror, so their symbol is the
  declarations above the caret with a smaller indent.
- **Find** (⌘F) opens the find bar, as the terminal's: a capsule at the
  top right of the text, over it, with the field, the match count ("3 of
  12"), three toggles (Match Case, Whole Word, Regular Expression, in the
  accent while on), Find Previous, Find Next and Close. The first match
  from the selection is selected as you type. Return and ⇧Return, ⌘G and ⇧⌘G
  step through the matches. A match scrolls into view below the bar. Esc
  closes it. **⌥⌘F** (Find and Replace, taken by the page: the menu has no
  item for it) adds a second row with the Replace field, **Replace** and
  **All** (Replace All); Return in the field replaces, ⌘Return replaces
  all. A read only file shows the find row only. Markdown has the same bar.

### Preview

- **Row 2** ([A file's row 2](#a-files-row-2)): before Show in File
  Explorer, the page as "3 of 12" for a PDF, and zoom for images and PDFs
  (Zoom to Fit, Actual Size, Zoom Out, Zoom In).
- **Images** (PNG, JPEG, GIF, WebP, HEIC, TIFF, BMP and SVG), centered and
  scrollable. Fit shrinks a large image to the card and never enlarges a
  small one. Zoom In and Zoom Out step by a factor of 1.25, from 5 % to
  1600 %.
- **PDF** in pdf.js's viewer: pages draw as they scroll into view, Fit is the
  page's width, and the page number follows the scroll.
- **Audio and video** in WebKit's player.
- **Any other file**, and one that WebKit or pdf.js cannot decode, shows the
  info view. So does a file over the 16 MB cap.

### Markdown

- **Row 2** ([A file's row 2](#a-files-row-2)): the outline toggle
  (`sidebar.left`, in the accent while the outline shows) after Back and
  Forward, and the mode menu before Open With. The menu shows the mode's
  symbol, with its name as the tooltip.
- **Four modes**, picked in the menu:

  | Mode | Symbol | What it shows |
  |---|---|---|
  | **Read** | `book` | the file rendered, read only |
  | **Live Edit** | `pencil` | the file rendered, editable, the caret's lines in Markdown |
  | **Source** | `chevron.left.forwardslash.chevron.right` | the whole file as File draws code: monospace, line numbers, Markdown's colors |
  | **Side by Side** | `rectangle.split.2x1` | Source on the left, Read on the right |

  The card keeps its mode: another Markdown file in the card, Back and
  Forward, and a relaunch show the mode last picked.
- **Read and Live Edit are one view.** Both are the same editor (CodeMirror
  with Markdown, GitHub's flavor), drawn as rendered Markdown: a live
  preview. It is a 640 pt column, 28 pt under row 2, in the system font 1 pt
  larger than the text size. So a switch moves nothing on screen but the
  caret's line. A switch to or from Source keeps the line at the top in
  place.
- **Read** is the view with every line drawn and no caret. It draws
  CommonMark and GitHub's flavor (GFM). The fixture
  `resources/research/ui/markdown-syntax.md` holds every construct.
  - **Marks** are hidden: a heading's `#`, a setext heading's underline,
    emphasis, a link's brackets and address, code ticks, quote marks, code
    fences, an indented code block's indent, and the backslash of an escape
    or a hard break.
  - **Paragraphs flow.** A line break in the source is a space, so the text
    wraps at the column's width. A hard break (two spaces or a backslash at
    the line's end) starts a new line.
  - **Headings** have their size and no line under them: only a `---` rule
    draws a line.
  - **Lists.** Bullets are `•`. Numbers count up from the list's first one, so
    `1. 1. 1.` shows 1, 2, 3, and `1)` shows `1.`. Each list depth indents
    1.5 em, and the bullet sits at the end of its indent. So the text, its
    wrapped lines and its later paragraphs start at one x.
  - **Task boxes** take the bullet's place: a top-level box starts at the
    text's left edge. A box is drawn by the page: 1.1 em square with a thin
    rounded border, centered on the line's lowercase letters. Ticked, it fills with the
    accent and shows a white check.
  - **Links.** Inline links, reference links (`[text][ref]`, `[ref][]`,
    `[ref]`), autolinks and bare addresses are links in the accent. A
    reference's definition line is hidden. `www.` addresses open with
    `http://`, e-mail addresses with `mailto:`. Images are not loaded: their
    alt text is a link to the image.
  - **Footnotes.** A reference (`[^note]`) is a small raised number, by the
    order of the definitions. A click scrolls to its definition. A
    definition (`[^note]: text`, also when the text is only an address) stays
    where it is written, in smaller secondary text, after its number.
  - **Quotes** have a bar at the left for each depth, and secondary text. Each
    depth indents 12 pt.
  - **Code** blocks have a rounded fill. A `---` rule is a line.
  - **HTML.** Tables and HTML blocks are drawn by markdown-it. An element
    that opens in one HTML block and closes in a later one (a `<details>`
    with Markdown inside) is drawn as one. HTML comments draw nothing. Inline
    HTML elements of text (`<kbd>`, `<sub>`, `<sup>`, `<b>`, `<a href>` and
    the like) and `<br>` draw as themselves. Other inline tags show as
    written. Entities (`&copy;`) show their character.
  - **Tables** size their columns to their content. Words wrap only when the
    table is wider than the column. A word wider than the column scrolls the
    table sideways. Code in a table uses the app's monospace. A table or an
    HTML block in a list item starts at the item's text.
  - **Front matter** shows as YAML in 12 pt monospace, secondary.
  - Copy gives the Markdown source of the selection, and Select All the whole
    file. For VoiceOver, Read is an article with headings, not a text box.
- **Task boxes.** A click on a box ticks it or clears it: one character, `x`
  or a space, changes in the file. In Read the card saves it at once, as ⌘S
  does, with any edits not saved yet. In the other modes it is an edit like a typed one, saved with ⌘S. Undo
  takes it back. The boxes of a file that is read only are dimmed and do not
  change.
- **Live Edit** makes the view editable. The lines with the caret or the
  selection show their marks; every other line looks as in Read. The
  caret's line is its own source line: the lines of its paragraph above and
  below it still flow. A table, an HTML block, a
  setext heading's underline and a hidden definition or comment show their
  source while the caret is in them. A click on a table or an HTML block puts
  the caret there. A click in Read and then ⌘E keeps the caret where
  the click was.
- **Source** uses the code colors of File (Pierre Light and Pierre Dark):
  marks in the punctuation color, headings as tags, links and addresses in
  blue, code in the string color, quotes in the comment color, emphasis in
  italics and strong text in bold.
- **Side by Side.** Source and the rendered page split the card in halves,
  with a 1 pt divider between them. The two scroll together by source line:
  the side that the user last scrolled, clicked or typed in leads. A tick in
  the page edits the source. A
  small button on the divider (`chevron.right`, "Hide Preview") folds the
  page away, and Source takes the whole width; the button then sits at the
  right edge (`chevron.left`, "Show Preview").
- **⌘E** (View ▸ Edit Mode, checked in every mode but Read) switches between
  Read and the last edit mode (Live Edit at first). ⌘F, ⌘G, ⇧⌘G and ⌥⌘F in
  Read switch to the last edit mode, where the find bar is. Read closes the
  find bar.
- **The outline** is a 190 pt column at the left with the document's
  headings, indented by level. A file with no heading hides the toggle
  and closes the outline. The outline closes when the last heading goes. It slides in and out (0.25 s). A click
  scrolls to the heading and in an edit mode puts the caret on it. `#section` links
  scroll to the heading with GitHub's id. A second heading of the same name is
  `#section-1`.
- Links open from Read and Side by Side's page ([Opening](#opening)). A
  landing with a line opens the card's edit mode (the last one, from Read)
  with the caret on that line. A page that loads again has the outline
  closed.
- Dirty, ⌘S, the reload and the toast are as in
  [Edits, saves and reloads](#edits-saves-and-reloads).

## Git

### The home

The repository's state on one page, in the app's style: rows as the
sidebar's (28 pt, radius 7), SF Symbols drawn in the text's color, the
app's fonts and `Look` colors. From the top:

- **Row 2** (native): Back and Forward, the branch, **Working Tree**
  (`plus.forwardslash.minus`), then Fetch
  (`arrow.clockwise`), Pull (`arrow.down`, with the number of commits
  behind) and Push (`arrow.up`, with the number of commits ahead). Working
  Tree and the three are small bordered buttons with their symbol and word.
  When the row has no room for all four words, all four show their symbol
  alone. A button
  shows a spinner while its command runs. The three and the branch are
  disabled while one of them, a switch or Commit runs, and when git cannot
  read the repository. Working Tree is disabled only when git cannot read
  it.
- **The branch** is a menu button with `source.branch` and the
  checked-out branch. Its menu lists the local branches, the current one
  checked, then under "Remote" the remote branches that have no local
  branch. A pick runs `git switch <branch>`, or `git switch --track` for a
  remote one.
- **The commit message** field ("Message") grows to 5 lines, then scrolls.
  **Commit** beside it is on the accent when there is a message and a
  change, else gray. ⌘↩ commits too. Commit takes the staged changes
  (`git commit -m`). With none staged, the button reads **Commit All**: it
  stages everything (`git add -A`), then commits. The message is in the card's state, so it
  stays while the card moves to a diff and back, and over a drop, a reload
  and a relaunch. It empties after the commit.
- **Staged Changes** and **Changes**, each only when it has files: a header
  with its count and the words **Revert All** and **Unstage All** or
  **Stage All**, then one row per file: the file's icon by its type (File
  Explorer's icons and colors, from the same `@pierre/trees` package), its
  name, its folder in secondary, the Revert (`arrow.uturn.backward`) and the
  Stage (`plus`) or Unstage (`minus`) buttons that show under the pointer,
  and its letter in the tree's colors. A click opens the Working Tree diff
  at that file.
- **No changes:** with nothing to commit, the message, Commit and both lists
  give way to one placeholder: `checkmark.circle` and "No changes".
- **History**, 26 pt under the changes, after a hairline: the last 500
  commits of every branch, remote branch and tag,
  and HEAD, as a graph, newest first (`git log --branches --remotes --tags
  HEAD --topo-order`, not `--all`, which adds the stash and notes). Each row
  has its lanes and dot, its branch, remote branch (`cloud`) and tag (`tag`)
  capsules, the subject, the short hash and the date (a time today, else the
  day). The checked-out branch's capsule is on the accent, and HEAD's dot is
  a ring. The first parent stays in its child's lane, as in `git log
  --graph`. Lane colors cycle through the accent, finished, working,
  needs-you and error colors. "No commits yet" before the first commit. A
  full page ends with **Show More**, a plain gray button in the middle,
  which reads 500 more (`git log -n 1000`, and so on). The page ends 10 pt
  under the last row.
- **Selecting a commit** works as in File Explorer. A click selects a
  commit: its row takes the accent at 24 %. A double-click or Return opens
  its diff in the card. ⌘-click opens it in a new tab and ⌥-click to the
  side. ↑ and ↓ move the selection, and the first arrow selects the first
  commit (↑ the last). After an arrow key, the selected row has a 1.5 pt
  ring in the accent, until the next click. A click anywhere else clears
  the selection. The arrows do nothing while the message field has the
  keyboard. A refresh keeps the selection where it is and does not scroll.
- **Not a Git repository:** when the root is in no repository
  (`git.root` is null), the page shows `folder.badge.questionmark`, "Not a
  Git repository", the folder's short path (`~/…`) and **Initialize
  Repository**, which runs `git init` after the click. When git cannot read
  a repository or cannot run, the page shows git's message in the middle.
- The home reads again after each change under the root while the card
  shows (on This Mac also `.git`'s own: a commit or a fetch from a
  terminal), and after each write.

### Writes

- git runs on the card's machine through its `Exec`, as `env
  GIT_TERMINAL_PROMPT=0 git -C <root> …`, so nothing can ask for a password.
  Writes run one at a time, in order, because git takes `index.lock`. A
  network command (Fetch, Pull, Push, a switch, Commit) can take 120 s, the
  others 30 s.
- A failed write shows git's message in the card's toast, with **Copy** and
  **OK**.
- **Revert** asks first in the card's toast, with **Cancel** and **Revert**:
  "Revert changes to ‹name›? This cannot be undone." A new file (untracked,
  or added in the index) is deleted, so the question names it: "Delete the
  new file ‹name›? This cannot be undone." Revert All with more than one file
  asks "Revert all ‹n› files? This deletes the new file ‹name› (or files ‹names›). This cannot
  be undone." (three names at most, else two and "and ‹n› more"). Revert puts
  each file back as `HEAD` has it, in the index and the work tree, from
  either list, and the old path of a rename too. VoiceOver reads the two
  Revert All buttons as "Revert All Staged Changes" and "Revert All Changes".

| Control | Runs |
|---|---|
| Fetch | `git fetch --all` |
| Pull | `git pull`: the user's `pull.rebase` decides. Diverged branches with no setting fail with git's message |
| Push | `git -c push.autoSetupRemote=true push`: a branch with no upstream is published under its name (git 2.37 or later) |
| Stage, Stage All | `git --literal-pathspecs add -A -- <path>` (and the old path of a rename), `git add -A` |
| Unstage, Unstage All | `git --literal-pathspecs reset -q -- <path>`, `git reset -q` (also before the first commit) |
| Commit | `git commit -m <message>`; Commit All runs `git add -A` first |
| Revert, Revert All | `git restore --staged --worktree --source=HEAD` of the tracked paths, then `git clean -fq` of the untracked ones (`git ls-files --others --exclude-standard`), each with `--literal-pathspecs`. With a tracked path it fails before the first commit, with git's message, and deletes nothing |
| Initialize Repository | `git init -q` |
| a branch | `git switch <branch>`, `git switch --track <remote branch>` |

### Diff

The changes of one source in one scroll (`@pierre/diffs`).
- **Row 2:** Back and Forward, **Git Home** (`house`), then
  `Unified | Side by Side`, **Word Wrap** (`text.wrap`, the app's symbol
  from Material Design Icons' `wrap`, a toggle in the accent while on; Side
  by Side always wraps, so it is disabled there), the file list button (`sidebar.left`, its title
  Hide File List or Show File List), Previous Change (`chevron.up`) and Next
  Change (`chevron.down`). There is no source
  pop-up: another source opens from the home.
- **An 8 pt gap** sits between row 2 and the page, also while it scrolls: a
  file header sticks below it, and the file list's line starts below it.
- **Working Tree** (`uncommitted` in the label) is the staged, unstaged and
  untracked changes against `HEAD` (against the empty tree before the first
  commit), up to 16 MB of patch. It is a live view: while the card shows,
  each change under the root (an agent's edits) asks for the patch again.
  Only the files whose text changed draw again: every other file keeps its
  box, and the scroll stays where it was. With no changes it shows
  `checkmark.circle` and "No changes" in the middle, as the home does, with
  no file list and its button off, and fills as files change. **A commit** shows against its first
  parent.
- **A commit's page** starts with its subject (15 pt, semibold), its body,
  then Author (name and email), Date (relative, then the date and time),
  Commit (the short hash: a click copies the full one and says "Copied")
  and Parent or Parents (each short hash opens that commit). The subject is
  the card's and the tab's title (`document.title`), and VoiceOver reads it
  as the card's name. The text can be
  selected.
- **The scroll.** Each file is a box with 8 pt corners and a 1 px border in
  the divider's color, 8 pt from the next box and from the sides. The box's
  header is a 32 pt row with a hairline under it, opaque in the card's color
  (`--card`, `Look.cardSolid`, no blur) under a faint fill: a disclosure,
  the file's icon, the file's name in semibold, its folder in secondary
  ("from ‹old path›" for a rename), `+n −m` in the finished and error
  colors, its letter, a **Viewed** box and **Open File** (not on a deleted
  file). In a card under 480 pt the folder and the counts give way. Viewed
  folds the file and dims its row in the list. A folded file shows its
  header alone, with all four corners round; a fold whose header sticks at
  the top scrolls back to the box's top. A refresh keeps each file's fold
  and Viewed while its text is the same. A Viewed file whose text changed
  opens again. A file new to the card with over 2,000 changed lines starts
  folded. Changes inside a line are marked by word. Added lines use the
  finished color at 10 %, removed lines the error color, and word marks
  28 %.
- **The sticky header** stays at the top of the view while its file is in
  view, and the next file's header pushes it up. It is `position: sticky`
  inside its box, so the system moves it as it scrolls and no script does.
  While it sticks it keeps the box's round top corners, on a square of the
  card's color, so no line shows in the corners. Each file's lines draw only
  near the view (`@pierre/diffs`' `Virtualizer` and `VirtualizedFileDiff`),
  but the box keeps the whole file's height. A box more than about 1,500 pt
  from the view takes an estimated height (20 pt a row) until it comes near.
  When a box above the view changes height (a refresh, a box that comes
  near), the file in view stays where it is. In a very fast scroll the lines
  can be blank for a frame; the header never moves. The scroll bar draws
  over the sticky header.
- **The file list** is a column at the left (28 % of the card, 160 to
  260 pt) in the home's row style: a title with the file count, then one row
  per file with its icon, its name, its folder in secondary, `+n −m` and its letter
  (`M A D R`, in the tree's colors). A click scrolls to the file. The file
  list button slides it out and in (0.25 s, the plugins' shared sidebar in
  `card.css`; at once with Reduce Motion).
- **Previous and next change** step through the change blocks in order, from
  the last one stepped to or the file picked in the list. They open a folded
  file.
- ⌘-click on a line opens the file at that line in a new tab, ⌥-click to the
  side. On a removed line it opens the line after the change.
- "No changes" shows when the patch is empty. A failed first read (not a
  repository yet, a machine away) shows git's error and asks again at the
  next change in the work tree.
- **A move to a place not kept** (a commit from the home, Parent) reads the
  new patch and the commit's facts first and then draws them in one step: the
  place before stays until then, with no blank page between. A kept diff
  shows at once and reads its patch again only if the work tree changed
  while it was hidden.
- A new diff starts with the card's Side by Side and Word Wrap (the header's
  values) and its file list (the card's state). The file list starts
  closed; when the user opens or closes it, the card keeps that choice.
  These are saved in the state file, so they survive a drop, a reload and a
  relaunch. A kept diff keeps its own. Viewed marks last while the page is
  kept.
- A file with no hunks (binary, a mode change, a pure rename) shows its
  header alone. `N unmodified lines` rows do not expand.
- `Look.cardSolid` is exact in Classic. In Glass it is measured on a card
  (dark `#2E`, light `#F9`), so an unusual wallpaper moves the card a few
  steps off the header, and on the keyboard card the header is a step
  darker than the card.

over the card that uses it, because a disabled menu item swallows its key.

| Keys | Command | When it has its key |
|---|---|---|
| ⌘[ ⌘] | Back, Forward in the card | while the card has a place that way. Else they select a pane |
| ⌘← ⌘→ | Back, Forward in the card | while no text field in the page has the keyboard: there they move the caret |
| ⌘S | Save (File menu): the editor's text to disk | only while File or Markdown has the keyboard |
| ⌘F | Find… (Edit menu): the editor's find bar; on the tree, its find bar | on File, Markdown and the tree. Disabled on Preview, the Git home and a diff |
| ⌥⌘F | Find and Replace: the find bar with its Replace row (the page's own key) | on File and Markdown, in a file that is not read only |
| ⌘G | Find Next (Edit menu) | always. Over a terminal it steps the find bar |
| ⇧⌘G | Find Previous (Edit menu) | only while File or Markdown has the keyboard. Elsewhere ⇧⌘G is Go to Directory |
| ⌘E | Edit Mode (View menu, while a File Explorer card has the keyboard; disabled outside Markdown): Read and the last edit mode | only while Markdown has the keyboard |
| ⌥⌘R | Reload Plugin (the card's menu, View ▸ Pane) | over a plugin card |
| ⌘↩ | Commit | in the Git home's message field |

- A floating window's menu bar and palette offer Save, Edit Mode, Find, Find
  Next and Find Previous with the same keys.
- Replace Pane (⇧⌘R) gives a fresh shell with the chooser. Close, Replace Pane
  and the commands that change a pane's kind ask nothing while the pane runs
  only its placeholder. Unsaved edits are not a reason to ask.

## Remote machines

Every read, save, listing, watch and git command runs on the pane's machine
through its `Exec`, over the relay's one SSH session
([Commands](/docs/reference/herdr-calls#commands)). Nothing is installed on
the machine. The limits:
- No apps in Open With: the file is not on the Mac.
- A file over 4 MiB opens read only, because a save sends the whole file
  through the relay.
- Choose Folder… is a typed path, not the folder panel. A path that is no
  folder shows "No folder ‹path›".
- No file system events: while a card shows, the app checks every 2 s. For a
  file it compares the file's `cksum`. For a folder (the tree, the Git home,
  a Working Tree diff) it compares the folder's entries, its `git status`
  and the changed files' text. A hidden card checks nothing.
- git comes from the machine's `PATH`, and a remote machine's git always
  runs: one without git shows no git and roots File Explorer and Git at the
  pane's folder. When This Mac has git only as the stub without the developer
  tools, cards on This Mac run no git
  ([Git status](/docs/talking-to-herdr#git-status)).
- Pull and Push use the machine's own credentials. A key with a passphrase
  and no agent fails with ssh's message, because nothing can ask for it.

## How the cards are built

- **Packages.** Each is a package in `~/.config/ovvi/plugins/<id>/`: its
  `package.json` with the `ovvi` key, a lockfile, its own `node_modules`,
  `src/` and the built `dist/`
  ([File Explorer and Git in the same layout](/docs/plugins/building#file-explorer-and-git-in-the-same-layout)).
- **One web view per card.** Each card is a `WKWebView` of its own, and
  WebKit gives each one its own WebContent process. A shared process pool
  does not help: `WKProcessPool` is deprecated and does nothing. A card's
  process uses about 28 to 45 MB (`footprint`).
- **One page, many places.** The card loads its plugin's page once. A move
  is `card.go`: the page draws the new place itself, in a hidden root over
  the old one, and swaps them once it drew, so the old frame stays until
  then. Each heavy place (File Explorer's four, Git's diff) is a module
  loaded with `import()` on first use, so a tree card loads no CodeMirror or
  pdf.js, and a Git home loads no `@pierre/diffs`. Git's home is in the
  entry, so it opens at once. A place ends its handlers, watches and views when the card
  leaves it. The card keeps the keyboard if it had it.
- **CSS.** The entry imports every place's CSS, because a bundler links no
  CSS of a dynamic chunk. File Explorer scopes it by the place
  (`data-place`), Git by each place's container (`#home`, `#diff`).
- **Files stay checked.** `files.read` gives the file's hash, and
  `files.write` with `over` writes only when the file on disk still has it.
  `files.info` gives the hash too, so File and Preview check it before a full
  read. Saves, hashes, watches and git run in HerdrKit's `Files` and `Git` on
  the card's machine ([The plugin API](/docs/plugins/api)).
- **SF Symbols in a page.** The Git home and the diff's list ask the app for
  the symbols they draw (`ovvi.symbol`), and use each PNG as a mask in the
  text's color.
- **The place rule** is in `places.json`, which the page and the app both
  read: the app picks the tab's icon, the page's accessibility identifier
  (`files`, `file`, `preview` or `markdown.<pane>.page`; Git's is
  `git.<pane>.page`) and which places take ⌘S and ⌘F from it.
- **Keys.** The card's view takes and drops the keyboard as a browser card
  does, and sends ⌘ keys to the menu first ([Keys](#keys)).
- **A crashed page** loads again, once per load. Unsaved edits are lost then.
  Every card is inspectable: Show Web Inspector in the card's menu, or
  Safari's Develop menu.

## Not built

- Go to File in ⌘K, search across a project, and ⌘-click on a path in a
  terminal.
- Stash, merge and rebase in Git.
- Quick Look for other file types: they show the info view.
- Expandable `N unmodified lines` rows in a diff (they need each file's whole
  text).
- A landing and Back and Forward kept over a relaunch, and Viewed marks
  saved.
- Images in Markdown's Read, and a table view in Live Edit.
- Markdown's footnotes gathered at the end of the page, as on GitHub, and
  `~sub~` and `^sup^`, which GitHub does not draw either.
