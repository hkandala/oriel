Every browser and plugin pane is stored in herdr this way
([Browser](/docs/ui/browser#the-label),
[File Explorer and Git](/docs/plugins/default-plugins#the-label)). The
plugin id is the manifest's `id` ([The manifest](/docs/plugins/manifest)),
and a plugin has one pane kind, so its labels have no pane name. A
manifest's `id` uses no `.` or `_`, so a label with one shows the missing
card.

## Label format

```text
label     = "oriel:" plugin-id [ "/" pane-name ] "#" iid [ " " arg ]
plugin-id = [a-z0-9][a-z0-9._-]{0,63}
pane-name = [a-z0-9][a-z0-9-]{0,31}
iid       = [a-z0-9]{6}
arg       = the rest: no control characters, at most 1024 characters
```

Examples, as a herdr TUI user sees them in the pane border:

```text
oriel:git-history#k3f9q2 main
oriel:explorer#q2m0zd /Users/me/code/oriel/README.md
oriel:git#a81xw0 /Users/me/code/oriel/ uncommitted
oriel:kanban/board#7tt1qe
oriel:browser#m4p8sa http://localhost:3000/dashboard
```

- The parser accepts `/<pane-name>`, and no plugin uses it: a plugin has one
  pane kind. A label with a pane name opens the plugin's one kind.
- The `oriel:` prefix keeps a user's own label (`todo: fix login`) from turning
  into a plugin.
- The argument goes last, so the useful part is what a TUI user reads. herdr
  trims labels.
- Labels travel in every snapshot to every device, so the argument stays
  small (under ~200 characters advised). Bigger state goes to a file
  ([State](/docs/plugins/api#state)).

## Instance id

The instance id (`iid`) names the pane's state file
([State](/docs/plugins/api#state)). `terminal_id` changes on a herdr
cold restart, and the label survives it, so the iid lives in the label.
- The device that creates the pane generates 6 characters of `[a-z0-9]`,
  checked against the snapshot. It never changes.
- The card itself is keyed like every card, by `(machine, session, terminal_id)`
  ([Reconcile](/docs/talking-to-herdr#reconcile)). Two panes with a copied
  label share one state file, last writer wins.

## Create

Browser and plugin panes are created the same way.

1. A pick ([New pane](/docs/ui/new-pane), the palette) → the argument from
   the pane's folder → generate the iid.
2. `layout.apply` without a `tab_id` makes a new tab with one pane. herdr
   starts the pane with its label and its placeholder command in one call:
   ```text
   layout.apply {workspace_id, focus:false,
                 root:{type:"pane", cwd, label:"oriel:<plugin>#<iid> <arg>",
                       command:["sh","-c",<script>,"sh",<title>,<arg>]}}
   ```
   - `cwd` is the source pane's cwd, so a diff split from an agent's pane
     opens in that agent's repository.
   - The script prints the title, the argument and "Shown in Oriel" in the
     middle of the pane, and again on `SIGWINCH` (a resize). It runs
     `stty raw -echo` and a background `cat <&0 >/dev/null`, and waits on
     it. `stty raw` makes Ctrl-C and Ctrl-D plain bytes, so a herdr TUI user
     cannot end the pane by accident (checked on 0.9.5).
   - herdr runs the argv itself. No login shell, quoting or envelope is
     involved: the title and argument are plain argv (`"$1"`, `"$2"`).
3. For a new tab, that is all. For a split, `pane.move {pane_id,
   destination:{type:"tab", tab_id, split, target_pane_id}, focus:false}` puts
   the pane in place, and the temporary tab closes itself. For left or top,
   then `pane.swap`, as for drops.

- Other devices can see the temporary tab for one snapshot. The device that
  creates the pane hides it by its label until it is in place.
- `pane.created` already carries the label, so other devices draw the card at
  once.

<Callout title="Never pass tab_id" type="warn">
`layout.apply` with a `tab_id` replaces the whole tab and kills its panes. The
app never passes it.
</Callout>

<Callout title="The label is the truth">
The placeholder is cosmetic, and the app relies on nothing in it. It shows
herdr TUI users and devices without the plugin what the pane is. If the
placeholder process is killed, herdr closes the pane. Closing a browser or
plugin pane never asks, because it runs only its placeholder (the app knows it
by its label).
</Callout>

## The placeholder

Every browser and plugin pane runs the placeholder. Two kinds of pane come
without it: after a cold restart herdr brings each pane back as a plain shell
with its label (it saves the command, but runs it again only after a live
update), and a pane that an agent or a person labels by hand has the shell it
was made with.

- Each time the app learns what a pane runs (`pane.process_info`), a browser
  or plugin pane with only its shell in front gets the placeholder: the app
  types ⌃U (which clears a line half typed in herdr's TUI), then `exec` and
  the placeholder's argv, in the base64 envelope that every
  login shell passes on ([Running commands](/docs/talking-to-herdr#running-commands)),
  and Return. The placeholder takes the shell's place, so the pane runs only
  the placeholder.
- It looks again when the pane's label changes, and once more 5 s after it
  found another program in front (a slow shell startup after a restart).
- Once per shell process (its pid). A pane that runs any other program gets
  nothing typed. The line starts with a space, which keeps it out of a history
  that ignores such lines. A shell's own question that waits for a line (an
  update prompt in a `.zshrc`) looks like the shell, and gets the line.

## Choices

- **The label marks the pane.** It is durable and readable, and survives
  moves and cold restarts. Rejected: metadata tokens (capped at 80
  characters, lost on restart); a pane list kept by the app.
- **A placeholder pane made in one call.** Zero app state, and one layout for
  every device and the herdr TUI, with no race with shell startup. The app
  types the placeholder only into a pane that came back without it. Rejected:
  typing the placeholder into a new shell that the app makes; plugin UI drawn by the app outside
  herdr's layout; a placeholder that reports itself as an agent.
