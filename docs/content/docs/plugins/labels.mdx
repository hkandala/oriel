## Label format

```text
label     = "oriel:" plugin-id [ "/" pane-name ] "#" iid [ " " arg ]
plugin-id = [a-z0-9][a-z0-9._-]{0,63}
pane-name = [a-z0-9][a-z0-9-]{0,31}
iid       = [a-z0-9]{6}
arg       = the rest: no control characters, at most 1024 characters
```

Examples, as a herdr TUI user sees them in the pane border:

```text
oriel:git-history#k3f9q2 main
oriel:markdown#q2m0zd docs/DESIGN.md
oriel:diff#a81xw0 base=main
oriel:kanban/board#7tt1qe
oriel:web#m4p8sa http://localhost:3000/dashboard
```

- A plugin with one pane kind omits `/<pane-name>`. A label without a pane
  name opens the first pane kind in the plugin's manifest.
- The `oriel:` prefix keeps a user's own label (`todo: fix login`) from turning
  into a plugin.
- The argument goes last, so the useful part is what a TUI user reads. herdr
  trims labels, and `setArg` trims too.
- Labels travel in every snapshot to every device, so the argument stays
  small (under ~200 characters advised). Bigger state goes to a file
  ([State and restore](/docs/plugins/state)).

## Instance id

`pane_id` changes when a pane moves to another workspace, and `terminal_id`
changes on a herdr cold restart. The label is the only stable carrier, so the
instance id (`iid`) lives in it.
- The device that creates the pane generates 6 characters of `[a-z0-9]`,
  checked against the snapshot. It never changes.
- Plugin cards are keyed by `(machine, plugin, iid)`, so they survive moves
  and restarts without reloading.

## Create

Web and plugin panes are created the same way (D51).

1. Picker → argument prompt if required → generate the iid (web and plugin panes).
2. `layout.apply` without a `tab_id` makes a new tab with one pane. herdr
   starts the pane with its label and its placeholder command in one call:
   ```text
   layout.apply {workspace_id, focus:false,
                 root:{type:"pane", cwd, label:"oriel:<plugin>#<iid> <arg>",
                       command:["sh","-c",<script>,"sh",<title>,<arg>]}}
   ```
   - `cwd` is the source pane's cwd, so a diff split from an agent's pane
     opens in that agent's repository.
   - The script prints the title, the argument and "shown by Oriel", then runs
     `stty raw -echo; exec cat >/dev/null`. `stty raw` makes Ctrl-C and
     Ctrl-D plain bytes, so a herdr TUI user cannot end the pane by accident.
   - herdr runs the argv itself. No login shell, quoting or envelope is
     involved: the title and argument are plain argv (`"$1"`, `"$2"`).
3. For a new tab, that is all. For a split, `pane.move {pane_id,
   destination:{type:"tab", tab_id, split, target_pane_id}, focus:false}` puts
   the pane in place, and the temporary tab closes itself. For left or top,
   then `pane.swap`, as for drops.

- The app's immediate read after its own write waits for the `pane.move`, so
  this device never shows the temporary tab. Other devices and a herdr TUI may see it for one snapshot.
- `pane.created` already carries the label, so other devices draw the card at
  once.

<Callout title="Never pass tab_id" type="warn">
`layout.apply` with a `tab_id` replaces the whole tab and kills its panes. The
app never passes it.
</Callout>

<Callout title="The label is the truth">
The placeholder is cosmetic, and the app relies on nothing in it. It shows
herdr TUI users and devices without the plugin what the pane is. The app never
types into a shell.

After a cold restart herdr brings the pane back as a plain shell with its
label: it saves the command but runs it again only after a live update. The
card works anyway. A fix is an upstream ask
([Future work](/docs/future-work)). If the placeholder process is killed,
herdr closes the pane.
</Callout>
