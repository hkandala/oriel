## Run and dial

```swift
protocol Exec {
    /// Run argv on the machine. Returns stdout as a byte stream and a stdin writer.
    func run(_ argv: [String]) async throws -> Channel
    /// Open a TCP stream to host:port, as seen from the machine.
    func dial(host: String, port: Int) async throws -> Channel
    func herdr() async -> String?   // from the login shell
}
```

Every pane kind and plugin reaches its machine through these two calls
(D2). Nothing of ours runs on the machine: `sshd`, POSIX tools and herdr do
the work. A later server helper would sit behind the same two calls
([Future work](/docs/future-work)).

- **`dial`:** on This Mac, a plain TCP connection. On a remote machine from
  macOS, `ssh -S <ctl> -W <host>:<port> <target>` on the host's ControlMaster
  (one process, one stream on its stdio). From iOS, a Citadel `direct-tcpip`
  channel. A web card needs a local port, not a stream; see
  [Remote localhost](/docs/plugins/web-page#remote-localhost).
- **This Mac:** `Process`. A GUI app does not get the shell's environment. So
  at launch the app reads `PATH`, `HOME`, `SSH_AUTH_SOCK`, every `XDG_*`
  variable and herdr's path once with `$SHELL -lic` (stdin from `/dev/null`,
  3 s timeout, output parsed after a unique marker). `HERDR_*` variables are removed from
  child processes.
- **A remote machine on macOS:** the same `Process` with this prefix
  ([macOS](/docs/machines#macos)):
  ```sh
  /usr/bin/ssh -F /dev/null -o ControlMaster=no -o BatchMode=yes \
      -o ProxyCommand=/usr/bin/false -S <ctl> <target> --
  ```
- **iOS:** one Citadel connection per host. Each run is an exec channel.
- **The remote command envelope.** ssh and Citadel hand one string to the
  machine's login shell, which may be bash, zsh or fish. Their quoting rules
  differ. So the app never builds a shell string from data. It sends:
  ```sh
  sh -c 'eval "$(printf %s "$1" | base64 -d)"' sh <BASE64>
  ```
  `<BASE64>` holds the real command as POSIX `sh`, with every argv element
  single-quoted. Base64 contains only `A–Z a–z 0–9 + / =`, so every shell
  passes it through unchanged.
- **Ending a child = closing its stdin.** A `control` run exits in about
  2 ms and herdr frees the pane at once (keys written before the close still
  arrive). A bridge run exits in about 100 ms. If the app quits or crashes,
  the kernel closes its pipes, so every child ends by itself, remote ones
  too: ssh closes the channel. (Measured with herdr 0.9.5, on This Mac and
  over SSH.)
- `observe` and `tail -F` ignore a closed stdin, so they always run in this
  wrapper, on This Mac too:
  ```sh
  sh -c '<cmd> & c=$!; cat >/dev/null; kill $c'
  ```
- One fallback: a channel the app ends by closing its stdin is killed by its
  pid (SIGKILL) if it is still alive about 1 s later. A one-shot command whose
  stdin is closed only so it reads end of input is not killed. A dropped
  stream or a timeout kills at once. The app signals a child only by its pid,
  never by process group.

## herdr on each machine

- herdr installs to `~/.local/bin`, which only the user's shell config puts
  on `PATH`. So the app asks the machine's login shell once,
  `$SHELL -lic 'command -v herdr'`, and takes the last line if it is an
  absolute path (an rc file may print first). Every herdr call on that machine
  runs that path; `PATH` stays the login shell's own. On This Mac the same
  shell run reads the environment, at launch
  ([Run and dial](#run-and-dial)). On a remote machine it is one run over SSH
  on connect, and the path goes inside the envelope.
- No path (herdr missing, or the shell failed or took over 3 s): the app shows
  the install command and asks the shell again, at most every 30 s while
  missing and one run at a time, so a herdr installed since is found. A path
  that is gone since (herdr moved or reinstalled elsewhere) is asked for again
  the same way. herdr older than 0.9.1 has no
  `remote-api-bridge`, so the first call fails. The page then shows
  "‹session› is not running" with **Start**, or Reconnecting. A snapshot that
  reports a version below 0.9.3 shows "herdr is too old" over "herdr ‹version›
  is too old; 0.9.3 or newer needed." The app asks again every 2 s, so the
  page clears by itself after an update.
- The version comes from `session.snapshot`. Decoding is lenient, so a newer
  protocol needs nothing.
- Commands start in the machine's home folder (sshd starts them there; on
  This Mac the app sets the child's working folder), so the app passes paths
  relative to it and never reads `$HOME`.
- Every herdr argv carries `--session <name>` (also `--session default`), so
  no inherited variable can point a command at another session.

## Requests

- `call(method, params)`: run `herdr --session S remote-api-bridge`, write
  one line `{"id":"1","method":"…","params":{…}}`, read one reply line, then
  close stdin. herdr answers one request per connection.
- **Timeout:** every `call()` times out after 10 s. On a timeout the app kills
  the bridge process (macOS) or closes the channel (iOS). A write that times
  out shows the notice "herdr did not answer", with no Retry. A read that
  times out shows Reconnecting.
- Long-lived streams (events, terminals, chat tails) have no timeout. The
  health check covers them.
- Cost: 18 ms median and 130 ms at p95 per call (measured locally), plus the
  network round trip. Text typing never takes this path (special keys do:
  [Terminal plane](#terminal-plane)). Simpler choice: the
  bridge, not the local socket. Revisit when a profile shows the cost hurts:
  talking to the local socket directly takes 0.5 ms.

## Events

- One long-lived bridge run per open session carries `events.subscribe`. A
  session without a page in any window has none
  ([Open sessions](/docs/machines#open-sessions)).
- Subscriptions (herdr accepts no wildcards):
  - `workspace.created|updated|metadata_updated|renamed|moved|reordered|closed`
  - `tab.created|closed|renamed|moved`
  - `pane.created|closed|moved|updated|exited|agent_detected`. herdr sends
    `pane.updated` when `terminal_title_stripped` changes, which can pick a
    pane's icon ([Program icons](/docs/ui/program-icons)). Spinner frames
    send none (herdr strips them); a title with changing text, such as a
    progress count, sends one per change, and the snapshot pacing below
    absorbs them.
  - `layout.updated`
  - `pane.agent_status_changed`, one entry per pane listed in
    `snapshot.agents[]`. Each entry makes herdr poll that pane every 100 ms,
    so plain shells are left out.
  - No `*.focused` events. They fire on every herdr TUI navigation, and the
    app ignores herdr's focus.
- **Any event line means "read `session.snapshot` again".** Event payloads
  are never decoded.
- **Snapshot pacing, per session:** at most one `session.snapshot` is in
  flight. An event, or the app's own write, starts a read at once if none is
  in flight; otherwise it sets "read again", and the read that ends with it
  set starts one more. A read takes 20–130 ms, so it batches the events that
  arrive during it.
- The stream is opened again, followed by a snapshot, when the set of agent
  panes changes, on `events_lost` (the reader fell behind herdr's 512-event
  buffer) and on `pane_not_found` (a listed pane closed first).
- The [health check](/docs/machines#health-check) reads the snapshot every
  30 s, so a missed event is caught there.

## Reconcile

<Flow steps={[['herdr event', 'any line on the stream'], ['pacing', 'one read in flight, then read again if needed'], ['session.snapshot', 'workspaces, tabs, panes, agents, layouts'], ['reconcile', 'stable objects, changed fields only'], ['views update', 'one row, not the window']]} />

- One snapshot holds every workspace, tab, pane, agent and layout.
- The session's HostStore applies it to stable `@Observable` objects (`Workspace`,
  `Tab`, `Pane`) keyed by id, and sets only the fields that changed. A status
  change redraws one row, not the window.
- Ids are scoped by session (two sessions can both have `w1:p1`). Every
  card is keyed by `(machine, session, terminal_id)`, which survives every
  move. A
  herdr cold restart gives new terminal ids, so cards are built again, which
  reads their state from the machine. A web or plugin pane's instance id only
  names its state file ([Labels and instance ids](/docs/plugins/labels)).
- Hand-written, lenient Codable models cover only the fields the app uses.

## Terminal plane

```text
herdr terminal session control <terminal_id> --cols C --rows R [--takeover]
  stdout → {"type":"terminal.frame","seq":1,"width":C,"height":R,
            "full":true,"bytes":"<base64 ANSI>"}
           {"type":"terminal.closed","reason":"…"}
  stdin  ← {"type":"terminal.input","text":"ls\r"}
           {"type":"terminal.resize","cols":120,"rows":40,
            "cell_width_px":8,"cell_height_px":17}
           {"type":"terminal.scroll",…}
           {"type":"terminal.mouse",…}
```

herdr draws the pane at our size and sends ANSI updates. A libghostty surface
draws them. Input takes two paths:
- Text (typing, IME, paste, plain Enter, Tab and Backspace) goes on the
  stream as `terminal.input`.
- Special keys (arrows, Esc, function keys, keys with modifiers, Ctrl
  chords, and the macOS line-editing keys such as ⌘← and ⌥←) go as
  `pane.send_keys`, one bridge call per burst. Their bytes depend on the
  program's input modes, and herdr encodes them for those modes. A Ctrl
  chord keeps its Shift: under the kitty keyboard protocol ⌃⇧S is its own
  key, and a program without that protocol gets ⌃S's byte (for a letter). Keys that
  pile up during a call go in the next one, in order with the text.

One path is [Future work](/docs/future-work).

### What streams

- The panes of the shown tab of the page in view, in each window. Other
  pages stream nothing.
- On the Mac, the 4 most recently shown other terminals, over all pages of
  all windows, keep their streams and their libghostty surfaces (each window
  has its own `PaneViewRegistry`; they share one count), least recently shown
  first out (D46). So coming back to them is at once and resizes nothing. A
  pane shown in two windows has two surfaces and two streams, and counts
  twice.
- Only the shown tab's terminals (and floating panes) draw. The others keep
  their last picture and still read their stream. libghostty also stops
  drawing in a minimized, hidden or covered window.
- A terminal past those 4 lets go of its stream (its herdr run ends) and of
  its surface: libghostty's three IOSurfaces at the card's size (about 17 MB
  each for a full-window card on a Retina screen). Its last picture stays as
  a still, marked purgeable while no window shows it, so it costs no memory
  then (the system may take it back under memory pressure). When it is shown
  again, a new surface is made under the still and the stream opens again;
  herdr's first frame redraws the screen, and the still goes once the new
  surface has drawn herdr's settled frames, so the card is never empty. A
  still the system took back gives the card's fill and the first fade-in.
- A terminal gets its surface only when it first streams, so a card that a
  lazy page lays out but never shows costs no GPU memory.
- One `terminal session` run per streaming terminal, also in one session:
  herdr 0.9.5 ties each client connection to one terminal
  (`ControlTerminal {target}` on a connection still in the pending terminal
  mode), and the CLI takes one target. One run costs about 7 MB and almost
  no CPU. Many terminals per run would need herdr's private client protocol
  on its socket.
- During a swipe the neighbor tab shows each card's last image, or its fill
  for a card never shown (a `pane.read visible` preview is not built yet).
  Its streams start when the swipe stops.
- Streams are opened by `terminal_id`, so they survive the pane moving, even
  to another workspace.

### Size

- Card size ÷ cell size gives cols × rows. While the card's size keeps
  changing (a window drag, a divider drag, the sidebar, layout motion), its
  terminal keeps its grid, clipped at the top left. Once the size has not
  changed for 150 ms, or a window drag ends, the terminal takes the card's size
  and the new grid goes to herdr at once. Pixel-only changes send nothing.
- herdr answers every resize, even to the same size, with a full frame
  (`"full":true`); its other frames only carry what changed.
- At a new grid (a resize, a new text size) a card that is not watching
  pauses libghostty's drawing, so neither libghostty's reflow of the old
  screen nor herdr's first frame shows: the card keeps its last picture, at
  the top left, until herdr's frames settle (below), then shows the new one
  at once. It never goes blank.
- A `control` frame's `width` and `height` are the real PTY size.
- herdr has no way to size a PTY without attaching (the attach's `--cols` /
  `--rows` resizes it), so a pane opened for the first time redraws once at
  the card's size: herdr's first frame is the old screen reflowed at the new
  size, and the program's redraw for `SIGWINCH` follows. The card draws
  nothing until herdr's frames stop for 0.1 s (at most 0.4 s after the first
  frame or the resize), then fades its terminal in (0.12 s). A fade that does not run
  leaves the terminal shown, never hidden. Background tabs are not attached ahead of time
  (D46's stream cap).

### One controller per pane

`control` can type and resize. `observe` only watches.

<Ownership />

1. **Mac:** open as `control` without `--takeover`. If herdr refuses (another
   device holds the pane), open as `observe` and show "In use elsewhere ·
   Take Back".
2. **iPhone and iPad:** open as `observe`. Looking never resizes the PTY.
3. On any device, the first key press, paste, or click or tap inside a
   watching card, or **Take Back**, opens the stream again with
   `--takeover`. Keys typed before the new stream's first frame are queued
   and sent in order.
4. Nothing else takes control. A watcher stays a watcher until its user acts,
   even after the other device lets go.
5. A device closes a stream (closes its stdin) when it stops showing the
   card ([What streams](#what-streams)). herdr frees the pane at once.
6. **Background:** a Mac app that becomes inactive keeps its streams. An iOS
   app closes its streams when it goes to the background.

### Control between windows

Two windows on the Mac can show the same session. Control is per session
(D66):
1. The window where the user last typed, pasted or clicked in a terminal card
   of the session holds that session's `control` streams.
2. Another window that shows the session opens `observe` streams for its
   cards, at its own card size. Its cards dim a little, and it shows
   "Controlled in another window · Take Back"
   ([Control capsule](/docs/ui/window#control-capsule)). Its cards show no
   per-card "In use elsewhere" label: the capsule covers them.
3. Take Back, or a key press, paste or click in a terminal card of the
   watching window, moves control: that window opens its streams again as
   `control` with `--takeover`. herdr's takeover ends the other window's
   streams, and they open again as `observe` (D8); herdr closes them with
   the reason "terminal attach taken over". The window's other streams of
   the session (recent tabs) take over too, and the other windows' watch. Keys
   typed before the first frame are queued, as for a device.
4. The session's `HostStore` records which window controls it, so its
   windows never take over from each other by themselves.
5. When the controlling window closes, or closes the session's page, the
   next window that shows the session controls it and takes over its streams,
   so the PTY takes its card size.
6. Windows on different sessions each control their own session.
7. Another device can still hold a single pane. That card shows "In use
   elsewhere · Take Back", as in [One controller per pane](#one-controller-per-pane).

### Watching on a narrow screen

- herdr does not report a pane's PTY columns, and `observe` clips or pads to
  the watcher's size.
- An iPhone watches at a fixed 160×50, with the font scaled to fit and pinch
  to zoom. An iPad watches at its card size.
- Observe cannot resize, so a size change restarts the stream.

### How a stream ends

After a `terminal.closed` line the CLI exits 0. If it cannot connect, or the
handshake fails, it exits 1 with the reason on stderr.

| Reason contains | The app |
|---|---|
| `already has an attached client` | watches; shows Take Back |
| `taken over` | watches; never takes back by itself |
| `not found` or `exited` | drops the card; waits for the snapshot |
| `detached` | does nothing (this device closed the stream) |
| `live update` | opens the stream again after 1 s |
| any other failure (exit 1, for example a handshake error after herdr updated but did not restart) | shows herdr's reason and **Retry** in the card |

### Scrolling, queries and links

- **Scrolling:** `terminal.scroll` goes to the program when it uses the mouse
  or alternate scroll (most agent TUIs). Otherwise it scrolls herdr's shared
  viewport. The app keeps no scrollback. Agent history is in the chat view.
- **Terminal queries:** herdr already answers them, so libghostty must not
  answer again. A stock libghostty would send its answers as key input. The
  app uses a pinned libghostty-spm build with uHerdr's response-suppression
  patch (`suppressesTerminalResponses`). [Spike S1](/docs/build-order#s1-strip)
  checks it.
- **Find** (⌘F) reads the pane's recent text with
  `pane.read {source:"recent", lines: 5000, format:"text"}` when the bar
  opens (again at the next step after Return in the pane), and searches it on
  the device on each edit. Each match scrolls herdr's shared viewport with
  `pane.scroll {pane_id, offset_from_bottom}`: the match line's distance from
  herdr's last row, less half of `viewport_rows`. herdr's text leaves out the
  screen's blank rows under its last text, but the offset counts them, so the
  bar adds them: from `pane.read visible` at the bottom, else from
  `pane.get`'s `max_offset_from_bottom + viewport_rows` less the text (a text
  cut at 5000 lines counts none). A herdr TUI on the same pane scrolls too.
  After each scroll, and 0.3 s after a burst of frames (at most 1 s of
  waiting), `pane.read visible` and `pane.get` (`scroll`) place the
  highlights. herdr's own
  `pane.copy_search` is not used: it needs a `content_revision` and a cursor
  from herdr's TUI client protocol and otherwise answers `stale_content`.
- **Links** in terminal output open on this device with ⌘-click, and only
  `http` or `https`.

## Git status

The sidebar's workspace rows show the branch and the ahead and behind counts
(D67). herdr's snapshot has no branch, so the app asks git on the machine:
- **Command.** `git --no-optional-locks -C <root> status --porcelain=v2
  --branch --untracked-files=no` (`--no-optional-locks`, so a run every 10 s
  never leaves `index.lock` behind), through `Exec.run`, so it works the same
  on This Mac and over SSH. `git` comes from the login shell's `PATH`, like herdr. The
  root is the workspace's `worktree.checkout_path`, else the cwd of its first
  pane. A run that takes over 5 s is ended.
- **Parse.** The `# branch.head` line gives the branch; when it is
  `(detached)`, the first 7 characters of `# branch.oid`.
  `# branch.ab +A -B` gives ahead and behind (absent without an upstream). The
  app reads no other line. A nonzero exit means the folder is not a git
  repository, and the row has no git line.
- **When.** For a workspace that is new or whose root changed, and every 10 s
  for every workspace, only for the page in view of a visible window. Hidden
  pages never run. One run per workspace at a time.
- **No developer tools.** At launch the app checks once where `git` is. When
  it is only `/usr/bin/git` and `xcode-select -p` fails, the app runs no git
  at all, so macOS never offers to install the developer tools. Rows then
  have one line.
- **Worktrees.** herdr's `worktree.is_linked_worktree` and `repo_key` place a
  linked worktree under its repository's workspace. No git run is needed for
  that. herdr 0.9.5 fills a workspace's `worktree` only after a `worktree.*`
  call looked at it: `worktree.list`, `worktree.open` or `worktree.create`.
  A plain `workspace.create {cwd}` in a repository leaves it out, so its row
  is never a worktree row. `worktree.open` also fills the open workspace of
  the worktree's repository.
- The result lives in memory on the session's `HostStore`.

## Writes are herdr calls

| User action | herdr call |
|---|---|
| New workspace (page header `+`, workspace menu, an empty session's New Workspace) | `workspace.create {cwd: $HOME, label, focus: false}` in that page's session (a launchd-started server's cwd is not `$HOME`); the label only when the user typed one; then the snapshot selects it |
| Folder dropped on the Dock icon | `workspace.create {cwd, focus: false}`, one per folder, in the session of the last key window's page in view, once that page is live; the last one is selected when it appears. With no window (a drop that starts the app), a window opens first |
| New tab | `tab.create {workspace_id, cwd}`, with the cwd of the keyboard card; from a workspace row's New Tab, that workspace's keyboard card, or `$HOME` |
| Split right or down | `pane.split {target_pane_id, direction: right or down, focus:false}`, then [equal splits](/docs/layout#dividers): a fresh snapshot, and one `layout.set_split_ratio` per split of the new pane's run whose ratio changes |
| Split left or up | `pane.split` right or down (`focus:false`), then `pane.swap {pane_id: old, direction: right or down}`: the old pane swaps with the new one beside it (herdr splits only right and down); then equal splits |
| Drag a divider | `layout.set_split_ratio {tab_id, path, ratio}` on release; ratio kept in 0.1–0.9 |
| Double-click a divider | `layout.set_split_ratio` with ratio 0.5 |
| Balance splits (⌥⌘=) | one `layout.set_split_ratio` per split of the selected tab whose ratio changes; ratio = units on the first side ÷ units under the split, where a child split the other way is one unit |
| Swap two panes (same tab) | `pane.swap {source_pane_id, target_pane_id}` |
| Move the keyboard card (⌥⇧⌘ + arrow) | `pane.swap {pane_id, direction, focus:false}` (herdr 0.9.5 focuses that tab anyway); the keyboard stays with the pane |
| Move Pane to Tab ▸ ‹tab› (card menu) | `pane.move {pane_id, destination:{type:"tab", tab_id, split:"right", target_pane_id}}` beside the tab's last card, then equal splits (as a drop on its capsule); the window then selects that tab |
| Move Pane to Tab ▸ New Tab (card menu) | `pane.move {pane_id, destination:{type:"new_tab", workspace_id}}`; the window then selects the new tab |
| Move Pane to Tab ▸ New Workspace (card menu) | `pane.move {pane_id, destination:{type:"new_workspace"}}`; the window then selects the new tab. The pane gets a new pane id; its terminal and card stay |
| Drop on an edge of a pane in the same tab | `pane.move {pane_id, destination:{type:"new_tab", workspace_id}}`, then `pane.move {pane_id, destination:{type:"tab", tab_id, split, target_pane_id}}` back beside the target (right or down), then `pane.swap {source_pane_id, target_pane_id}` for left or top, then equal splits; each step uses the pane id herdr's reply names, and the snapshot is read after (herdr refuses a move into the pane's own tab with `same_tab`) |
| Drop on an edge of a pane in another tab | `pane.move {pane_id, destination:{type:"tab", tab_id, split, target_pane_id}}`; for left or top, then `pane.swap`; then equal splits |
| Drop on another tab's capsule | `pane.move {pane_id, destination:{type:"tab", tab_id, split:"right", target_pane_id}}` beside the tab's last card, then equal splits |
| Drop on the tab track's empty end or `+` | `pane.move {pane_id, destination:{type:"new_tab", workspace_id}}` |
| Drop on a workspace row | `pane.move {pane_id, destination:{type:"new_tab", workspace_id}}` |
| Drop on empty space at the bottom of the sidebar page, or on its header's `+` | `pane.move {pane_id, destination:{type:"new_workspace"}}` |
| Move Tab Left or Right, drag a tab | `tab.move {tab_id, insert_index}`, inside its workspace only. herdr inserts before the tab now at `insert_index` (0 to the count), so one place left is index − 1 and one place right is index + 2 |
| Move Up or Down, drag a workspace | `workspace.move_block {workspace_ids, before_workspace_id}` with the row's group: the workspace and its linked worktrees, in order; without `before_workspace_id` the group goes last. A dragged worktree alone goes before another worktree of its repository, or (last) before the workspace after the last one |
| Open Session: a new name, a running or a stopped session | starts `herdr --session S server` when it is not running (a launchd job on This Mac, D47; `nohup` on a remote machine) and waits for `session.snapshot`; a server the app started with no workspace gets `workspace.create {cwd: $HOME}`; then the page opens and its `HostStore` connects ([Checks on connect](/docs/machines#checks-on-connect)) |
| Open Session: Stop, Delete | `herdr --session S session stop S` (the server ends, and every program in it) or `session delete S` (a stopped session only); both ask first; then the list is read again. A failure shows herdr's reason with Retry |
| Detach Session | no herdr call; the page's store disconnects when no window shows it, and the session keeps running |
| Close a pane | `pane.close`; asks first unless the pane's only foreground process is its shell (`pane.process_info`); web and plugin panes close at once (known by their label), and the app removes their [state file](/docs/plugins/state#the-instance-state-file) |
| Close a tab | `tab.close`; asks first only when a pane of it runs more than its shell (`pane.process_info` of each pane, at once), naming what runs, with the pane count |
| Close a workspace | `workspace.close {workspace_id, close_group}`; asks as for a tab, with the tab and pane count. `close_group: true` for a repository's workspace with linked worktree workspaces: herdr refuses the close without it (`workspace_group_close_required`), and with it closes all of them, also ones not next to it. The git worktrees stay on disk. A worktree's own workspace closes alone |
| Close Other Tabs, Close Tabs to the Right | one `tab.close` per tab, all at once; asks once as for a tab, with the total pane count |
| Rename a tab or workspace | `tab.rename {tab_id, label}` / `workspace.rename {workspace_id, label}`; an empty or unchanged name sends nothing |
| Rename a pane | `pane.rename {pane_id, label}`; an empty name sends `label: null`, which clears the label |
| Go to Directory (⇧⌘G) | `pane.send_input` of `cd -- '‹path›'` and Return, only when the pane runs only its shell |
| Insert Path (⇧⌘I) | `pane.send_input` of the shell-quoted path, no Return |
| Find next or previous (⌘F) | `pane.scroll {pane_id, offset_from_bottom}` to the match; offset 0 when the bar closes |
| Start an agent | [agent.start steps](/docs/plugins/terminal-and-agent#agent) |
| Resize Pane (View ▸ Pane, the palette; no key) | `pane.resize {pane_id, direction, amount: 0.05}` on the keyboard card; herdr moves the nearest divider that way, or returns `changed:false` when there is none |
| Move the keyboard (⌥⌘ + arrow; not a write) | `pane.neighbor {pane_id, direction}`, read only; the app gives the keyboard to the card it names |
| Git state of the workspace rows (not a write) | no herdr call: `git status` on the machine ([Git status](#git-status)) |

- No close can be undone.
- Every create and move passes `focus:false`, so herdr's focus never moves.
- Every workspace reorder is `workspace.move_block`, which names the
  workspace to go before. The app never calls `workspace.move`.
- `pane.move` and `pane.swap` can succeed with `changed:false` and a `reason`
  (`same_tab`, `zoomed_tab`, `cross_tab`, `no_neighbor`). The app shows the
  reason. Its drag targets avoid `same_tab` and `cross_tab` by design
  ([Drag and drop](/docs/ui/drag-and-drop#what-herdr-allows)).
- A drop that takes several steps stops at the first step that fails. The
  pane stays where it got to, and the notice says so.
- After its own write, the app reads the snapshot at once. A new tab, a split
  and a close show before herdr answers: the new tab or pane as an empty card
  under a stand-in id, a closing pane, tab or workspace left out. The
  snapshots after the write confirm it (herdr's tab or pane takes the
  stand-in's place; the closed one is gone) or take it back (a failed write).
  Otherwise the app never changes its own state by hand (phase 25).
- Writes of a session run one at a time, in order: a write asked while
  another runs waits for it.
- A close reads `pane.process_info` of its panes, at most 8 at a time. When
  the last answers say only shells run, the close shows at once while herdr
  is asked; a program found brings it back with the question. A pane with no
  answer yet waits for herdr's. A pane whose new shell is still starting (its
  first seconds, [Program icons](/docs/ui/program-icons)) runs short-lived
  startup programs (`ls`, `sort`): it is asked again every 200 ms, up to
  0.8 s, until only its shell runs; a close of it is not shown before herdr's
  answer.
- A tab closed before herdr made it (⌘T, then a close at once) goes at once;
  herdr's tab is closed as it comes.
- `pane.swap` makes herdr focus that tab and its pane and mark it seen, even
  with `focus:false` (herdr 0.9.5). The herdr TUI does not jump. Accepted,
  because a swap only follows a drag, a split left or up, or a key the user
  pressed. With `focus:false`, `pane.move` leaves herdr's focus alone.
- `pane.move` into the pane's own tab returns `changed:false`,
  `reason:"same_tab"`.
- `layout.set_split_ratio`: in `path`, `false` is the first child and `true`
  the second; the root is `[]`. A path that ends at a pane fails with
  `split_not_found`. herdr clamps the ratio to 0.1–0.9 itself.
