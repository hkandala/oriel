## Project

- One Xcode project, one macOS SwiftUI app target, and one local Swift
  package, `HerdrKit`.
- Minimum OS: macOS 26 (Liquid Glass; one minimum means no fallbacks).
  Building needs Xcode 27.
- **Several windows** (`WindowGroup`; File ▸ New Window, ⌘N). Each window
  shows one machine and has its own state: open pages and selection. Windows
  that show the same session share its `HostStore`, and control passes
  between them per session, so two windows never fight over a pane (D66).
  The other windows are the floating panes' (D50), each owned by a main
  window.
- Signing: ad hoc (`make app`), with App Sandbox off and Hardened Runtime on,
  because it runs the `herdr` CLI and `ssh`. Notifications need a real signing
  identity.

| Need | Choice | Why |

| Terminal drawing | `Lakr233/libghostty-spm`, exact pin (it brings DisplayLink) | Metal, IME, one Swift API |

| The chat's Markdown | `swiftlang/swift-markdown` 0.9.0, exact pin (it brings cmark-gfm) | Apple's GFM parser: tables, task lists, strikethrough (D86) |
| Plugin card content ([Default plugins](/docs/ui/plugins)) | CodeMirror 6 (editor, languages, search), `@pierre/diffs`, `@pierre/trees`, `markdown-it`, `pdfjs-dist`; exact pins in `web/package-lock.json` | recognized editors and viewers in the system's WebKit; no framework of our own |
| Building the plugin pages | Node with npm (in the `Brewfile`, and installed on CI), `esbuild`, run by `make web` | one bundle per kind with shared chunks; the built bundle is not in git |

Each library has its entry, with its license, in the app's `Acknowledgements.txt`, the web ones included

## Making the strip work

1. **Terminals swallow the swipe.** One `NSEvent`
   monitor locks the axis at the start of each scroll gesture: a horizontal
   gesture that starts in the strip pages the
   strip; anything else goes to the view under the pointer. A gesture begun
   with ⌥ held goes to the window's sessions or the sidebar's rows
   ([Swiping](/docs/ui/swiping)).
2. **Lazy SwiftUI containers destroy views that scroll off screen.** The
   PaneViewRegistry owns every terminal view. Each
   SwiftUI wrapper makes its own container; the newest container adopts the
   view, and a container removes it only if it still owns it. Stream lifetime
   follows the HostStore, never whether a view is in a window. Off-screen
   surfaces stop drawing but keep reading their stream (herdr drops a watcher
   that reads nothing for 30 s). At most 20 streaming terminals and 20 web
   cards out of view (D46), least recently used first out; an evicted card
   frees its surface or its web view and keeps its last image.
   A lazy stack whose pages change under it can lay
   out none: one strip shared by every workspace drew no page after it drew
   again on a middle tab and the next workspace had fewer tabs. So each
   workspace gets its own strip. Any accessibility client (VoiceOver,
   XCUITest) hides that bug, so `make strip-check` drives the app without one.
3. **libghostty's default key bindings eat the app's shortcuts.** Every
   surface gets `keybind = clear`, and keys go to the main menu first.

## Tab bar and Liquid Glass

- The tab bar is part of the app's own 46 pt title row, a horizontal
  `ScrollView` in the hidden title bar. It is not a `ToolbarItem`: the
  toolbar holds only a `ToolbarSpacer`.
- One glass marker follows the strip's scroll offset
  (`onScrollGeometryChange`). The lit tabs come from the same number: every
  tab from `floor(x/w)` to `ceil((x+w)/w) − 1`. When the scroll stops, the
  selection changes to the page in view. A click, a key, the palette or a new
  or closed tab shows the new page at once, and the marker jumps with it; only
  a swipe or a mouse's sideways wheel slides them. Nothing morphs.
- Each capsule has one status slot: × on the hovered tab, else
  the working dots. The dots are a Core Animation keyframe animation at 15
  frames a second or less, phased by the clock, so the app does no work per
  frame; needs you and
  finished are badges on the icon (D42).
- The window title (`navigationTitle`) is "‹tab title› - ‹page title›" (the machine's name for `default`).
- The tab bar follows Rex's (research notes in `resources/research/clients/rex.md`).
- One `Look` token value per style and appearance draws every surface (D44).
  Glass is only on the Glass style's tab marker and sidebar pill, popovers,
  the palette and floating panels; the sidebar sits flat on the window, pane
  cards are translucent on it.

## Other details

- Drag and drop: the page holds the dragged item (`Dragged`: a pane, tab or
  workspace id). The pasteboard carries only the type
  `dev.hkandala.oriel.drag`, declared in the Info.plist, to route the drag to
  the app's drop targets. Tab capsules spring-load. During a drag, drop
  zones sit above each card's surface. Drops on another session or machine
  are refused.

## Tests

- **End to end first.** `OrielUITests` drives the app with XCUITest against
  a real herdr in throwaway sessions (`oriel-e2e-*`), and checks the result
  through accessibility identifiers and through herdr itself
  (`session.snapshot`, `pane.read`). Remote tests go through a local `sshd`
  on CI. Trackpad swipes and drags are posted as CGEvents by
  `scripts/swipe.swift` and `scripts/drag.swift`.
- **Unit tests** in `HerdrKit` (`swift test`), only for logic with branches:
  decoding a recorded herdr snapshot, the split-tree rebuild, the equal-split
  ratios, the snapshot pacing (one read in flight, read again), float
  requests, the seen rules, git status parsing, fuzzy matching, program icon
  matching, the terminal stream's frames, the remote command envelope and
  the relay, and `Files` and `Git` (listings, reads, saves, the patch and the
  graph) run through `ProcessExec` and the relay on a real repository.
- **Plugin tests** (`PluginTests`, `FileTests`, `MarkdownTests`,
  `FilesTests`, `GitTests`) open each page in a throwaway session and check the page's
  text and controls through accessibility, and the labels and files through
  herdr and the disk.
