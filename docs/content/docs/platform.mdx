## One codebase

- One Xcode project, one multiplatform SwiftUI app target (macOS, iPadOS,
  iOS), and one local Swift package, `HerdrKit`.
- Minimum OS: macOS 26 and iOS 26 (Liquid Glass; one
  minimum means no fallbacks). Building needs Xcode 27.
- **One main window** (`Window` on macOS, multiple scenes off on iPad), so two
  windows never fight over control of the same panes. The pill panel is the
  only other window, and it opens no terminal stream.
- iPhone uses its own `NavigationStack` layout instead of a collapsed split
  view.
- macOS only: `ProcessExec`, the pill panel, the askpass script, the Local
  Network preflight, scroll routing with `NSEvent`, the AppKit terminal
  subclass, the Dock badge, the `Window` and `Settings` scenes. iOS only:
  `CitadelExec`, the UIKit terminal subclass, the compact layout.
- Signing: macOS has App Sandbox off and Hardened Runtime on, and ships as a
  notarized Developer ID download (it runs the `herdr` CLI and `ssh`). iOS
  ships on the App Store. Citadel is linked for iOS only.

## Dependencies

| Need | Choice | Why |
|---|---|---|
| Terminal drawing | `Lakr233/libghostty-spm`, exact pin, plus uHerdr's `suppressesTerminalResponses` patch (a vendored wrapper; upstreamed if accepted) | Metal, IME, one API on AppKit and UIKit, a built-in iOS key bar; used by bigtty and Heeler. The patch stops libghostty from answering terminal queries that herdr already answered |
| SSH on iOS | `orlandos-nl/Citadel` 0.12.1, exact pin | pure Swift; exec and `direct-tcpip` channels are enough (it depends on a swift-nio-ssh fork, so updates are reviewed) |
| SSH on macOS | the system `/usr/bin/ssh` | the user's SSH setup works unchanged |
| Plugin runtime and web pages | `WKWebView` with a `WKUIDelegate`, wrapped for SwiftUI, one per card | built in; the same plugin runs on both OSes; the delegate sees new-window requests, which SwiftUI's `WebPage` drops |
| Markdown | `AttributedString(markdown:)` | built in |

## Making the strip work

1. **Terminals and web views swallow the swipe.** On macOS one `NSEvent`
   monitor locks the axis at the start of each scroll gesture: a horizontal
   gesture that starts in the strip pages the
   strip; anything else goes to the view under the pointer. On iOS the
   terminal subclass yields its pan gesture when the motion is mostly
   horizontal.
2. **Lazy SwiftUI containers destroy views that scroll off screen.** The
   PaneViewRegistry owns every terminal view, web page and plugin card. Each
   SwiftUI wrapper makes its own container; the newest container adopts the
   view, and a container removes it only if it still owns it. Stream lifetime
   follows the HostStore, never whether a view is in a window. Off-screen
   surfaces stop drawing but keep reading their stream (herdr drops a watcher
   that reads nothing for 30 s). At most about 24 streaming terminals and 6 live web views
   (web pages and plugin cards together; 2 on iPhone), least recently used
   first out; an evicted card keeps its last image. Web page message handlers
   sit behind a weak proxy.
3. **libghostty's default key bindings eat the app's shortcuts.** Every
   surface gets `keybind = clear`, and keys go to the main menu first.

If [spike S1](/docs/build-order#s1-strip) fails, the strip becomes one AppKit or UIKit paging container
(about 300 lines per platform) holding the cached views.

## Tab bar and Liquid Glass

- The tab bar is one `ToolbarItem` with `.sharedBackgroundVisibility(.hidden)`
  (no double glass), holding a horizontal `ScrollView`. v0 has no toolbar
  item: the tab bar is a row in the hidden title bar (phase 3b).
- One glass marker follows the strip's scroll offset
  (`onScrollGeometryChange`). The lit tabs come from the same number: every
  tab from `floor(x/w)` to `ceil((x+w)/w) − 1`. When the scroll stops, the
  selection changes to the page in view. A click on a tab scrolls the strip
  there, so the marker slides as during a swipe; nothing morphs.
- If the toolbar squeezes the item ([spike S2](/docs/build-order#s2-tab-bar)),
  the window hides its title bar and the tab bar sits at the top of the
  detail column with `WindowDragGesture`.
- Each capsule has one status slot: × on the selected or hovered tab, else
  the working dots. The dots are one `TimelineView` at 15 frames a second or
  less, driven by the clock and drawn only while visible; needs you and
  finished are badges on the icon (D42).
- The window title (`navigationTitle`) is "‹tab title› - ‹session›".
- Reference for this Rex-like behavior: the Rex study
  ([`rex-ui.md`](https://github.com/hkandala/oriel/blob/main/resources/research/clients/rex-ui.md)),
  then [gorex](https://github.com/hkandala/oriel/blob/main/resources/research/clients/gorex.md).
  Neither is a reference for the glass API, so spike S2 stays open.
- One `Look` token value per style and appearance draws every surface (D44).
  Glass is only on the Glass style's tab marker and sidebar pill, popovers,
  the palette and floating panels; the sidebar sits flat on the window, pane
  cards are translucent on it, and pills are opaque.

## Other details

- Drag and drop: a `Transferable` pane reference (machine id + pane id),
  declared in the Info.plist. Tab capsules spring-load. During a drag, drop
  zones sit above each card's surface. Drops on another machine are refused.
- iOS key bar: libghostty-spm's `inputAccessoryItems`.
- Plugin bridge: `window.oriel`, injected into each plugin page; every call
  checks the card's machine binding in Swift.

## One test target

Recorded herdr 0.9.3 JSON (snapshot, layouts, closed reasons) and short
transcript samples. It checks: decoding, the
split-tree rebuild, the lit-tab math, the snapshot pacing (one read in flight,
read again), the equal-splits ratios, the label parser (`oriel:` with
and without a pane name, an argument with spaces and `#`), the remote command
envelope (hostile strings round-tripped through bash, zsh and fish), the
state-file write command, the bridge refusing
`run` and `dial` to another machine, and each
transcript parser.
