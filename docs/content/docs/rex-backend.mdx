This page is future work. It is not scheduled. It records how Oriel can talk
to Rex through the same [`Multiplexer` interface](/docs/architecture#the-multiplexer-interface)
that herdr uses, so the work is ready when we pick it up. The full protocol
research is in
[`rex-server.md`](https://github.com/hkandala/oriel/blob/main/resources/research/clients/rex-server.md).
The Rex app's UI is in
[`rex-ui.md`](https://github.com/hkandala/oriel/blob/main/resources/research/clients/rex-ui.md).

## What Rex is

Rex ([superlogical.com](https://www.superlogical.com)) is a terminal
multiplexer for macOS by Superlogical. It has two parts:

- **Rex Server:** a Go program, also the `rex` CLI. One server runs per user
  account and machine. It listens on a Unix socket at
  `~/Library/Application Support/rex/server.sock` (mode 0600). It keeps the
  shells alive and runs one libghostty-vt emulator per terminal.
- **Rex.app:** a SwiftUI and AppKit client with its own libghostty-vt and
  Metal renderer.

The server speaks HTTP/1.1 on the socket. `GET /llms.txt` returns the whole
protocol as Markdown, and `GET /api/help` returns it as JSON with JSON
Schemas. The research used `rex 0.0.1792519967-gd05acf`, API revision 4.

## How the models map

| Rex | Oriel | Notes |
|---|---|---|
| server (host) | machine, and its one `Session` | one server per account and machine; `sessions()` returns one entry |
| session | workspace | ordered; generated label such as `crisp-forest` |
| window | tab | ordered; each session has an `active_window_id` |
| layer `tiled` | the tab's split tree | `split.direction` `horizontal` is `.right`, `vertical` is `.down`; `ratio` is the first child's share |
| layer `floating` | none | skipped (Oriel has no floating panes yet) |
| block | pane and terminal | one stable id, `block:<uuidv7>`, so `Pane.id == Pane.terminalID` |
| client | one Oriel app on one machine | survives a dropped connection for 60 s |

A block keeps its id when it moves between windows. Rex has no separate
terminal id, and none is needed.

## Transport

Rex has no SSH transport. Its client endpoints are the Unix socket, HTTP(S)
and Tailscale. Oriel does not need any of them: a raw WebSocket works over the
socket through `nc -U`, which the research tested.

- Oriel runs `nc -U <socket>` through `Exec.run`. On This Mac this is a local
  `Process`. On a remote machine it is the same argv inside the
  [remote command envelope](/docs/talking-to-herdr#run-and-dial) over SSH.
- The channel carries plain bytes. Oriel speaks WebSocket (RFC 6455) on it with
  a small client of its own: about 150 lines, client masking, text and binary
  frames, ping and pong. `URLSessionWebSocketTask` cannot open a Unix socket.
- `rex server status --json` gives the socket path (`endpoint`) on each
  machine. `rex server start` starts the server. It is idempotent.
- If `nc` is missing, `socat` or `python3` can carry the same bytes.

Each machine has two kinds of WebSocket:

| Socket | Path and subprotocol | Count | Carries |
|---|---|---|---|
| control | `/api/control`, `rex.control.v1` | one per machine | JSON `hello`, `welcome`, `request`, `response`, `event` |
| data | `/api/data`, `rex.data.terminal.v1` | one per shown terminal | binary: handshake, snapshot, then raw PTY bytes |

The control socket opens with a `hello` (`api_revision: 4`,
`client.kind: "app"`, `client.name: "Oriel"`). The `welcome` returns a
`client.id` and a `reconnect_token`. A request is about 0.3 ms on the server,
so Oriel needs no pacing beyond the event rules below.

## RexClient

`RexClient` is the second `Multiplexer` conformer. It owns the control
socket. It sends requests by id and gets responses out of order. It gives
events to one reader.

| `Multiplexer` member | Rex calls | Notes |
|---|---|---|
| connect (in `HostStore`) | control socket, `hello`, then `session.bootstrap {event_scope: "all"}` and `session.attach` for every session | require `api_revision >= 4` |
| `sessions()` | `server.status` | one `Session` per server; `running` means the socket answers |
| `startServer()` | `rex server start` through `Exec.run` | then wait until `server.status` answers |
| `snapshot()` | `session.view {session_id}` per session, in parallel; `com.superlogical.terminal.program_status` per block | the view has every window, the tiled layout with ratios, and each window's `focused_block_id` |
| `updates()` | events on the control socket | see [Events](#events) |
| `refresh()` | `session.view` for each session | revisions make it safe to repeat |
| `pane(id)` | `session.describe_block` and `com.superlogical.terminal.process` | `process.foreground.cwd` is the real cwd, with no OSC 7 needed |
| `program(id)` | `com.superlogical.terminal.process` | nil if the foreground is a shell (its `argv0` starts with `-`) |
| `terminal(...)` | `data.connect`, the data socket, `session.own_block`, `com.superlogical.terminal.resize` | see [RexTerminalStream](#rexterminalstream) |
| `split(pane, dir)` | `session.new_split {anchor_id, direction, side: "after", layout, focus: false}` | `.right` is `horizontal`, `.down` is `vertical` |
| `newTab(workspace, cwd)` | `session.new_window {session_id, layout: {block: {flavor, options: {cwd}}}, focus: false}` | returns `window_id`. `focus` defaults to true, so always send false |
| `newWorkspace(cwd)` | `session.create {initial_windows: [...]}`, then `session.attach` | returns the first `window_id`. `create` does not attach |
| `close(pane:)` | `block.close {session_id, block_id}` | closes the window too if it was the last block |
| `close(tab:)` | `session.close_window {session_id, window_id}` | |
| `sendKeys(keys, pane)` | `client.key {session_id, block_id, key}`, one per key | ordered with other input; see [Input](#input) |

The designed actions that are not in the interface yet also map one to one:
rename (`session.set_label`, `set_window_label`, `set_block_label`), divider
drag (`session.resize_pane`, named by the two blocks on its sides), swap
(`session.swap_blocks`), move (`session.move_block`, `move_window`,
`session.move`), close workspace (`session.destroy`), and read pane text
(`com.superlogical.terminal.format {format: "text", trim: true, unwrap: true}`,
with scrollback).

The flavor for a new shell is `com.superlogical.terminal.shell`.

### Events

One control socket carries all events. Each event has a `seq` that starts at 1
and has no gaps. A response carries the `seq` of the last event before it.
So Oriel applies the response, then only events with a higher `seq`.

- `session_view_changed {revision}`: read `session.view` again for that
  session, but only if the revision is higher than the one Oriel holds. These
  events can arrive out of order.
- `session_created`: attach the new session, then read its view.
  `session_destroyed`, `session_moved` and `session_label_changed` change the
  workspace list.
- `block_event` with `program_status_changed` or `program_status_removed`:
  update the agent status in place.
- `block_event` with `process_changed` or `pwd_changed`: update the pane's
  program and cwd.
- A close with 1008 (`event backlog exceeded`), or a dropped socket: connect
  again, send `reconnect_token`, bootstrap and read every view again. Events
  in the gap are lost.

herdr's events carry no state, so Oriel reads a snapshot after each one (D5).
Rex's revisions let Oriel skip a read when the view did not change.

## RexTerminalStream

Rex streams raw PTY bytes, not a redrawn screen. Oriel's libghostty surface
is then the second copy of the terminal: the server keeps the first.

### Open a stream

1. Call `data.connect {session_id, block_id, data_ref_id: "terminal", subprotocol: "rex.data.terminal.v1"}`
   on the control socket. It returns a one-time ticket that is good for 60 s.
2. Open the data socket on a new `nc -U` channel. Within 5 s, send the binary
   HELLO: `01` and the 16 ticket bytes.
3. Read the 32-byte WELCOME: `81`, a 16-byte reconnect token, 3 zero bytes, a
   u32 keep time in ms and a u64 nonce. A REJECT is `82` and a reason byte.
4. Read the rest as one byte stream. Message boundaries carry no meaning.

### The snapshot

The stream starts with a `GHOSTSNP` snapshot: libghostty-vt's own binary
format, with the screen, the modes and the scrollback. It has a 10-byte header
(`"GHOSTSNP"` and a u16 version), then records of
`[u16 tag][u32 len][u32 crc32c][payload]`. The FINISH record (tag 6) ends it.

libghostty-spm, the library Oriel uses, has no snapshot decoder. So:

- **First version:** walk the record framing to the FINISH record (about 20
  lines) and drop the snapshot. Seed the screen with
  `com.superlogical.terminal.format {format: "vt"}` and every `extra_*` flag
  on. Then apply the live bytes. Output in the few ms between the snapshot and
  the `format` reply is drawn twice. Shells and agent TUIs redraw, so this is
  harmless. `format` fails with `too_large` above 1 MiB, so the app then sends
  `trim` or starts with no history.
- **Later:** decode the snapshot with libghostty-vt
  (`ghostty_snapshot_decoder_*`), format it as VT and feed that to the
  surface. This is exact, but it adds a second binary dependency. The format
  is "v1, work in progress", and it must match the libghostty version in Rex.

### Live bytes and Rex messages

After the snapshot come the program's raw bytes. Rex puts its own messages in
the stream as APC sequences: `ESC _ rex1;<nonce>;<json> ESC \`. The types are
`resize`, `theme` and `child_exited`. A `resize` and usually a `theme` come
right after the snapshot.

- Strip each APC whose nonce matches the WELCOME nonce. Keep a carry buffer,
  because an APC can span two messages. A theme APC is about 3 KB.
- Pass an APC with another nonce through as output: a program printed it.
- Resize the local emulator at the `resize` APC, not when the card changes
  size. No full frame follows a resize. The program redraws after SIGWINCH.
- `child_exited` ends the program. The data socket then closes with 4000
  (`block closed`) when the block closes.

### Size, scrollback and queries

- The owner sets the PTY size with `com.superlogical.terminal.resize` and the
  colors with `set_theme`. A non-owner's resize is only recorded as
  "desired".
- A watcher gets bytes for the owner's grid. Its surface grid must stay at the
  APC size, and the card clips or scales it.
- The scrollback is Oriel's own: the snapshot's history plus live output. The
  surface keeps a real scrollback limit, and the wheel scrolls it locally.
- The server answers terminal queries (DA, OSC 10 and 11). The surface keeps
  `suppressesTerminalResponses` on, as under herdr.

### Input

All input goes on the control socket. Data sent on the data socket after the
WELCOME is ignored.

- Keys: `client.key {session_id, block_id, key}`. The key object has the same
  fields as libghostty's `ghostty_input_key_s` (`key`, `mods`,
  `consumed_mods`, `text`, `unshifted_codepoint`, `composing`, `action`). So
  the surface forwards every key event as it is, and the server encodes it for
  the program's modes. The split between text and `sendKeys` goes away.
- Typed text: `client.action {action: "com.superlogical.terminal.write", args: {data}}`.
  This keeps text in order with keys. A direct `terminal.write` is not ordered.
- Paste: `block.event {type: "paste"}`. The server adds bracketed paste when
  the program asks for it.
- Mouse and wheel: `block.event {type: "mouse"}` and `{type: "wheel"}`, only
  while the program has mouse reporting on. Otherwise the local surface
  scrolls and selects. Outside mouse mode, the server scrolls and selects on
  its own shared copy, which Oriel does not use.
- Focus: `block.event {type: "focus"}`, only with mode 1004 on.

### End and resume

| Event | The app |
|---|---|
| close 4000 | drops the card; waits for the view |
| socket drops | sends RESUME (`02`, the latest token, a u64 count of stream bytes read) within 60 s; output from the gap arrives |
| RESUME fails | opens a new stream with a new ticket |
| close 1000 from the app | the app stopped showing the card; it then calls `session.disown_block` if it owned the block |

## Agent status

Rex agents report status with OSC 7501, the Program Status Protocol that Rex
designed. The server parses it and keeps records per block: `state` (`idle`,
`working`, `done`, `blocked`, `error`), `kind` (`permission`, `question`,
`auth`), `progress`, `app`, `title` and `msg`.

Oriel reads these records through the API, with
`com.superlogical.terminal.program_status` and the `program_status_changed`
and `program_status_removed` events. It never parses OSC 7501 in its own
surfaces. This keeps D55: status comes only from the multiplexer's API, and
every device agrees.

- A block's status is its strongest record: `blocked`, then `working`, then
  `done` or `error`, then `idle`. `error` shows as done with the word
  "failed".
- Workspace and tab status fold their blocks, as herdr's do.
- Rex has no `completion_seq`. Oriel uses a `done` record's `updated_at` as
  the finish marker. "Seen" stays in the app, keyed by block, record id and
  `updated_at`.
- Codex sends OSC 7501 itself. An agent that does not (Claude Code, for
  example) has no record. Oriel then knows the agent only by
  `process.foreground.name`, with no status.

## Ownership

A Rex block has at most one owner client. The owner sets the PTY size and
theme. Anyone attached can stream it, type into it and close it. This is close
to herdr's control and observe, and D8 maps onto it:

| D8 step | Rex |
|---|---|
| Mac opens without takeover | `session.own_block {block_ids, mode: "request"}` |
| refused: watch, show Take Back | the result's `owner` is not Oriel's client id |
| first key, paste or click, or Take Back | `session.own_block {mode: "take"}` |
| "taken over" | `block_owner_changed {previous: <me>, reason: "take"}` |
| iPhone and iPad watch | no `own_block` call; stream only |
| card no longer shown | close the data socket, then `session.disown_block` |

Two differences matter:

- A watcher can still type in Rex. Oriel keeps its own rule: a key press in a
  watching card takes control first, so the PTY size follows the device that
  types.
- When the owner leaves, Rex hands the block to the next claimant in line.
  herdr does not. Oriel shows the new state from the `block_owner_changed`
  event and does not take back by itself.

Rex.app claims the blocks that it shows. If Rex.app and Oriel show the same
block, ownership moves between them on each claim. This is accepted.

## Focus

Focus is shared server state in Rex: each session has an active window, and
each window has a `focused_block_id`. The rules of D13 apply:

- Every create call sends `focus: false`. `session.new_window` defaults to
  `focus: true`.
- Oriel never calls `session.focus_*`.
- `session.zoom_block` moves focus to its block unless the call names the
  `window_id`. Zoom stays the app's own ([Zoom](/docs/layout#zoom-is-the-apps-own)).
- `session.swap_blocks` and `session.move_block` can move focus with the
  block. Oriel calls them only after a drag, as with `pane.swap`.
- Oriel reads `focused_block_id` once, for the first selection, as it does
  with herdr.

## Changes to HerdrKit

Today a second backend cannot build the app's model types from outside
`HerdrKit`. These changes come first, each as small as it can be:

1. Public memberwise inits for `Snapshot`, `Workspace`, `Tab`, `Pane`,
   `Agent` and `SplitNode`. They have only decoding inits now, and
   `Snapshot.trees` has an internal setter.
2. `TerminalStream` as a struct of closures (`events`, `input`, `resize`,
   `scroll`, `mouse`, `close`). Today it parses herdr's NDJSON from a
   `Channel` and its init is internal.
3. A byte `Channel`. Today `Channel` gives stdout as UTF-8 lines. The
   WebSocket frames need raw bytes in and out.
4. A neutral error. `HerdrError` is the error type of `Update.error` and
   `HostStore.State` today. Its messages name herdr commands, such as
   "Restart herdr on This Mac". It becomes an error with a fix string that
   the backend gives.
5. `HostStore` picks the backend per machine. It names `HerdrClient` in one
   place today.
6. A lookup for `rex` like the one for herdr. `Exec.herdr()` asks the login
   shell for herdr's absolute path (D38). A Rex client needs the same for
   `rex`, or for `nc` and the socket path from `rex server status --json`.

The terminal path in `PaneTerminal` then branches on the backend: a real
scrollback, all keys through `client.key`, and wheel events sent only in mouse
mode.

## Testing

Tests never touch the user's Rex server. Each e2e run starts an isolated
server on its own socket, and the app connects to that socket:

```sh
rex server run --listen unix:///tmp/oriel-e2e.sock
```

The run creates sessions named `oriel-e2e-*` and stops the server at the end.
The same rules as for herdr apply: existing sessions are read only, and
Oriel never calls focus methods.

## Risks

| Risk | Effect | Plan |
|---|---|---|
| GHOSTSNP is "v1, work in progress" | a decoder breaks after a Rex update | first version skips the snapshot and seeds with `format vt` |
| The resize APC races the card size | wrapped or broken lines | resize the surface only at the APC |
| A watcher gets the owner's grid | clipped or scaled cards on small screens | pin the surface grid to the APC size |
| Rex.app and Oriel claim the same block | the PTY size changes hands | accepted; Take Back as with herdr |
| Agents without OSC 7501 | no status for those agents | show the agent by process name only |
| `nc` missing on a machine | no connection | `socat` or `python3`; a clear message |
| `format` over 1 MiB | no seeded history | `trim`, or start with no history |
| Oriel shows in `rex client ls` and Rex.app | other users see the client | accepted; the hello names it "Oriel" |
