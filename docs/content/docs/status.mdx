## Agents and notifications

- Tab capsules, workspace rows, the Agents button and view, the hover card, notifications and the
  Dock all read `agent_status` and `completion_seq` from the
  snapshot. No extra calls.
- Status comes only from the multiplexer's API (D55), never from
  [OSC 7501](/docs/reference/glossary) ([Future work](/docs/future-work)).
- **"Finished, not seen"** = `completion_seq` in `snapshot.agents[]` is not
  null and differs from the value this device recorded as seen. How "seen"
  works: [Selection and "seen" are the app's own](/docs/layout#selection-and-seen-are-the-apps-own).
- Each agent pane is needs you (herdr's `blocked`), working, finished (not
  seen) or idle. herdr's `done` is not used. A tab and a workspace show the
  strongest state of their panes: needs you, then finished, then working,
  then idle.
- Looking at a pane means its tab is selected on the page in view and the
  window is key. Looking records its finish as seen.
- Each change carries the time the app saw it. The Agents view shows its age
  from that time.

### Agents

The Agents button (D61) covers the session of the page in view.
- **The dot.** The button shows an amber dot while an agent of that session
  needs you.
- **Hover.** Resting the pointer on the button for 0.25 s lists the agents of
  that session that need you. A click on one selects its workspace, tab and
  pane; the sidebar does not change.
- **Agents view.** A click, ⌘. or View ▸ Show Agents turns the sidebar page into the list of every
  agent pane of that session, idle ones too, sorted by priority (needs you,
  working, done, idle) or by workspace, in groups that fold. A click on a row selects that
  workspace, tab and pane and gives the pane the keyboard, so its finish is
  seen.

The look is in [Main window: Agents button](/docs/ui/window#agents-button)
and [Agents view](/docs/ui/window#agents-view).

### Notifications

The app makes notifications itself, from snapshot changes, for every session
open in any window. Each change posts once, even when several windows show
the session:
- A pane's status becomes `blocked`: "codex needs you", with "‹session› ·
  ‹workspace› · ‹tab›" as the body.
- `completion_seq` changes to a new non-null value: "pi finished", with the
  same body.
- None for the pane the user is looking at. While the app is active, the
  others still show as banners.
- The first snapshot after app launch, or after a page opens, never
  notifies. After a reconnect, changes against the last known state do
  notify.
- The id is `"<machine>|<session>|<terminal_id>"` (`local` for This Mac), so
  a newer notification replaces the older one. It is removed when the user
  looks at the pane, and when its state no longer holds (the pane works,
  idles, closes or loses its agent).
- A click activates the app, shows that page and selects the pane.
- The app asks for permission (alerts and the badge) at launch; macOS asks the
  user only once.
- Notifications are on for needs you and for finished; the Dock badge counts
  needs you only; no sounds. These are fixed ([Settings](/docs/ui/settings)).

### macOS

- `UNUserNotificationCenter`. Its delegate is set at launch, in the app
  delegate (`NSApplicationDelegateAdaptor`), so a click that starts the app
  is not lost.
- **Dock badge:** the number of panes that need you, over every open page.
- **Sounds:** none.
- **Dock menu:** a row per pane that needs you or finished ("codex needs you ·
  default · infra"; a click selects it), a separator, then New Tab.
