## Agents and notifications

- Tab capsules, workspace rows, the Agents button and view, the hover card, notifications, the
  Dock and the pills all read `agent_status` and `completion_seq` from the
  snapshot. No extra calls.
- Status comes only from the multiplexer's API (D55), never from
  [OSC 7501](/docs/reference/glossary) ([Future work](/docs/future-work)).
- **"Finished, not seen"** = `completion_seq` in `snapshot.agents[]` is not
  null and differs from the value this device recorded as seen. How "seen"
  works: [Selection and "seen" are the app's own](/docs/layout#selection-and-seen-are-the-apps-own).
- Each agent pane is working, needs you, finished (not seen) or idle. A tab
  and a workspace show the strongest state of their panes: needs you, then
  finished, then working.
- Each change carries the time the app saw it. The Agents view shows its age
  from that time.

### Agents

The Agents button replaces Activity (D61). It covers the session of the
window's current page.
- **The dot.** The button shows an amber dot while an agent of that session
  needs you.
- **Hover.** Resting the pointer on the button for 0.25 s lists the agents of
  that session that need you. A click on one selects its workspace, tab and
  pane; the sidebar does not change.
- **Agents view.** A click or ⌘. turns the sidebar page into the list of every
  agent pane of that session, idle ones too, sorted by priority (needs you,
  working, done, idle) or by workspace order. A click on a row selects that
  workspace, tab and pane and gives the pane the keyboard, so its finish is
  seen.

The look is in [Main window: Agents button](/docs/ui/window#agents-button)
and [Agents view](/docs/ui/window#agents-view).

### Notifications

The app makes notifications itself, from snapshot changes:
- A pane's status becomes `blocked`: "codex needs you", with "‹session› ·
  ‹workspace› · ‹tab›" as the body.
- `completion_seq` changes to a new non-null value: "pi finished", with the
  same body, unless the user is looking at that pane.
- The app posts them only while it is not active or the pane is not shown.
- The first snapshot after app launch never notifies. After a reconnect,
  changes against the last known state do notify.
- The id is `"<machine>|<session>|<terminal_id>"`, so a newer notification
  replaces the older one. It is removed when the pane is seen.
- A click opens the app at that pane.
- Settings ▸ Notifications has, for needs you and for finished: Notify (on),
  Badge the Dock icon (on for needs you, off for finished) and Play a sound
  (off) ([Settings](/docs/ui/settings)).

### macOS

- `UNUserNotificationCenter`. Its delegate is set at launch, so a click that
  starts the app is not lost.
- **Dock badge:** the number of panes that need you, plus the finishes not
  seen while that setting is on.
- **Sounds:** one system sound per status, "Funk" for needs you and "Glass"
  for finished, off by default.
- **Dock menu:** a row per pane that needs you or finished ("codex needs you ·
  default · infra"; a click selects it), a separator, then New Tab.
- While the pill is on screen, notifications are posted as `.passive`
  (Notification Center, no banner). The exception is when VoiceOver or Switch
  Control is on, because those users cannot reach the pill.

### iOS

- The same notifications, while the app is open or within its ~30 s
  background time.
- No push in v1: the iPhone shows status while the app is open. Alerts while
  the app is closed need a small relay that forwards encrypted payloads to
  Apple's push service ([Future work](/docs/future-work)).

## Floating pills: how they work (macOS)

The look and behavior are in [Floating pills (macOS)](/docs/ui/pills).

- **When:** the pill shows whenever the app is not active, and hides when it
  becomes active. Two notifications drive it, plus screen changes for
  placement. Nothing polls. The only timer is the peek's 8 s shrink. It
  appears on the screen under the pointer. A setting turns the pill off.
- **One AppKit `NSPanel` hosting SwiftUI.** No SwiftUI scene can do this:
  `UtilityWindow` hides when the app is inactive, and a floating `Window`
  activates the app when clicked.
- One fixed-size transparent panel on the right edge holds the pill, list and
  pill card, so it never resizes. Transparent parts let clicks through.
- **Panel settings:**
  ```swift
  // in init
  styleMask = [.borderless, .nonactivatingPanel]
  level = .floating
  collectionBehavior = [.canJoinAllSpaces, .stationary, .ignoresCycle,
                        .fullScreenAuxiliary, .canJoinAllApplications]
  hidesOnDeactivate = false
  canHide = false
  becomesKeyOnlyIfNeeded = false
  hasShadow = false
  backgroundColor = .clear
  // ignoresMouseEvents is never set: transparent pixels pass clicks through
  ```
- **Keyboard:** a borderless panel cannot become key by default. So
  `PillPanel` overrides `canBecomeKey` to return true only while a pill card
  is open and has been clicked.
- **First click:** `PillPanel.sendEvent` catches a mouse-down inside a pill
  card that is not key, makes the panel key, and swallows the event. A pill, a
  list or a peek never takes a keystroke from the app the user is typing in.
- After the pill card closes or a reply is sent, the panel orders out and
  back in, which hands the keyboard back.
- An `NSTrackingArea` with `.activeAlways` tells the peek that the pointer is
  over it (SwiftUI hover is unreliable in an inactive app).
- **Same data and rules:** glyphs and pill cards read the HostStore snapshot.
  The pill card is the chat view, so it never opens a terminal stream. Its key
  buttons use the key guard
  ([Sending and answering](/docs/chat-view#sending-and-answering)). Peeking
  or opening a pill card does not mark an agent seen. **Mark seen**, a reply
  or **Open in app** does.
- **Accessibility:** each glyph and row has a label ("codex, needs you,
  infra") and an Open action. The pill is never the only path. The Agents
  view, notifications and the Dock badge remain.
- Simpler choices: no dragging, no notch placement, no global hotkey, no
  per-workspace pills. Revisit each one when users ask for it.
