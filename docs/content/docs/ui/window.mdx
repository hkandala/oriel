## Windows

![Two windows on the same session: one controls, one watches](/mockups/J.jpg)

- Each window shows one machine
  ([What a machine is](/docs/machines#what-a-machine-is)). File ▸ New Window
  (⌘N) opens another window on the same machine (D34). Two windows can show
  different machines or the same machine.
- Two windows on the same machine share the live data of each session. Each
  window keeps its own selection: page, workspace, tab, keyboard card, zoom,
  sidebar view and sidebar width.
- A new window opens in the middle of the screen at 90 % of its size, at
  least 1200 × 760 pt and at most the screen's size. A window macOS restores
  keeps its frame. Zooming the window (⌥-click on the green button) fills the
  screen.
- Control is per session (D66). When two windows show the same session, the
  window where the user last typed or clicked in a terminal controls that
  session's panes. The other window watches: its cards dim a little and a
  [control capsule](#control-capsule) offers **Take Back**. Two windows on
  different sessions each control their own session.

## Title row

One row, 46 pt tall as in Rex, always the same (D45). While the sidebar is
open, the traffic lights, the sidebar toggle and the machine button sit in a
leading area as wide as the sidebar, so the first tab starts where the cards
start, also during a resize. From left to right:
1. The traffic lights, centered on the row at 23, 46 and 69 pt from the
   left, where Rex has them. The window keeps AppKit's compact toolbar (whose
   own row is 40 pt) and moves the three standard buttons with plain frame
   changes, again after every AppKit layout; full screen has none. The row's
   items start 91 pt in, so the sidebar toggle sits where Rex has it.
2. The sidebar toggle, always shown outside the overview (⌃⌘S). It has no highlight when the
   sidebar is open. The icon changes instead: an outline window with a sidebar
   line while the sidebar is closed (`sidebar.left`), and the sidebar part
   filled while it is open (`sidebar.left` under
   `rectangle.leftthird.inset.filled`). The sidebar slides in and out over
   0.3 s, and does not slide under Reduce Motion. Each window keeps its own
   choice. Items in the row are 8 pt apart.
3. The [machine button](#machine-button).
4. The [workspace button](#workspace-button), only while the sidebar is
   collapsed.
5. The [tab bar](#tab-bar): the selected workspace's tabs, whether the sidebar
   is open or collapsed.
6. A spacer.
7. The [Agents button](#agents-button).
8. The [overview](#overview) button (⌃⌘O).
9. ⌘ (the command palette, ⌘K) and `+` (new tab, ⌘T).

While the overview is open the row shows only the traffic lights and one ×
that leaves it ([Overview](#overview)).

Each title-row button except the Agents button shows the system tooltip with
the action's name and its shortcut, for example "New Tab ⌘T". So do the page
header's `+`, the footer's Open Session button and each card header button.

The window title is "‹tab title› - ‹page title›" (the page in view's sidebar title: the machine's name for
`default`), so the
Window menu and Mission Control show it.

## Machine button

![The machine menu](/mockups/E.jpg)

- The machine's icon alone: no chevron and no name. This Mac is a
  laptop when it has an internal battery, else a desktop.
- The menu lists the machines, each with its icon and name, and a checkmark
  on the current one. Then "Open Session…" (the window's Open Session panel,
  as ⌥⌘T, for the machine's other sessions), "Add Remote Host…" and, with
  remote machines in the list, "Edit Remote Host ▸" with each of them
  ([Add a machine](/docs/ui/add-a-machine)).
- Picking another machine brings its window forward (the one used last, when
  there are several); with none open, a new window on it opens with its
  `default` session. This window and its pages stay. Picking the window's own machine
  does nothing (⌘N opens another window on it).
- macOS 27 draws no images in these menu rows, so there only the names show.

## Workspace button

![Sidebar collapsed, workspace menu open](/mockups/D.jpg)

Shown only while the sidebar is collapsed, after the machine button.
- An outline folder icon, then "‹page title› | ‹workspace›" (the sidebar page header's title, so the
  machine's name for `default`): the title in the
  title row's chrome color, a thin vertical line in the divider color, the
  workspace in the selected title color, a step brighter, all semibold. Then
  a chevron. At most 260 pt wide: the session name stops at 110 pt (with an
  ellipsis), and a workspace name that does not fit fades out at its end over
  16 pt.
- The menu starts with a filter field ("Filter or create…"). Then one group
  per page open in this window, in page order, under the session's name. A
  row shows the workspace's state icon, its name and its branch on the right.
  At the end: New Workspace, then "Open Session…" (⌥⌘T).
- The menu is a glass panel under the button, 300 pt wide, its list at most
  340 pt tall, built from the palette's filter list. Rows are 26 pt. The arrows
  or the pointer move the highlight, Enter acts, Esc closes. A typed name that matches no workspace shows
  "New Workspace “‹name›”" first; Enter makes it in the session of the page
  in view and selects it.
- Picking a workspace of another page also shows that page.

## Tab bar

The tab bar is always in the title row. The sidebar never lists tabs (D45).
One capsule per herdr tab of the selected workspace (D42).
- **Track.** A capsule 34 pt tall sits behind the tabs. It is hidden when the
  workspace has one tab; Classic dark has none, as in Rex.
- **Width.** Every tab is 220 pt wide and never shrinks. When the tabs do not
  fit, the bar scrolls sideways (a scroll gesture over it), and a 24 pt fade
  shows on each end that has tabs out of view. A click selects a tab where it
  is, with no scroll; a tab selected another way (keys, the palette, a new tab)
  comes into view at once, without motion. A tab or a pane dragged and held
  near either end of the bar scrolls it (the scroll view's own drop scroll).
- **Dividers.** 1 pt wide, 18 pt tall, centered between
  tabs. A divider next to the selected, a lit or the hovered tab is hidden. They
  fade over 0.2 s.
- **Selection.** One marker follows the strip as it scrolls, so it sits
  between two capsules while the strip is between their pages. It is 30 pt
  tall and fully round, 2 pt inside the track, as in Rex. Only a scroll gesture
  or a mouse's sideways wheel slides the strip, and the marker with it (Rex's
  spring, stiffness 520, damping 46; Reduce Motion makes it jump). Any other
  switch (a click, +, ⌘T, ⌘1…⌘9, ⇧⌘[ and ⇧⌘], the palette, a close) shows the
  tab's page at once. Glass draws the marker as a Liquid Glass capsule, Classic
  as a plain raised pill.
- **Close.** When the selected tab closes, the window selects the tab used
  before it (the latest one still open), else the tab on its left, else the
  new first tab.
- **Hover.** The hovered tab gets the hover fill over 0.14 s, the same shape
  as the selection; the whole 34 pt slot takes the clicks.
- **Content.** The program icons (11 pt in from the track's edge), the title
  (10 pt after them; the selected tab's in white 0.9 or black 0.9, the others
  in the title row's chrome color), and one status slot. A tab with
  several panes shows its panes' icons overlapping: up to 5, 4 pt apart, the
  keyboard card's icon in front. A tab with one pane shows one icon
  ([Program icons](/docs/ui/program-icons)).
- **Title.** One line. When it does not fit, its end fades out over 16 pt; it
  never shows an ellipsis. The folder part is in secondary text. The title is
  herdr's tab label. When the label is herdr's default (only digits), the
  title is the keyboard card's program and its folder's name, for example
  "zsh ~" or "pi oriel" (D65). Until the program is known (a new tab's first
  second), the title is "New Tab", never the number.
- **Status slot.** × only on the hovered tab (a 22 pt hit area over the
  title's fade, so the tab's width never changes). Otherwise three working dots, on every tab with a
  working agent, the selected one too. Needs you
  and finished are badges on the front icon
  ([Theme and accessibility](/docs/ui/theme-and-accessibility#status)).
  VoiceOver reads the state in the tab's value: "codex, needs you".
- **Announcement.** When a tab that is not selected turns to needs you or
  finished, its icons bounce once (1 → 1.15 → 1, a spring) and its title shows
  "‹agent› needs you" or "‹agent› finished" for 3 s. A long text fades at its
  end like any title. Reduce Motion turns the bounce off.
- **Context menu** on a capsule: Rename Tab, Move Tab Left, Move Tab Right,
  Close Tab, Close Other Tabs, Close Tabs to the Right. The last two are also in
  the File menu and the palette, for the selected tab. Each asks once, with
  what runs and the total pane count, only when a program besides the shell
  runs in one of the panes. Rename (or a double-click anywhere on the capsule) puts a
  text field in place of the title: Enter saves, Esc cancels.
- **Keycap hints.** If the user holds ⌘ for 0.7 s while the window is key,
  each of the first nine capsules shows a keycap "⌘1"… at its end, where the
  working dots sit, or left of the × while hovered; the title fades out before
  it, and never runs under it. The workspace rows show theirs at the same
  time. The keycaps fade in over 0.13 s and out over 0.1 s when ⌘ is released.
- Drag a capsule to reorder the tabs ([Drag and drop](/docs/ui/drag-and-drop)).
- Rest the pointer on a capsule to see the [hover card](#hover-card).

## Agents button

![Hover on the Agents button: who needs you](/mockups/G.jpg)

- A list of statuses (`list.bullet.rectangle`), after the tab bar. While the
  [Agents view](#agents-view) is on, it is filled
  (`list.bullet.rectangle.fill`); the button has no highlight and no tooltip.
- A 7 pt amber dot shows when an agent of the page in view needs you.
- A click, ⌘. or View ▸ Show Agents (checked while on) turns the Agents view
  on and off (D61). Turning it on with the sidebar collapsed opens the
  sidebar in the Agents view. Turning it off shows the workspaces; the
  sidebar stays open. A click gives the keyboard back to the keyboard card.
- **Hover.** When the pointer rests on the button for 0.25 s, a glass panel
  hangs under it: 320 pt wide, at most about 480 pt tall. It lists the agents
  of the page in view that need you, under the header "Needs you ·
  ‹page title›" (11 pt, secondary; the title as in the [page header](#sidebar)). The rows are the same as in the Agents view.
  A click on a row selects that workspace and tab and gives the pane the
  keyboard; the sidebar does not change. With nobody waiting it does not
  show at all. There is no footer. A click on the button is not a rest: the
  panel opens only after the pointer leaves the button and comes back.
- The panel stays while the pointer moves into it (0.15 s grace). It closes
  when the pointer leaves both, on a click or a scroll outside it, or with
  Esc. It does not open while a mouse button is down. It fades and grows in
  from 0.97 over 0.13 s.
- The panel is drawn inside the window, not as a popover window, so the
  terminal keeps the keyboard. It is drawn over the whole window, so no
  scroll view clips it. The hover card uses the same panel.

## Sidebar

Flat on the window background, with no panel (D44). Arc-style pages, one per
session open in this window (D43).
- **Open sessions, not all sessions.** A window starts with one page: the
  machine's `default` session, started if it is stopped. It never loads the
  other sessions by itself. The user adds pages with
  [Open Session](#open-session), as many as they like. Only open pages have a
  `HostStore`, snapshot reads and an event stream.
- **Detach Session.** The context menu of the page header and of its page dot
  has Detach Session (also in the File menu). It removes the page from this
  window. Its store disconnects, so its event stream and its terminal streams
  end. The herdr session keeps running and stays in the Open Session list.
  Detach Session is disabled on the last page. The UI says "session", never
  "page": Window ▸ Previous Session and Next Session show the page before or
  after.
- **Restore.** Windows come back after a normal quit too: Oriel registers
  `NSQuitAlwaysKeepsWindows` in its own defaults, so the system's "Close
  windows when quitting an application" setting does not apply to it (a
  user's own `defaults write` still wins). A window that macOS restores opens
  the pages it had again,
  each with its selected workspace and tabs. A session that no longer runs is
  skipped, and a workspace or tab that is gone falls back to herdr's focus. A
  window never comes back in full screen: one that macOS restores in full
  screen leaves it. A new window (⌘N) opens with `default` only
  ([Data](/docs/data#which-pages-a-window-opens)).
- **Pages.** A sideways swipe on the sidebar moves to the next or previous
  open page ([Swiping](/docs/ui/swiping)).
- **Page dots.** At the bottom of the page, above the footer: one 6 pt dot per
  open page, 6 pt apart. The current page's dot is in primary text color, the
  others tertiary. A click on a dot shows its page. Hidden while one page is
  open. VoiceOver reads each dot as its page's title (the page header's).
- **Page header.** The session's name, the page's title (13 pt bold, the
  rows' size, primary, as in the Agents view); for a machine's `default`
  session, the machine's name instead: This Mac's own name (System Settings,
  "Hari's MacBook Pro") or the remote machine's name from the list. The Open
  Session panel and the palette keep the real names. 22 pt in
  from the window's edge and 3 pt above the first row, and, at the trailing
  end, a `+` that makes a new workspace in that session, in `$HOME`. The
  snapshot after it selects the new workspace.
- **Middle.** The [workspace rows](#workspace-rows), or the
  [Agents view](#agents-view) while it is on. 18 pt fades show at the top and
  bottom of the list when content is under them.
- **Empty session.** A session with no workspace shows a New Workspace
  button on its page. The strip shows no button, only an icon and "This
  session is empty" (the user's words, phase 28).
- **Footer.** The filter field and one button, **Open Session** (⌥⌘T), which
  opens the [Open Session](#open-session) panel. The filter keeps the rows
  whose name or branch matches. A matching worktree also keeps its
  repository's row. The footer has no New Workspace and no Add Remote Host:
  the page header has `+`, and the machine menu has Add Remote Host.
- **Width.** 240 pt by default, from the window's edge to the cards, as in
  Rex: the rows sit 10 pt in from the window's edge, and the 8 pt handle lies
  over the gap before the cards. Drag the handle to resize it between 227
  and 480 pt. Each window keeps its own width. During
  the drag the strip keeps its pages whole.

The sidebar never shows tabs, and its bottom never shows agent activity.

## Workspace rows

One row per herdr workspace of the session, in herdr's order, like herdr's
Spaces panel.
- **Line 1.** A 14 pt state slot and the name (13 pt). The state icon is the
  strongest state of the workspace's panes: a 7 pt amber dot (needs you), the
  three working dots (working), a 7 pt green dot (finished, not seen), a 7 pt
  gray ring with a 1.5 pt stroke (an idle agent), or a quiet 4 pt dot in the
  tertiary color (no agent), so the slot never looks empty. The
  workspace menu rows show the same icons. VoiceOver adds the state word to
  the row's value.
- **Line 2**, only for a git repository: a branch glyph, the branch, then
  ↑ahead in the finished color and ↓behind in the error color when they are
  not zero. All 11 pt, secondary. There is no changed-file count. A workspace
  that is not a git repository has one line and no text about git (D67,
  [Git status](/docs/talking-to-herdr#git-status)).
- **Size.** 44 pt with two lines, 30 pt with one, 2 pt apart. The selected
  workspace is a raised pill, radius 10.
- **Worktrees.** A workspace that herdr marks as a linked git worktree
  (`worktree.is_linked_worktree`) sits right after the workspace with the same
  `repo_key` that is not a linked worktree. It is indented 14 pt, with a 1 pt
  guide line in the separator color from its repository's state slot down.
  With no such workspace in the session, it is a normal row.
- **Keycap hints.** If the user holds ⌘ (with the tabs' keycaps) or ⌃⌘ for 0.7 s while the window is key,
  each of the first nine rows (in the order ⌃⌘1–9 jumps) shows a keycap
  "⌃⌘1"… at the end of its first line; the name gives way to it and never runs
  under it. Same look and fades as the tabs' keycaps.
- **Click** selects the workspace in the app only ([Selection and "seen" are
  the app's own](/docs/layout#selection-and-seen-are-the-apps-own)).
- **Context menu.** New Tab, Rename Workspace, Move Up, Move Down, Close
  Workspace.
  - New Tab opens in the folder of that workspace's keyboard card, or `$HOME`.
  - Move Up and Move Down move a group past the next group. A group is a
    workspace and its worktrees. Both are disabled on a worktree row (it
    moves with its repository) and at the ends.
  - Close Workspace asks only when a program besides the shell runs in one of
    its panes, with what runs and the tab and pane count. On a repository
    with worktrees it also closes their workspaces, and the dialog says so.
    The worktrees stay on disk.
- **Rename.** Rename Workspace, or a double-click on the name, puts a text
  field in its place: Enter saves, Esc cancels. An empty or unchanged name
  sends nothing.
- VoiceOver reads the branch with the ahead and behind counts, and "worktree
  of ‹repository›" for a worktree row.
- Drag a row to reorder the workspaces
  ([Drag and drop](/docs/ui/drag-and-drop)).

## Agents view

![The Agents view of one session](/mockups/H.jpg)

The Agents button turns the sidebar page into a list of the agents of that
session only (D61). A sideways swipe or a page dot shows the next open
session's agents. The page dots and the footer stay.
- **Header.** The page's title (the session's name, the machine's name for `default`, as in the
  page header; a long name shortens in its middle) and,
  on the same baseline, a sort menu: **Priority** (the groups Needs you, Working, Done and Idle,
  each with a count, herdr's order inside a group) or **Workspace**
  (the groups are the workspaces, under each name with a count, in herdr's order of
  workspaces, tabs and panes). Priority is the default.
  Each window keeps its choice. The name starts on the edge of the group
  labels and the row icons; the sort label's text ends where the times end.
  The name is the title (13 pt bold, primary, as in the workspaces view); the sort menu is a
  small quiet button (11 pt, secondary, a capsule filled on hover, its edge on the rows' edge); a long
  name shortens before it does.
  The group labels ("Working 1", "alpha 2") are
  section labels, as in a macOS sidebar: 10 pt semibold, secondary, with
  12 pt of room above each group. No line under the header.
- **Folding.** A click on a group label folds its rows or shows them again; a
  chevron at the label's end points right while folded; while open it shows,
  pointing down, only under the pointer, as in a macOS sidebar. A
  folded group keeps its label and count. The folds are kept per session and
  per order, across relaunches.
- **Rows.** One row per agent pane, even when several share a tab. 48 pt, two
  lines, 4 pt apart; the program tile with its badge centers on both. Line 1,
  on one centered line: the pane's name when it has one, else the agent's
  name (herdr's `display_agent`, else `agent`), then on the right the status
  capsule, "Needs you" (amber), "Working" (blue), "Done" (green) or "Idle"
  (gray), the text in the color on a 0.15 fill of it, and the age ("now", "3m", "2h", "4d"), counted from the
  time the app saw the change. Line 2: "‹workspace› · ‹tab title›" in
  secondary text (the tab bar's title, D65); only the tab title in Workspace
  order, where the group names the workspace.
- The row of the shown tab's keyboard card is lit like the selected
  workspace row.
- Idle agents show. With no agents the list is empty, with no text.
- The footer filter keeps the rows whose pane, agent, workspace or tab name
  matches.
- A click goes to that workspace, tab and pane and gives the pane the
  keyboard, which records a finish as seen.
- Rest the pointer on a row to see the [hover card](#hover-card) of its tab.

How it works: [Agents and notifications](/docs/status#agents-and-notifications).

## Open Session

![The Open Session panel](/mockups/F.jpg)

The one place to create or open a session, as a page of this window (D68).
It replaces the old session picker. The footer's Open Session button, the
workspace menu's and the machine menu's "Open Session…" and File ▸ Open Session… (⌥⌘T) open it.
- A glass panel like the command palette, 420 pt wide, near the top of the
  window, with no title and no buttons: Enter acts, Esc or a click outside
  closes it. One panel shows at a time: opening it closes the command palette
  or the workspace menu, and opening one of those closes it.
- A text field, "Name a new session, or find one", empty and with the
  keyboard at first.
- The list, filtered by the field. It shows at once the sessions the page
  last read (as it connected, or as the panel last opened), then reads them
  again; a change updates its rows in place. Groups with the headers "New", "Running", "Stopped" and "Open
  in this window":
  - **New:** "Create session “‹typed name›”" when the text is a valid herdr
    session name that no session has. With an empty field: "Create session
    “‹name›”" with a suggested two-word name.
  - **Running** sessions that are not open in this window, then **Stopped**
    sessions.
  - Last, the sessions already open in this window.
  - The rows carry no hint text: the group headers say what a pick does. A
    small symbol leads each row: a plus to create, a stack for a running or
    stopped session, a checkmark for an open one.
- The arrows or the pointer move the highlight, in the same frame and with no
  fade, as in a menu (a row scrolled under a still pointer does not take it).
  Enter or a click acts on a row.
  - A new name, a running session and a stopped session take one path. The
    app starts the server if it is not running (a launchd job on This Mac,
    D47); a server the app started gets its first workspace in `$HOME`. Then
    the session's page opens last in the window's pages and shows, and its
    store connects.
  - An open session: its page shows.
- **Stop and Delete.** The highlighted row of a running session (not open in
  this window) has a Stop button at its right end: the server stops, and every
  program in it ends; its workspaces and tabs stay for its next start. The
  highlighted row of a stopped session has Delete: its workspaces, tabs and
  panes go for good. Both ask first ("Stop the session “‹name›”?", "Delete the
  session “‹name›”?"), as a close does (D41). The list is read again after
  each, and the light stays on the same session. Both buttons are red.
- **Detach.** The highlighted row of a session open in this window has a
  plain Detach button, as File ▸ Detach Session: its page leaves this window
  and the session keeps running, listed again under Running, and the light
  goes to the list's first row. Not on the window's last page.
- While a server starts, stops or is deleted, its row shows a spinner. A
  failure shows its text in the panel, with Retry, and the panel stays open.

How it works: [Checks on connect](/docs/machines#checks-on-connect).

## Hover card

A peek at what runs in a tab (D63). Its live tab preview (phase 25) went in
phase 27: the [overview](#overview) shows live tabs instead.
- **When.** The pointer rests 0.25 s on a title-bar capsule or an Agents
  row. The card stays while the pointer moves into it (0.15 s
  grace). It goes when the pointer leaves, on a click elsewhere, on a scroll,
  and with Esc. One card at a time, and none during a drag.
- **Where.** Centered under a capsule, 6 pt below the title row, or 6 pt right
  of the sidebar edge for an Agents row. It stays inside the window.
- **Look.** A glass panel (floating glass, see
  [Theme](/docs/ui/theme-and-accessibility)), radius 12, 280 pt wide. It fades and grows
  in from 0.97 over 0.13 s.
- **Content**, top to bottom:
  - The tab title (folder part dimmed) and the tab's status capsule, if any.
  - One row per pane, at most 6 and then "+N more": the program glyph, the
    program or agent name, the folder in secondary text, and the status
    capsule or the working dots on the right.
  - For a pane that needs you: the last 3 non-empty lines of its screen, in
    secondary monospaced text. The app reads them with `pane.read` when the
    card opens, one call per such pane, and shows nothing if the read fails.
- A click on a pane row selects the workspace and tab and gives that pane the
  keyboard. A click on the title selects the tab.
- VoiceOver: the card is a panel in the window (the Agents button's hover
  panel) with the rows as buttons. A tab's action
  "Show Panes" opens it.

## Strip

- One page per tab, full width, paged. Each workspace of each session has its
  own strip, so a switch never starts from another workspace's scroll.
- Inside a page, pane cards follow herdr's split tree, with an 8 pt gap
  between them. The gap is the divider: drag it to resize (a grip shows on
  hover and while dragged), double-click it to reset it to 0.5, and ⌥⌘=
  balances the tab. A split made in the app gives the panes in its row equal
  shares.
- Layout changes animate over 0.13 s: a new card slides in from its side, a
  closed one fades away, a zoom grows the card to the page and back. A
  divider drag follows the pointer.

How it works: [Layout and sizing](/docs/layout).

## Pane card

- **Card.** Radius 10. Its terminal fades in over 0.12 s once herdr's frames
  stop for 0.1 s, or 0.4 s after the first frame (at once with Reduce Motion).
  At each new grid it keeps its old picture until herdr's frames settle, then
  shows the new one at once ([States](/docs/ui/states)).
- **Header.** 36 pt tall. 11 pt in from the leading edge: the program glyph
  (16 pt, secondary), 3 pt before herdr's pane label if set, else the
  program's name and the folder in secondary text, for example "vim ~/code" or
  "zsh ~" ([Program icons](/docs/ui/program-icons)). 8 pt in from the trailing
  edge, four 22 × 22 pt buttons, 2 pt apart: Split Right, Split Down, Zoom and
  Close, with 11 pt regular glyphs, dimmer than the title row's buttons (white
  or black 0.33), as in Rex. Zoom is disabled when the tab has one pane.
- **Terminal.** 10 pt in from the card's sides and 8 pt above its bottom; its
  text starts 12 pt in, as in Rex.
- On macOS the buttons show on the keyboard card and on a hovered card. On iOS
  they always show.
- Agent and terminal cards also have a chat|term view switch, plugin panes a
  plugin|term switch. Plugin and web cards also have **Refresh**, which loads
  the card again from the machine
  ([When a card reads its state](/docs/plugins/state#when-a-card-reads-its-state)).
- **Context menu** on the header, and on the terminal, where it starts with
  Copy, Paste and Select All. As in herdr, a right click in the terminal opens
  the menu even when the program reads the mouse. ⌥-right click sends the
  click, without the ⌥, to a program that reads the mouse, and does nothing
  in one that does not (herdr's `right_click_passthrough_modifier = "alt"`).
  herdr's per-pane setting that gives a pane's right clicks to its program is
  not in its API, so the app does not follow it:
  - Split Right (⌘D), Split Down (⇧⌘D), Split Left, Split Up, Zoom Pane or
    Restore Pane (⇧⌘↩).
  - Move Pane to Tab ▸ (New Tab and New Workspace, a separator, then every
    tab of the session but the pane's own, grouped by workspace: each
    workspace's name as a section header, in the sidebar's order), Rename
    Pane…, Reset Pane Name.
  - Close Pane (⌘W).
- The same items are in View ▸ Pane in the menu bar, for the keyboard card
  (the zoomed card of the selected tab, when there is one). Close Pane stays
  in the File menu.
- After a move, the window selects the tab the pane went to, and the pane
  keeps the keyboard.
- **Rename Pane** puts a text field in the header. Enter saves the label; an
  empty name clears it; Esc cancels. Then the keyboard goes back to the card.
  **Reset Pane Name** (enabled once the pane has a name, also in the palette)
  clears herdr's label, so the header shows the program again.
- Drag the header to move the pane ([Drag and drop](/docs/ui/drag-and-drop)).
- Close asks first unless the pane runs only its shell.
- ⌘-click on a link in a terminal opens it in the default browser, `http` and
  `https` only.

## Find bar

⌘F (Edit ▸ Find…) opens the find bar on the keyboard card; ⌘F again focuses
its field.
- A glass capsule 320 pt wide and 32 pt tall at the card's top right, 8 pt in
  from its edge and 8 pt under the header: the field ("Find"), the match count
  ("3 of 12", in a fixed slot so the bar never changes width), ↑ (Find
  Previous), ↓ (Find Next) and × (22 pt buttons with 11 pt regular glyphs, as
  the card header's). One bar per window page, on the card it
  opened on.
- A new query selects the last match, nearest the bottom. ⌘G or Enter goes to
  the next match down, ⇧Enter or ↑ to the previous one up, round the ends. Esc
  or × closes the bar and gives the keyboard back to the card. As in Rex, Find
  Previous has no shortcut: ⇧⌘G is Go to Directory.
- The text comes from herdr, read when the bar opens and again at the next
  step after Return was pressed in the pane, and the search is case blind.
  Each match scrolls herdr's viewport to it, with the match line centered.
  Closing the bar scrolls back to the bottom. herdr's viewport is shared, so a
  herdr TUI on the same pane scrolls too.
- The matches on the screen are highlighted: the selected one in the accent at
  0.45, the others at 0.2, placed from herdr's visible text after each scroll
  and again 0.3 s after the pane's frames stop (at most 1 s of waiting).
- The bar closes, and herdr scrolls back to the bottom, when its card leaves
  view (another tab, workspace or page, or another card zoomed) and when its
  page or window closes. A failed scroll shows a [notice](#notice).

How it works: [Scrolling, queries and links](/docs/talking-to-herdr#scrolling-queries-and-links).

## Zoom

- The zoom button, a double-click on the header, or ⇧⌘↩ zooms a card. It
  fills its tab's page in the strip, as if it were the only pane. Only the
  zoomed card resizes; the others stay, hidden, at their size.
- A zoomed card shows only two buttons: Restore (the accent at 0.6 on an
  accent circle at 0.07, as in Rex; no saturated blue) and Close.
- A split from the zoomed card restores the layout first, so the new pane
  shows. Moving the keyboard to a hidden card restores it too.
- Restore or ⇧⌘↩ restores the layout. Esc is not used, because the program in
  the pane needs it.

## Overview

Every tab of the session at a glance, live (D70): for watching many agents at
once.
- **Open and close.** The title-row button (`square.grid.2x2`, between the
  Agents button and ⌘), View ▸ Show Overview, the palette, and ⌃⌘O toggle it;
  Esc and the title row's × leave it. Each window has its own; it does not come
  back after a relaunch.
- **What it hides.** The sidebar, the tab bar and every title-row button: the
  row keeps only the traffic lights and, at its end, one × (Close Overview,
  ⌃⌘O) that leaves the overview. ⌘K and ⌘. still work. The overview covers
  the window below the title row and fades in over 0.18 s as it opens (ease
  out; at once under Reduce Motion).
- **Canvas.** One page per session of the window, side by side: a sideways
  swipe (or a wheel with Shift) moves to the next or previous session, as on
  the sidebar, and the page it lands on becomes the window's page in view.
  Inside a page, scrolled vertically: the session's title as the sidebar's
  page header has it (13 pt semibold; This Mac's name for `default`), then
  the session's workspaces in the sidebar's order, 32 pt apart: each
  workspace's name (13 pt semibold, secondary), then its tabs as tiles in a
  grid, 2 to 4 a row (as many 340 pt tiles as fit), 16 pt apart. Wide
  margins all round, as in the user's reference: 8 % of the window's width
  left and right (at least 48 pt), 40 pt above and below, so the grid sits
  centered.
- **Tile.** One card per tab (the card's fill, rim and edge), as in the
  user's reference: at its top a 36 pt title row like a card header (the
  tab's icon stack, its title with the folder dimmed, and its status
  capsule), and under it, 8 pt in, a miniature of the page: the tab's cards in
  herdr's layout, at the page's real proportions (the strip's page as it
  shows when the overview closes), each card its fill and edge with its
  terminal drawn live inside, at the place and size it has in the card (no
  header content: the tile's title row names the tab). A zoomed tab shows its
  zoomed card. A floated pane's card shows the float icon. The selected tab
  of each workspace has the keyboard card's look. On hover the title row
  shows × at its end (Close Tab, as the tab bar's ×: it asks only when a
  program runs).
- **Click.** A click on a tile selects its workspace and tab and leaves the
  overview: the tile's miniature grows to the strip's page over 0.18 s
  (ease out), its terminals scaling up live, then the strip shows. Esc, the title
  row's × and ⌃⌘O leave the same way, from the selected tab's tile (at once
  when that tile is scrolled away). Under Reduce Motion it leaves at once. ⌘.
  (Show Agents in the menu or palette) leaves it first and opens the Agents
  view after the zoom; a
  notification or Dock click leaves it at once and shows its pane. Other keys
  and the palette act as usual and the overview stays: ⌘T adds a tile, a tab
  key moves the selected tile.
- **Keyboard.** While the overview is open no terminal has the keyboard (a
  terminal view in a miniature refuses it); Esc leaves, unless a panel (the
  palette, Keyboard Shortcuts) or a text field is open. Closing it gives the keyboard back to the
  tab's card.
- VoiceOver: each tile is a button named by its tab's title, with the
  workspace as its group.

### How the miniatures draw

- They are the terminals themselves: each tile hosts the pane's own
  libghostty view (the one its card shows) inside an AppKit view whose bounds
  are the card's terminal size and whose frame is the tile's. AppKit draws
  the view scaled (a layer transform), so libghostty keeps its size, grid and
  pixels, and herdr's PTY keeps the card's size, never the tile's (a terminal
  that streams for the first time opens at its card's size, as a visit
  would). A window resize refits them 150 ms after it stops, as the cards do. No second surface, stream or copy;
  while the overview shows, the strip does not, so a terminal view is still in
  one place (D35). The strip's cards take their views back when it closes.
- While the overview is open, every card of every session in it streams and
  draws, also the tiles scrolled out of view and the other sessions' pages:
  nothing in it is lazy, so each terminal view is in the window and has its
  surface, and a tile scrolled or swiped into view shows its live screen at
  once, with no fade (phase 28). On a remote machine every card's stream goes
  through the relay's one SSH session ([SSH sessions](/docs/machines#ssh-sessions)).
  Those are not visits: when the overview closes, a terminal shown only by it
  goes back to where it was (its surface and stream let go) and the recently
  shown set is unchanged (D46).
- Cost: the user accepts the memory while it is open. Every card of the
  window's sessions keeps a surface at its full card size (about 52 MB for a
  full-window card on a Retina screen), so the cost follows the sessions.
  Phase 27, lane O's scenario (17 cards, 8 printing; debug build, this Mac,
  Retina): 166 MB and 1.4 % CPU with the strip; 902 MB and 16.7 % CPU with
  all 17 laid out; 224 MB, 1.7 % and the strip's 4 herdr runs after it
  closed. libghostty-spm takes its content scale only from the window, so
  smaller surfaces for the miniatures would need a change there.

Options weighed: a second, small, observe-only surface per pane at a small
font (a herdr run, a renderer and a font atlas per pane, and observe cannot
resize, so the grid would not fit the tile); pictures read from the live
surfaces on a timer (only the shown tab's draw; each other card would need a
surface anyway); screen text (`pane.read`, no colors: phase 25's hover card
preview, removed with it); SwiftUI's `scaleEffect` on the strip's page
(SwiftUI does not scale an AppKit view: the terminal stays at full size).

## Floating pane

A pane can float in a small window of its own, above the main window or, kept
on top, above other apps (D50). herdr has no floating pane, so this is
Oriel's own: the pane stays in its herdr tab, and other devices and herdr
clients see it there.
- **Float Pane** (the `pip.enter` button in the card header, the pane's menus,
  View ▸ Pane and the palette) opens the window. Several can be open. On a
  floated pane's card the button is lit, and it brings the window to the
  front.
- **The window** has no tab bar and no sidebar. Its title row is the main
  window's: 46 pt, with the traffic lights where the main window has them.
  It holds the traffic lights, then the pane's quick info (its icon, its
  program and folder, or its label, and its agent's state capsule), a thin
  vertical line, then "session › workspace › tab" in 11 pt tertiary text,
  quieter than the pane's folder, on one line (the
  session as the sidebar names it, so `default` shows the machine's name; a
  long one gives way first, in its middle), then on the right the title
  row's 28 pt buttons: **Stay on Top** (a pin), **Close** (closes
  the pane, and asks first as any close does, in the floating window, also
  for a Close from the card in the tab) and, rightmost, **Detach**
  (`pip.exit`: the window closes and the card shows its terminal in its tab
  again; nothing stops). The red traffic light detaches too. Below the title
  row, the glass card holds only the terminal, with no header, 8 pt in from
  the window's edges, its text 10 pt in from the card's sides, as in a pane
  card. A pane's first float opens it at 60 % of the main window's width and
  75 % of its height (at least 720 × 460 pt), centered over the main window; it
  moves and resizes like any window, and keeps its frame for the next time
  that pane floats.
- **Stay on Top** keeps the window above every app's windows and on every
  Space, like picture in picture. It stays on until turned off.
- **In the tab** the card keeps its place in the splits and its header. In
  place of the terminal, in the middle of the card: "This pane is open in a
  floating window." in secondary text, and a **Show Pane** button that brings
  the window to the front. The placeholder is never the keyboard card: ⌘[ ⌘]
  and Focus Follows Mouse skip it.
- **Keys and ⌘K.** In the floating window the menu bar and the palette offer
  only what applies to it: Detach Pane (⇧⌘W), Close Pane (⌘W), Stay on Top,
  Find, Find Next and Find Previous, the font size items, Copy and Paste. The
  palette lists no tabs, workspaces or sessions.
- **Saved.** The floating panes and their Stay on Top are kept with the main
  window that floated them, and open again when it restores. A pane that
  herdr closed closes its window; one that moved to another tab or workspace
  stays floating (its terminal is the same), and the main window stays where
  it is. Closing the main window closes
  its floating windows.
- The terminal streams the whole time it floats, whichever tab or session the
  main window shows. Another window on the same session shows the pane as a
  normal card.
- **From other tools:** `oriel://float?session=‹herdr session›&pane=‹pane id›`
  (and `&machine=‹machine id›` for a remote machine; This Mac otherwise)
  floats that pane over the machine's front main window, also when its
  session is not open there: then the session gets no page, no sidebar row
  and no strip page, and it disconnects when its last float goes (such a
  float does not come back after a relaunch). Open again for the same pane,
  it brings the window forward. A session or pane that is not there shows a
  notice and no window. pi-herd opens its agents this way when Oriel is the
  frontmost app, as herdr's own popups do not show in Oriel.

## Notice

A short message after a failed action or a refused move.
- A capsule at the bottom center of the strip, 30 pt above its bottom, 36 pt
  tall: glass, a leading symbol in a tone color (red `xmark.octagon.fill` for
  an error, amber `exclamationmark.triangle.fill` for a warning, blue for
  information), the text (two lines at most), an optional action button and ×.
- A failed write's notice has no action: after a timeout the write may have
  happened, so a retry is not safe. The Open Session panel's "Could not
  start" notice has **Retry**.
- It goes after 4 s, or at ×. A newer notice replaces it.

## Control capsule

A window that watches a session another window controls (D66).
- Its cards of that session draw their content at 0.85 of its opacity, and a
  capsule at the bottom center of the strip, 30 pt above its bottom, says
  "Controlled in another window", with **Take Back**. It is a
  [notice](#notice) in the information tone with `macwindow.on.rectangle` and
  no ×, sits under a notice when both show, and shows only while the page in
  view is watched. VoiceOver reads its text when it appears.
- Take Back, or a key press, paste or click in one of its terminal cards,
  moves control of the session to this window. The other window then watches
  and shows the capsule.
- A pane that another device holds shows "In use elsewhere · Take Back" in its
  card instead
  ([One controller per pane](/docs/talking-to-herdr#one-controller-per-pane)).

## Command palette

⌘K or the title-bar ⌘ button opens it (D48). ⇧⌘P also opens it (Rex's key).
- 480 pt wide. The search field says "Search".
- **Rows.** 28 pt: a symbol, the title, and on the right the shortcut in
  secondary glyphs, or › for a row that opens a sub-page. The selected row is
  an accent pill, radius 8; the arrows or the pointer move it.
- **Sections.** On the first page with an empty field: Tabs (of the selected
  workspace), Workspaces (of every page in the window, with the session's
  name), Sessions, then Commands, each under a header. A typed filter gives one
  list, best match first. A sub-page shows only its own rows, under its title.
  Sessions lists the pages open in this window; Open Session… opens the
  [Open Session](#open-session) panel.
- **Matching.** Fuzzy, in the order of the typed letters, over titles and
  keywords: "split" finds Split Right, "dark" finds Appearance ▸ Dark. On a
  tie, a title that starts with the filter comes first ("font size" gives
  Font Size › before Increase Font Size), then commands before places, then
  the menu's and the sidebar's order.
- **Sub-pages.** ⌫ on an empty field or Esc goes back one page; Esc on the
  first page closes the palette.
  - Rename Tab ›, Rename Workspace ›, Rename Pane ›: the field holds the
    current name; Enter saves.
  - Move Pane to Tab ›: New Tab, New Workspace, then the session's other tabs
    under their workspaces' names. A move into a tab lands right of its last
    card.
  - Appearance › and Interface Style ›: a row highlighted for 0.75 s previews
    on the window. Enter keeps it; Esc restores the old one.
  - Font Size ›: 8 to 32 pt.
- **Go to Directory** (⇧⌘G) opens the system folder panel at the keyboard
  card's folder. Choosing a folder types `cd -- '‹path›'` and Return into the
  card. Enabled only when the card runs only its shell.
- **Insert Path** (⇧⌘I) opens the same panel with files too. Choosing types
  the shell-quoted path at the cursor, without Return.
- **Settings as commands.** Each on/off setting in the menu bar is one command
  whose title says what it does now: "Turn On Focus Follows Mouse" or "Turn
  Off Focus Follows Mouse".

The palette and the menu bar come from one command list, so each title and
shortcut is written once
([Keyboard shortcuts](/docs/ui/theme-and-accessibility#keyboard-shortcuts)).
