Grouped in the order of the sidebar. Each row is a rule that holds now, with a
link to the page that has the mechanism. Earlier choices are in "Rejected".
Numbers are stable: a new decision gets a new number, and the number of a
decision that no longer holds is not used again.

## Source of truth and protocol

| # | Decision | Why | Rejected |
|---|---|---|---|
| D1 | herdr is the source of truth for workspaces, tabs, panes, layout, web addresses and plugin panes. ([Data](/docs/data)) | Clients with their own copy drifted. A fresh device rebuilds from herdr. | App-owned tabs or layout. |
| D2 | Every pane kind reaches its machine through two calls: `run(argv)` and `dial(host, port)`. Closing a run's stdin ends it. ([Run and dial](/docs/talking-to-herdr#run-and-dial)) | One path for local, remote macOS and iOS; herdr's own remote method. A closed stdin ends a child even after an app crash, remote ones too. | A daemon, relay or bridge of our own on the machine; a release message, a global pid list and a kill at exit. |
| D3 | Every remote command goes through a base64 envelope run by `sh`. ([Run and dial](/docs/talking-to-herdr#run-and-dial)) | The login shell may be fish, where POSIX quoting is not safe. | Quoting argv into the login shell. |
| D4 | Control plane = `herdr --session S remote-api-bridge` on every machine, one call per request. ([Requests](/docs/talking-to-herdr#requests)) | One path; no socket lookup; the cost hides behind the snapshot pacing. | A direct local socket; socket forwarding. |
| D5 | Events only mean "read the snapshot again"; no payload is decoded. Status events only for agent panes; no focus or `pane.updated` events. Reads are paced per machine: one in flight, plus a read-again flag. ([Events](/docs/talking-to-herdr#events)) | One code path; each status entry costs herdr a poll; a read batches the events that arrive during it. | Applying deltas; subscribing to every pane; polling `session.snapshot` every second; a debounce with a maximum wait. |
| D6 | Snapshots are applied to stable observable objects with hand-written lenient models. Every card is keyed by `(machine, terminal_id)`. ([Reconcile](/docs/talking-to-herdr#reconcile)) | One status change redraws one row. `terminal_id` survives every move; after a cold restart cards are built again from the machine. | One big state value; code generation; plugin cards keyed by instance id. |
| D7 | Terminal plane = `herdr terminal session control/observe` by `terminal_id`, for the selected tab of the selected machine (Mac: plus D46). Text goes on the stream; special keys and Ctrl chords go as `pane.send_keys`. ([Terminal plane](/docs/talking-to-herdr#terminal-plane)) | Public, per pane, works over SSH, survives moves. herdr encodes special keys for the program's input modes. | herdr's private client socket; `terminal attach` in a PTY; polling `pane.read`; encoding special keys in the app. |
| D8 | One control rule: the Mac opens `control` without takeover and watches if refused; iPhone and iPad open `observe`. Any device takes control (`--takeover`) on the first key press, paste, click or tap in the card, or Take back. ([One controller per pane](/docs/talking-to-herdr#one-controller-per-pane)) | One controller and one PTY size per pane. Looking on a phone never resizes the PTY. Looking on a Mac pins it to the card size, which is accepted. | Taking over on open; automatic takeover; `control` on every device. |
| D38 | Refuse herdr older than 0.9.3. The version comes from the snapshot. herdr's install folders are on `PATH`, and every herdr argv carries `--session`. ([herdr on each machine](/docs/talking-to-herdr#herdr-on-each-machine)) | Old herdr lacks what we use; lenient decoding needs nothing for newer protocols; no inherited variable can redirect a command. | A read-only mode; a banner for newer protocols; a herdr lookup step and `--check`. |
| D40 | Every `call()` times out after 10 s. One health loop per machine reads the snapshot every 30 s, every 2 s while it fails; automatic retries never prompt. ([Health check](/docs/machines#health-check)) | A dead link must not hang writes. The snapshot carries the version and catches missed events. A retry that prompts would show a dialog every few seconds. | No timeout; a timeout on streams; a separate `ping`, wake check and back-off. |
| D46 | The Mac keeps the `control` streams of recently shown tabs, about 24 terminals, least recently shown first out; hidden ones stop drawing but keep reading. ([What streams](/docs/talking-to-herdr#what-streams)) | Coming back to a tab resizes nothing: no second redraw of a full-screen app while a herdr TUI is also attached. | Releasing on leaving a tab (each return resized the PTY twice); streaming every pane. |
| D49 | A `Multiplexer` Swift protocol, with herdr as its first and only implementation: a deliberate exception to "no abstraction with one implementation". ([The Multiplexer interface](/docs/architecture#the-multiplexer-interface)) | Oriel is a client for terminal multiplexers, herdr first. One named seam keeps herdr's JSON and argv out of the views and plugins. | herdr types used directly by the views; waiting for a second multiplexer before naming the seam. |
| D52 | Web cards reach a remote `localhost` through `dial`, on the same local port when it is free. The Open :port chip comes from the terminal text the app already streams; the ports list runs on demand. Tailscale and LAN addresses load directly. ([Remote localhost](/docs/plugins/web-page#remote-localhost), [Finding ports](/docs/plugins/web-page#finding-ports)) | SSH already does it; nothing to install on the machine; forwards use no SSH session; the same port keeps the page's origin (OAuth callbacks, CORS lists); the chip needs no extra stream. | A server helper of our own now ([Future work](/docs/future-work)); SOCKS (WebKit never proxies loopback); a different local port every time; `pane.output_matched` on a second event stream. |
| D57 | Where things live: anything that takes space in the layout is a multiplexer pane with a label; transient UI is app memory only; per-device settings are app storage. ([Data](/docs/data#where-things-live)) | One rule for every new feature; keeps D1 true; a fresh device rebuilds every layout from the multiplexer. | App-only surfaces in the layout (a second layout system); syncing UI state between devices. |

## Machines

| # | Decision | Why | Rejected |
|---|---|---|---|
| D15 | macOS SSH = system `ssh`, one ControlMaster per host started on purpose, forwarding off, a bundled askpass script. ([macOS](/docs/machines#macos)) | The user's setup works; one prompt per host; no path back to the Mac. | `ControlMaster=auto`; a Swift SSH library on macOS. |
| D17 | iOS uses Citadel with a Secure Enclave key; machines in `UserDefaults`; the Mac via Remote Login. ([iOS](/docs/machines#ios)) | Pure Swift; the key cannot leave the device; no new mechanism. Spike S7 tests the exec channels first. | libssh2 + OpenSSL; a relay. |
| D43 | A machine is one herdr session: one entry in the machine list and one sidebar page. Sessions on one host share one SSH connection. The app counts no channels: when the server refuses one, it closes the least recently shown kept stream and tries once more. ([What a machine is](/docs/machines#what-a-machine-is), [SSH sessions](/docs/machines#ssh-sessions)) | herdr's own unit is the session; one connection per host keeps one prompt. The server's refusal is the only true count. | One connection per session; one machine per host; a channel budget with reservations, priorities and a learned limit. |
| D47 | On This Mac the app starts a session's server as a one-shot launchd job in the user's GUI domain, with the environment the CLI sees. A remote server starts with `nohup` over SSH. ([Checks on connect](/docs/machines#checks-on-connect)) | launchd is the server's parent and responsible process, so macOS privacy prompts never name Oriel; the server has its own process group and outlives the app; server and CLI agree on paths. | Never starting the local server; `launchctl submit` (launchd restarted the server after `herdr session stop`); `nohup` or a double fork from the app (the app stays the responsible process); a Terminal window running herdr. |
| D54 | The app keeps its own machine list on macOS and iOS. On macOS the Add Machine sheet offers herdr's machines, checked while the list is empty. herdr on the Mac is needed only for This Mac's sessions. ([The machine list](/docs/machines#the-machine-list), [Add a machine](/docs/ui/add-a-machine)) | One code path on both platforms; remote machines work on a Mac without herdr; the askpass dialog answers ssh's questions. | herdr's machine list as the only list on macOS, with `herdr machine add` in a terminal card; an import at first launch; a second list kept in sync both ways. |

## Layout and terminals

| # | Decision | Why | Rejected |
|---|---|---|---|
| D9 | libghostty-spm draws terminals, as a pinned build with uHerdr's response-suppression patch. ([Dependencies](/docs/platform#dependencies)) | Best quality on both platforms. The patch stops a second answer to terminal queries that herdr already answered. | SwiftTerm as the main renderer (kept as a fallback); xterm.js in a web view. |
| D10 | Layout = herdr's split tree rebuilt from the flat snapshot; resize = `layout.set_split_ratio`. ([Layout and sizing](/docs/layout)) | Ratios live in herdr; no extra calls. | App-owned sizes; `layout.export` per tab. |
| D11 | Zoom is the app's own: the zoomed card fills its tab's page, drawn by the split tree (each split above it stacks its sides; the others stay hidden at their size). ([Zoom](/docs/ui/window#zoom), [Zoom is the app's own](/docs/layout#zoom-is-the-apps-own)) | `pane.zoom` moves herdr's focus, marks the tab seen and blocks moves. In the split tree, no terminal view changes host and no other PTY resizes. | `pane.zoom`; a separate layer (its terminal view did not come back on restore). |
| D12 | One tab = one page in the strip. ([Swiping](/docs/ui/swiping)) | Matches herdr and Cube. | Panes wider than the window in one long scroller. |
| D13 | The app never calls herdr's focus methods; selection and "seen" are the app's own, per device. ([Selection and "seen"](/docs/layout#selection-and-seen-are-the-apps-own)) | Each focus call moves every attached herdr TUI. | Focusing on click or swipe. |
| D14 | "Finished, not seen" = `completion_seq` not null and different from the seen value; the first sighting counts as seen. herdr sets `completion_seq` on a finish and clears it at the next status change. ([Status area](/docs/status#status-area-and-notifications)) | herdr skips `done` when a TUI watches the tab; the counter restarts with herdr. | Waiting for `done`; a "greater than" test. |
| D41 | **Changed by D51.** Closing a pane asks first unless the pane runs only its shell. Closing a tab or workspace always asks. ([Writes](/docs/talking-to-herdr#writes-are-herdr-calls)) | A close kills processes on every device and cannot be undone. | Asking only when an agent works; never asking. |
| D42 | Rex-like behavior follows gorex: one tab status slot (× on hover > ▲ > ✓ > ◔), a static ◔, double-click a divider to reset it to 0.5, ⌃⌘= to make splits equal, the window title from the selected tab. ([Main window](/docs/ui/window)) | gorex is a readable Rex copy; a static glyph avoids constant redraws. gorex is not a glass reference. | An animated working glyph; several glyphs per tab. |
| D56 | Image paste into a terminal, agent or chat reply box: write the image as PNG (at most 10 MB) to a new temporary folder on the pane's machine with `run` and stdin, then paste its path like text. ([Image paste](/docs/plugins/terminal-and-agent#image-paste)) | Works the same on This Mac and over SSH with what exists; agents already accept a pasted image path; what uHerdr, collie, termote and roamgate do. | Sending image bytes through the terminal (herdr's stream and agents do not take them); a server helper; a folder of our own with its own cleanup. |

## Chat and status

| # | Decision | Why | Rejected |
|---|---|---|---|
| D28 | **Changed by D50.** Floating panes = panes in a tab labeled `oriel:float`; float and dock are `pane.move`; cards inside the main window; frames in memory. ([Future work](/docs/future-work)) | herdr keeps which panes float; any pane kind can float; nothing stored. | herdr popups; label markers; a window per floating pane. |
| D29 | Chat = the agent's transcript tailed on the machine + `agent.prompt`; parsers for pi, Claude Code and Codex; a screen-text chat for every other agent or terminal pane. Web and plugin panes have no chat view. ([Chat view](/docs/chat-view)) | What every working chat view does; any agent or terminal pane can switch. | Per-agent prompt parsers; parsing the screen into fake messages. |
| D30 | The blocked panel sends a key only if the agent is still blocked and the prompt text is unchanged. ([Sending and answering](/docs/chat-view#sending-and-answering)) | The prompt may have changed on another device. | Sending without a check. |
| D31 | Notifications are made by the app from snapshot changes; `.passive` while the pill shows (except with VoiceOver or Switch Control); no iOS push in v1; a push relay is [Future work](/docs/future-work). ([Notifications](/docs/status#notifications)) | herdr sends its own only to TUI clients; no double alerts; push needs a relay. | herdr's private notifications; dropping banners. |
| D32 | Floating pills: one non-activating `NSPanel`, one pill with a glyph per agent, a pill card that is the compact chat view, peeks that never take the keyboard, opaque. ([Floating pills](/docs/ui/pills), [how they work](/docs/status#floating-pills-how-they-work-macos)) | One proved the shape; never steal a keystroke; glass renders flat in an inactive app. | A pill per agent; a SwiftUI window; glass pills. |
| D50 | Floating panes move to [Future work](/docs/future-work). | v1 needs the strip, splits and chat first; nothing in herdr or the app depends on floating panes. | Building them in v1. |
| D55 | Agent status comes only from the multiplexer's API. Under herdr the app never parses OSC 7501 (herdr does not support it yet, draft PR #5172; once it does, it folds it into `agent_status` and `completion_seq`). Another multiplexer's implementation may parse it where the app owns the terminal bytes. No new UI. ([Status](/docs/status#status-area-and-notifications)) | herdr's terminal stream is a redrawn screen, so the sequence never reaches the app; one source keeps every device in agreement. | Parsing OSC 7501 in the app's libghostty surfaces under herdr. |

## Look and platform

| # | Decision | Why | Rejected |
|---|---|---|---|
| D33 | **Changed by D44.** Dark theme only: opaque near-black window, opaque cards, dark-tinted glass on chrome. ([Theme and accessibility](/docs/ui/theme-and-accessibility)) | An all-dark look with no colored windows. | A translucent window; a light theme in v1. |
| D44 | Dark theme only, frosted: a dark-tinted behind-window blur for the window, translucent dark pane cards with a hairline border on it. The sidebar sits flat on that background (no panel); Liquid Glass only on the tab marker, popovers and the palette. Replaces D33's opaque window and cards. ([Theme and accessibility](/docs/ui/theme-and-accessibility)) | The user's reference look (Rex): the desktop shows through softly, cards float; only the cards stand out from it. | Opaque window and cards; glass on the cards; a glass sidebar panel; a light theme in v1. |
| D45 | One title-bar row: sidebar toggle, session picker (the session name; its machine is in the list it opens), then the tab capsules while the sidebar is hidden, ⌘ and + on the right. It starts after the traffic lights, at the window edge in full screen. While the sidebar is shown, tabs are its rows under workspace section headers. ([Main window](/docs/ui/window)) | The reference look; tabs show once, where there is room. | A tab bar and a sidebar at the same time; agent rows in the v0 sidebar. |
| D48 | ⌘K (and the title-bar ⌘ button) opens the command palette: a centered glass panel that lists tabs, workspaces and running sessions, filtered as you type, arrows to move, Enter to jump, Esc to close. Card actions join it later. ⇧⌘N makes a new session, ⌘T a new tab, ⌘W closes the keyboard card. ([Keyboard](/docs/ui/theme-and-accessibility)) | ⌘K is the palette key in Rex, Slack, Linear and VS Code's quick open; herdr owns the screen, so Terminal's ⌘K (clear) has nothing to clear. | ⇧⌘P (VS Code's command palette, less known outside editors); ⌘P. |
| D34 | One multiplatform target, macOS 26 and iOS 26, one main window. ([One codebase](/docs/platform#one-codebase)) | Liquid Glass and `WebView`; no fallbacks; no control fights. | Separate apps; back-deploying; several main windows in v1. |
| D35 | Horizontal gestures belong to the strip; the PaneViewRegistry owns every view. ([Making the strip work](/docs/platform#making-the-strip-work)) | Terminals and web views would eat the swipe; SwiftUI would destroy views. | Each view handling its own scroll. |
| D36 | iPhone shows one pane per page and opens agents in chat. ([iPhone and iPad](/docs/ui/iphone-and-ipad)) | Splits do not fit; chat needs no PTY. | Shrinking splits onto a phone. |

## Pane kinds and plugins

| # | Decision | Why | Rejected |
|---|---|---|---|
| D18 | Everything is a plugin: one registry, manifest shape and picker; terminal, agent and web are native core plugins. ([Everything is a plugin](/docs/plugins)) | One model for every pane kind without JavaScript cost for core panes. | Special-casing core kinds; herdr TUI plugins in the picker. |
| D19 | **Changed by D53.** Plugin UI = TypeScript + React in one JSContext per card, rendered as native SwiftUI through a component kit. ([Plugin UI](/docs/plugins/plugin-ui)) | Native look and behavior; ~3 MB per card; the JS reaches only the injected API; works on iOS. | React in a web view; React Native; native Swift plugins; ExtensionKit. |
| D20 | **Changed by D53.** Plugins live in the app, installed from a git URL or a linked folder; the app never runs npm. ([Packages](/docs/plugins/packages)) | One install per device for every machine; no setup on any machine; a simple dev loop. | herdr plugins on each machine; an in-app store. |
| D21 | **Changed by D51.** A plugin pane is a herdr pane labeled `oriel:<plugin>[/<pane>]#<iid> <arg>`. A placeholder is typed only once the new pane's shell is in front; it is cosmetic. ([Labels and instance ids](/docs/plugins/labels)) | The label is durable and readable; the iid survives moves and restarts. | Metadata tokens; an app-side pane list. |
| D22 | Bigger plugin state lives in a JSON file on the pane's machine, keyed by iid; preferences stay per device. ([State and restore](/docs/plugins/state)) | Shared by every device, survives reinstalls, no sync service. | Labels for everything; app storage. |
| D23 | **Changed by D59.** After every rename or state write, a `oriel_rev` metadata token tells other devices to refresh. ([Web page](/docs/plugins/web-page), [State and restore](/docs/plugins/state)) | A rename sends no event; a token change does. | Polling; a terminal-title trick. |
| D24 | **Changed by D53.** Plugin API = `exec` on the card's own machine, pane context, `setArg`, instance state, the snapshot, preferences, toasts, confirmed `open`, clipboard copy, navigation. ([Plugin API](/docs/plugins/api)) | Covers diff, git history and Markdown; nothing more. | Network, storage, a herdr call API, plugins outside panes in v1. |
| D25 | **Changed by D53.** Plugin security: one VM per card bound to its machine; one permission (`exec`) described honestly; consent at install and on new permissions, keyed by id and source; a This Mac confirm; no network or HTML from the app; user-gesture rule for `open` and the clipboard; a watchdog. ([Plugin security](/docs/plugins/security)) | The user sees exactly what they grant; the app adds no reach beyond `exec` on the pane's machine. | Finer permissions that do not hold; claiming a sandbox that `exec` cannot give. |
| D26 | iOS v1 ships core plugins only. ([Plugins on iOS](/docs/plugins/ios)) | Downloaded code is an App Store review risk. | User plugins on iOS in v1. |
| D27 | **Changed by D52, D58.** Web page = core plugin with label `web:<url>`. A label set elsewhere loads only after a click, unless the user approved that origin for this machine. Per-machine data stores; remote `localhost` through forwards on other ports. ([Web page](/docs/plugins/web-page)) | Durable marker; no request leaves the device without the user; machines stay apart. | Auto-loading every label; SOCKS (WebKit never proxies loopback); same-port forwards. |
| D37 | The agent picker lists the available `integration.list` entries. ([Agent](/docs/plugins/terminal-and-agent#agent)) | One call; herdr checks the `PATH`. | Probing every agent with `command -v`. |
| D51 | Web and plugin panes stay placeholder panes, created with `layout.apply` (a new tab whose pane starts with its label and an inert placeholder command, in one call), then `pane.move` into place; the temporary tab closes itself. `layout.apply` never gets a `tab_id`. The app never types into a shell. Web and plugin panes close without asking. ([Create](/docs/plugins/labels#create)) | The only way to keep zero app state and one layout for every device and the herdr TUI. Creating with the command removes the race with shell startup, the `pane.process_info` gate, the envelope, the shell history line and the extra rename. | Typing the placeholder into a new shell; app-only plugin UI outside herdr's layout (a second layout system); a placeholder that reports itself as an agent. |
| D53 | A plugin is a small web page (HTML and JavaScript) drawn in a native web view in its card, served from the app (`oriel-plugin://<id>/`), with `window.oriel`: `run(argv)` and `dial(host, port)` on the pane's machine, plus pane context, `setArg`, instance state, the snapshot, preferences, toasts, confirmed `open` and clipboard copy. One permission (`run`), consent as before. A content rule and a Content Security Policy keep the page to its own files and scripts. No build tool. Git history, Diff and Markdown are rebuilt on it. The same plugins run on iOS; iOS v1 ships the core ones. ([Plugin UI](/docs/plugins/plugin-ui), [Plugin API](/docs/plugins/api)) | Works on macOS and iOS from day one with WebKit; any web library; little app code. | The TypeScript + React kit drawn as native SwiftUI (D19; [Future work](/docs/future-work) option (a)); React Native; native Swift plugins; ExtensionKit. |
| D58 | **Changed by D59.** Web cards save their viewing state on the pane's machine: the label `oriel:web#<iid> <url>` keeps the address the user typed; the current address and scroll position go in the instance state file `web/<iid>.json`, written debounced with `oriel_rev`, as for plugins. A card opens the saved address by itself only when the typed address may load by itself and the saved one has the same origin or an approved one; otherwise it follows the typed address's rules. ([Web page](/docs/plugins/web-page#viewing-state-on-the-machine)) | Coming back to a web card, on any device or after a restart, shows the page where the user left it; one label grammar and one state path for every plugin. | Rewriting the label on every navigation (a rename per click, visible to every TUI); app-only state per device. |
| D59 | No card follows another device live, web cards included. A card reads its state file only when it is built: a fresh app start, a new device, the card shown again after it was closed or evicted, or on iOS a card the system discarded in the background (returning from the background is not a fresh start; cards in memory keep their state). Every plugin and web card has **Refresh** in its header, which replaces the web card's Reload: it rebuilds the card, loading the page and its state from the machine. State writes stay debounced, last writer wins, and no longer change `oriel_rev`, which now follows only renames. `oriel.state` is for view state; data every device must see live belongs in files the plugin reads with `run`. ([When a card reads its state](/docs/plugins/state#when-a-card-reads-its-state)) | One rule for every card; a scroll on one device never moves the card under the user's eyes on another; one token write per rename instead of one per state write. | Following state writes live through `oriel_rev` (D23, D58); live follow for web cards only; separate Reload and Refresh buttons on web cards. |
