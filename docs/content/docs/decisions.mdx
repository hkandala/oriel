Grouped in the order of the sidebar. Each row is a rule that holds now, with a

## Source of truth and protocol

| # | Decision | Why | Rejected |
|---|---|---|---|
| D1 | herdr is the source of truth for workspaces, tabs, panes and layout. ([Data](/docs/data)) | Clients with their own copy drifted. A fresh install rebuilds from herdr. | App-owned tabs or layout. |
| D2 | The app reaches a machine through `run(argv)`. Closing a run's stdin ends it. A remote machine's runs share one SSH session through the relay, a Perl script sent with the connection and never installed ([The SSH connection](/docs/machines#the-ssh-connection)). ([Running commands](/docs/talking-to-herdr#running-commands)) | One path for local and remote machines; herdr's own remote method. A closed stdin ends a child even after an app crash, remote ones too. A server may allow only a few sessions per connection, and a second connection asks for a second passcode. | A daemon or bridge installed on the machine; one SSH session per run (servers refuse past `MaxSessions`); a release message, a global pid list and a kill at exit. |
| D3 | Every remote command goes through a base64 envelope run by `sh`. ([Running commands](/docs/talking-to-herdr#running-commands)) | The login shell may be fish, where POSIX quoting is not safe. | Quoting argv into the login shell. |
| D4 | Control plane = `herdr --session S remote-api-bridge` on every machine, one call per request. ([Requests](/docs/talking-to-herdr#requests)) | One path; no socket lookup; the cost hides behind the snapshot pacing. | A direct local socket; socket forwarding. |
| D5 | Events only mean "read the snapshot again" (no payload is decoded, except a float request, D50; status events only for agent panes; no focus events; `pane.updated` only because a terminal title change can pick a pane's program icon). Reads are paced per session: one in flight, plus a read-again flag; a read again starts 250 ms after the one before started at the earliest, unless a write of the app asked for it. ([Events](/docs/talking-to-herdr#events)) | One code path; each status entry costs herdr a poll; a read batches the events that arrive during it. | Applying deltas; subscribing to every pane; polling `session.snapshot` every second; a debounce with a maximum wait. |
| D6 | Snapshots are applied to stable observable objects with hand-written lenient models. Every card is keyed by `(machine, session, terminal_id)`. ([Reconcile](/docs/talking-to-herdr#reconcile)) | One status change redraws one row. `terminal_id` survives every move; after a cold restart cards are built again from the machine. | One big state value; code generation. |
| D7 | Terminal plane = `herdr terminal session control/observe` by `terminal_id`, for the selected tab in each window (plus D46). Text goes on the stream; special keys and Ctrl chords go as `pane.send_keys`. ([Terminal plane](/docs/talking-to-herdr#terminal-plane)) | Public, per pane, works over SSH, survives moves. herdr encodes special keys for the program's input modes. | herdr's private client socket; `terminal attach` in a PTY; polling `pane.read`; encoding special keys in the app. |
| D8 | One control rule: the app opens `control` without takeover and watches if refused. It takes control (`--takeover`) on the first key press, paste or click in the card, or Take Back. ([One controller per pane](/docs/talking-to-herdr#one-controller-per-pane)) | One controller and one PTY size per pane. Looking pins the PTY to the card size, which is accepted. | Taking over on open; automatic takeover. |
| D38 | Refuse herdr older than 0.9.3; the version comes from the snapshot. The machine's login shell finds herdr once (`command -v herdr`), and every call runs that absolute path with `--session`. ([herdr on each machine](/docs/talking-to-herdr#herdr-on-each-machine)) | Old herdr lacks what we use; lenient decoding needs nothing for newer protocols; the app runs the herdr the user's terminal runs, and `PATH` stays the user's own; no inherited variable can redirect a command. | A read-only mode; a banner for newer protocols; herdr's install folders in front of `PATH` (they reordered the `PATH` of the server and every pane, and needed a trim and `env -P`); `--check`. |
| D40 | Every `call()` times out after 10 s ([Requests](/docs/talking-to-herdr#requests)). One health check per session reads the snapshot every 30 s, every 2 s while it fails; automatic retries never prompt ([Health check](/docs/machines#health-check)). | A dead link must not hang writes. The snapshot carries the version and catches missed events. A retry that prompts would show a dialog every few seconds. | No timeout; a timeout on streams; a separate `ping`, wake check and back-off. |
| D46 | The app keeps the shown tabs' cards plus the 20 most recently shown other terminals (their `control` streams and surfaces) and the 20 most recently shown other web cards (browsers and plugins, their web views), across all windows, least recently shown first out (`spareTerminals`, `spareWebCards`). Floated cards and cards with unsaved edits are never dropped. On a memory-pressure warning both go down to half. A hidden terminal keeps a copy of its last frame; a web card keeps a picture at 1x, under one 200 MB cap for every picture in the app, and a dropped one is made again from its label under it. ([What streams](/docs/talking-to-herdr#what-streams), [What stays in memory](/docs/ui/browser#what-stays-in-memory)) | Going back to a visited tab is at once; a kept terminal costs about 7 MB of herdr run plus its surface, a kept web card about 28 MB (its WebKit process), and neither costs CPU at rest. 40 + 40 worked too (1.7 GB for all processes), so the bound is memory, which macOS's warning guards. | 4 kept; 16 terminals and every web card kept; 32 kept; no bound, only memory pressure; purgeable pictures (macOS takes them back within seconds); pictures at pixel size (1275 MB against 833 MB at 1x for 20 browsers); a byte budget. |
| D49 | A `Multiplexer` Swift protocol, with herdr as its first and only implementation: a deliberate exception to "no abstraction with one implementation". ([The Multiplexer interface](/docs/architecture#the-multiplexer-interface)) | Oriel is a client for terminal multiplexers, herdr first. One named seam keeps herdr's JSON and argv out of the views. | herdr types used directly by the views; waiting for a second multiplexer before naming the seam. |
| D57 | Where things live: anything that takes space in the layout is a multiplexer pane with a label; transient UI is app memory only; per-device settings are app storage. ([Data](/docs/data#where-things-live)) | One rule for every new feature; keeps D1 true; a fresh device rebuilds every layout from the multiplexer. | App-only surfaces in the layout (a second layout system); syncing UI state between devices. |
| D66 | Control is per session across windows. When two windows show the same session, the window where the user last typed or clicked in a terminal holds that session's `control` streams; the other opens `observe`, dims its cards a little and shows "Controlled in another window · Take Back". Take Back, or a key press or click in a terminal card there, moves control to that window. Windows on different sessions each control their own. ([Control between windows](/docs/talking-to-herdr#control-between-windows)) | One controller and one PTY size per pane, as in D8. Per session, so one window never mixes controlled and watched cards of one session. | Control per pane between windows; both windows asking for control (they fight over the PTY size); one main window. |

## Machines

| # | Decision | Why | Rejected |
|---|---|---|---|
| D15 | SSH = the system `ssh`, one ControlMaster per host started on purpose, forwarding off, an askpass script the app writes beside the sockets. ([The SSH connection](/docs/machines#the-ssh-connection)) | The user's setup works; one prompt per host; no path back to the Mac. | `ControlMaster=auto`; a Swift SSH library on macOS. |
| D43 | A machine is a host (This Mac or an SSH host) with its own icon; a window shows one machine and its open sessions as pages, starting with `default`, and Detach Session removes a page. Sessions on one host share one SSH connection and one relay session (D2). ([What a machine is](/docs/machines#what-a-machine-is), [SSH sessions](/docs/machines#ssh-sessions)) | Users think of a computer, not of a herdr server; a session costs nothing until it is opened; one connection keeps one prompt. | One machine per herdr session; every running session loaded by itself; one connection per session; a channel budget. |
| D47 | On This Mac the app starts a session's server as a one-shot launchd job in the user's GUI domain, with the CLI's `PATH`, `HOME`, `SSH_AUTH_SOCK` and `XDG_*` variables. A remote server starts with `nohup` over SSH. ([Checks on connect](/docs/machines#checks-on-connect)) | launchd is the server's parent and responsible process, so macOS privacy prompts never name Oriel; the server has its own process group and outlives the app; server and CLI agree on paths. | Never starting the local server; `launchctl submit` (launchd restarted the server after `herdr session stop`); `nohup` or a double fork from the app (the app stays the responsible process); a Terminal window running herdr. |
| D54 | The app keeps its own machine list; herdr on the Mac is needed only for This Mac's sessions. ([The machine list](/docs/machines#the-machine-list), [Add a machine](/docs/ui/add-a-machine)) | Remote machines work on a Mac without herdr; the askpass dialog answers ssh's questions. | herdr's machine list as the only list, with `herdr machine add` in a terminal card; an import at first launch; a second list kept in sync both ways. |
| D67 | A workspace row shows git state like herdr's Spaces panel: the branch and ahead and behind counts, no changed-file count. The app runs `git --no-optional-locks -C <root> status --porcelain=v2 --branch --untracked-files=no` on the machine through `Exec.run` (root = `worktree.checkout_path`, else the cwd of the workspace's first pane), for a workspace that is new or whose root changed and every 10 s, one run per workspace, only for the page in view of a visible window. When git is only the `/usr/bin/git` stub without developer tools, the app runs none. A linked git worktree sits indented under its repository's workspace. ([Sidebar](/docs/ui/window#sidebar), [Git status](/docs/talking-to-herdr#git-status)) | herdr's snapshot has no branch. One porcelain run gives the branch and the counts in a stable format; skipping untracked files keeps it fast in a big repository. Runs only for rows that show. The stub would open the "install developer tools" dialog. | A changed-file count; polling every page; a `git` library in the app. |
| D68 | The Open Session panel is the one place to create, start or open a session as a page of the window: a field ("Name a new session, or find one") over a list of New, Running (not open in this window), Stopped, and the sessions already open. Enter or a click on a row takes one path for a new, a running and a stopped session: start the server if it is not running (D47), then open its page last in the window. On an open session it switches to its page. A running session's row has Stop, a stopped one's Delete; both ask first. The footer button, the workspace menu and File ▸ Open Session… (⌥⌘T) open it. ([Open Session](/docs/ui/window#open-session)) | One place and one name for every way to get a session onto a page. | A session picker in the title row; separate New Session and Change Session commands. |

## Layout and terminals

| # | Decision | Why | Rejected |
|---|---|---|---|
| D9 | libghostty-spm draws terminals, at an exact pin. ([Dependencies](/docs/platform#dependencies)) | Metal, IME and one Swift API. | SwiftTerm; xterm.js in a web view. |
| D10 | Layout = herdr's split tree rebuilt from the flat snapshot; resize = `layout.set_split_ratio`. ([Layout and sizing](/docs/layout)) | Ratios live in herdr; no extra calls. | App-owned sizes; `layout.export` per tab. |
| D11 | Zoom is the app's own: the zoomed card fills its tab's page, drawn by the split tree. ([Zoom is the app's own](/docs/layout#zoom-is-the-apps-own)) | `pane.zoom` moves herdr's focus, marks the tab seen and blocks moves. In the split tree, no terminal view changes host and no other PTY resizes. | `pane.zoom`; a separate layer (its terminal view did not come back on restore). |
| D12 | One tab = one page in the strip. ([Swiping](/docs/ui/swiping)) | Matches herdr and Cube. | Panes wider than the window in one long scroller. |
| D13 | The app never calls herdr's focus methods; selection and "seen" are the app's own, per device. ([Selection and "seen"](/docs/layout#selection-and-seen-are-the-apps-own)) | Each focus call moves every attached herdr TUI. | Focusing on click or swipe. |
| D14 | "Finished, not seen" = `completion_seq` not null and different from the seen value; the first sighting counts as seen. Looking at a pane (its tab selected on the page in view of the key window) records it seen. Seen values live in memory in the session's store, shared by its windows. ([Selection and "seen"](/docs/layout#selection-and-seen-are-the-apps-own)) | herdr skips `done` when a TUI watches the tab; the counter restarts with herdr. | Waiting for `done`; a "greater than" test. |
| D41 | Closing a pane asks first unless the pane runs only its shell. Closing tabs or a workspace asks only when a pane of them runs a program besides its shell. The dialog names what runs; its action button is red; Return confirms, Esc cancels. ([Writes](/docs/talking-to-herdr#writes-are-herdr-calls)) | A close kills processes on every device and cannot be undone; a pane with only its shell loses nothing. | Asking only when an agent works; always asking for tabs and workspaces; never asking. |
| D42 | Tabs act like Rex's: 220 pt each on a capsule track that scrolls when they do not fit, 1 pt dividers, one selection capsule that slides with Rex's spring, and × on the hovered tab only. A working agent shows three dots that animate at 15 fps or less, in step on every tab and still under Reduce Motion, on every tab with a working agent, the selected one too; needs you (amber) and finished (green) are 7 pt badges on the front program icon. Dividers have a 16 pt hit area and a 36 × 3 pt grip in the muted secondary color on hover and drag; a double-click sets 0.5, ⌥⌘= balances the tab, and every split made in the app evens out its row. ([Main window](/docs/ui/window#tab-bar), [Layout](/docs/layout#dividers)) | Rex is the reference look, measured from Rex; dots show work without a word, and a slow clock-driven animation costs little. gorex stays the readable source for the slot and divider behavior. | A static ◔ glyph in one status slot (× > ▲ > ✓ > ◔); several glyphs per tab; an animation per tab with its own phase. |
| D64 | No card fades: every card is drawn at full strength, in key windows and the others. Only the keyboard card's fill and stroke set it apart, and in Glass only a little. A watching window's 0.85 dim (D66) stays. No setting. ([Layout](/docs/layout#the-keyboard-card)) | Faded cards and Glass's darker card fill sat too far apart from the keyboard card. | Rex's content fade (0.7 for other cards, 0.5 and 0.8 in a window that is not key) with View ▸ Fade Inactive Panes to turn it off; a black overlay over unfocused cards. |
| D69 | Drag and drop offers only what herdr allows, and builds the rest from herdr calls: a swap only inside one tab; a move into another tab beside a card; a drop on an edge of a card in the same tab is a move to a new tab, a move back beside the target and, for left or top, a swap. Tabs reorder inside their workspace; a tab dropped on another workspace or on New Workspace moves there pane by pane, its split tree and ratios rebuilt. Workspaces reorder with `workspace.move_block` (a workspace with its linked worktrees). A pane moved into a tab gets an equal share of its run of splits, as after a split. Nothing moves between sessions or machines. ([Drag and drop](/docs/ui/drag-and-drop)) | herdr 0.9.5 refuses a swap across tabs (`cross_tab`) and a move into the pane's own tab (`same_tab`), splits only right or down, and moves tabs only inside a workspace (`layout.apply` makes new terminals). Every step stays a herdr call (D1). | Only swap inside one tab; drops between sessions. |

## Pane kinds

| # | Decision | Why | Rejected |
|---|---|---|---|
| D71 | Every pane the app creates shows a chooser first: Terminal (selected, so Return gives a terminal), Agent (its four agents open in place), Browser, File Explorer or Git. The shell starts at once behind it; the chooser is the app's own state. An agent is ready when herdr reports it with a status other than `unknown`. ([New pane](/docs/ui/new-pane)) | A pane says what it is for in one key; a quick terminal stays one key away; herdr reads agent status from the screen on every machine. | A shell shown at once; a glass panel with tiles and a second step for agents; a ready signal from frames going quiet. |
| D72 | A browser pane is a herdr pane labeled `oriel:browser#<iid> <url>` running a placeholder, drawn by the app as a `WKWebView` with Web Inspector, one WebKit store per machine, its page and history in a state file on the machine, and a page from the machine loading by itself only from an approved or safe origin. An open card follows its label. ([Browser](/docs/ui/browser)) | The label survives moves and cold restarts and every device and the TUI see it; WebKit costs no app size; agents can open and change pages with herdr alone. | Chromium through CEF; app-only tabs; loading every label by itself; a card that ignores renames until rebuilt. |
| D73 | A remote machine's browser pages go through one SOCKS proxy per machine: the app's own front on a loopback port before ssh's `-D` on the ControlMaster, with `localhost` loaded as `<machine>.localhost` and every other loopback request blocked. ([Remote localhost](/docs/ui/browser#remote-localhost)) | One forward covers every port and name; refusals come at once; the page never reaches This Mac's loopback; nothing is installed on the machine. | A forward per port (clashing ports, changed origins); ssh's `-D` alone (60 s waits); a server helper. |
| D88 | A link that asks for a new window (⌘-click, `target=_blank`, the context menu's Open ‹Link› in New Tab) opens a browser pane in a new herdr tab, in the background, its origin approved. A page's own `window.open` (an OAuth popup) stays over the card, on glass, closed by Esc or its ×. No download items. ([Popups, links and dialogs](/docs/ui/browser#popups-links-and-dialogs)) | Links open as in Safari; the new tab is a herdr pane every device sees; a popup needs its opener. | WebKit's popup sheet for every new window (it could not be closed over a white page); loading `target=_blank` in the card; download items that save nothing. |
| D74 | The chat view is only for agents Oriel starts with its flags (from the chooser, or again with Relaunch with Chat, D83): their own history, followed on their machine, plus `agent.prompt` to send; a pane is known by a launch marker in its foreground argv (`pane.process_info`). ([Chat view](/docs/ui/chat-view)) | The history is the agent's own record, so it is exact and survives a relaunch of the app with no state; the same code works over the relay. | A chat for every pane from its screen text (it breaks with each agent release); restarting the agent in a structured mode (`codex --remote` with an app-server, `pi --mode rpc`, ACP, the Agent SDK), which adds a process or a server for nothing the hooks do not give; live text word by word. |
| D75 | A small core, and the live terminal for the rest: the chat answers only Claude Code's single-choice questions and OpenCode's permissions and questions; tool approvals, other questions, dialogs and pickers show the live terminal at the bottom of the card. ([Waiting](/docs/ui/chat-view#waiting)) | Every case stays answerable without a chat answer for each. | In-chat tool approvals: in Claude Code a company hook that allows beats Oriel's deny, and a waiting hook keeps prompts open that would close by themselves; in Codex a waiting hook runs before its reviewer and hides the TUI's prompt. |
| D76 | The chooser types a launch line into the pane's shell: the command with inline hooks or a plugin, no quote or backslash in a hook, side files in `~/.cache/oriel/chat/T/` (0700) that each launch sweeps after 30 days untouched; the bare command once more when the shell comes back at once. ([Launch flags](/docs/ui/chat-view#launch-flags)) | The user's alias or function still runs; one line works in sh, bash, zsh and fish; nothing is written to the user's config; a build that refuses the flags still starts. | A settings file per launch; `/tmp` (shared between users); `env … sh -c 'exec …'` (skips the user's alias); writing hooks into the user's settings; a bypass flag for Codex's hook review (its trust hash instead). |
| D77 | pi-oriel ships inside the app and is written to the machine named by its content; Pi's phase is its state file alone. ([Launch flags](/docs/ui/chat-view#launch-flags)) | The user may not have pi-hkandala; two app versions never fight over one file; the state file works on remote machines without herdr's pi integration. | An extension in pi-hkandala; herdr's status for Pi's working and idle. |
| D78 | OpenCode's chat goes through its own server on 127.0.0.1 with a password per launch from a 0600 file, reached with `curl` on its machine; a build that never reports (MetaCode) is told by what it does: no state line in 15 s flips the card to its terminal. ([Where messages come from](/docs/ui/chat-view#where-messages-come-from)) | opencode writes no transcript file; the password keeps other local programs off the port and never shows in argv or the scrollback. | `command -v opencode` up front (the app's shell is not the pane's); opencode 2.x's shared service. |
| D79 | The chat looks like Messages, with no status island: a 760 pt column on any card with roomy Markdown, the user's messages and the agent's replies in the blue and gray bubbles of macOS Messages, a reply box that grows to 5 lines with the model and effort under the text and Send always in the accent, the reply box on glass over the bottom of the messages, one app-wide detail level (Replies only, Activity, Everything; Replies only by default) in a glass pill that reads the level, beside Chat \| TUI in the header's second row, each run of tool calls as one quiet line in pi-content-layout's words whose calls open to their input and output, and thinking as a step of its run. ([What it looks like](/docs/ui/chat-view#what-it-looks-like), [Detail levels](/docs/ui/chat-view#detail-levels)) | Long replies read well on a wide card; the replies get the attention, not the tool calls; the view controls sit together; the messages show under the glass, as the user asked; one wording in the chat and in pi. | A web view; the level names Steps and All (they did not say what shows); a glass card per run of tool calls (as loud as a reply); the level as three segments beside the reply box; a status island; a `Show:` pull-down (its label said less than the pill); replies as plain text (they did not read as one side of a conversation); a gray Send in an empty chat; a swipe between chat and terminal (swipes belong to the strip). |
| D80 | A browser card, a plugin card and an agent card have two header rows: row 1 has the title and the card buttons, as a terminal card's one row; row 2 has the kind's controls (the browser's toolbar; a plugin's Back, Forward and its page's controls; the agent's name and folder, its state as a dot and a word as t3code draws a thread's, then the level pill, Chat \| TUI or Relaunch with Chat). ([Pane card](/docs/ui/window#pane-card)) | Every card keeps its title and buttons in the same place, and the kind's controls get the full width. A terminal keeps its height. | The browser's toolbar as its whole header; the agent's state as a capsule on row 1 (it did not line up with the title); the agent's controls squeezed beside its title; two rows for every card. |
| D81 | A browser card has no list of the machine's listening ports: the user types the address. ([The card](/docs/ui/browser#the-card)) | The list added little over typing `localhost:3000`, and cost a run with process lookups on the machine each time it opened. | A ports chip that listed the listeners, grouped by workspace. |
| D82 | An agent pane is named by its own session's title: the user's herdr label, else the title the agent keeps (read on its machine with herdr's `agent_session`), else "Untitled"; in the card, the floating window, the tab and the Agents view. ([Session titles](/docs/ui/chat-view#session-titles)) | Claude Code, Codex and OpenCode name sessions themselves, and pi's `/name` names one; the user's own label still wins. One small read per change, on any machine. | Titles the app makes itself; writing the title into herdr's label (it renames the pane for every device); a scan of the agent's files for a session herdr does not report. |
| D83 | Relaunch with Chat starts an agent that runs without Oriel's flags again with them, in the same session: Stop if needed, ⌃C, the agent's quit command, then the launch line with the resume arguments, made before the agent quits. It asks first while the agent works or waits. ([Relaunch with Chat](/docs/ui/chat-view#relaunch-with-chat)) | The chat needs the launch marker and hooks that only a launch adds; resuming keeps the conversation; a failed run on the machine leaves the agent running. | A chat from screen text (D74); a bare-command fallback (it starts a new session); a session found by scanning files; a restart with no question during a turn. |
| D84 | A chat pane opens on its TUI; the user switches to Chat (Chat \| TUI). After Relaunch with Chat it opens on the chat. ([Switching views](/docs/ui/chat-view#switching-views)) | The user asked for the terminal first; Relaunch with Chat is itself a request for the chat. | The chat first; a setting for the first view. |
| D85 | A chat reads a history file whole, from its start, and shows it once read up to where it ended at the open; the backlog is parsed off the main thread, a run of lines at a time, with the loader in the empty chat meanwhile. On the pane's machine awk drops the lines the agent's parser skips, and counts their bytes. ([Where messages come from](/docs/ui/chat-view#where-messages-come-from)) | One Claude Code turn can pass 256 KiB, so a tail showed no earlier turns; the filter keeps most of a transcript (Claude Code's `api-request-*` records) off a remote machine's relay; a whole first read does not show row by row; a 108 MB session took seconds and half the main thread when parsed there, and now the window keeps its frame rate. | The last 256 KiB; a parser on the machine; parsing on the main actor with a yield every 200 lines (the window stuttered while a long session loaded). |
| D86 | A reply's Markdown is parsed by Apple's `swift-markdown` (cmark-gfm) and drawn with SwiftUI: tables, task lists, strikethrough, nested lists and quotes, rules; bare web addresses linked with `NSDataDetector`; an image shown as its linked description, never fetched. ([What it looks like](/docs/ui/chat-view#what-it-looks-like)) | A known GFM parser covers the standard syntax with no hand-made parsing; a fetched image could send what the agent read to any server. | `AttributedString(markdown:)` (no tables or task lists); a parser of our own; a web view. |
| D89 | Two default plugins, File Explorer and Git, are pane kinds built into the app, each a herdr pane labeled `oriel:<kind>#<iid> <arg>` running a placeholder, with no state file: the label holds the place the card shows (a folder, a file, a repository's root, or a diff's root and source), and it picks the page. One card moves between places with Back and Forward, as a browser does, and its label follows. A click opens in the card, ⌘-click in a new herdr tab right after the card's tab (`layout.apply`, then `tab.move`), ⌥-click in a pane to its side (`pane.move` after `layout.apply`). The words of the five kinds before (`file`, `preview`, `markdown`, `files`, `diff`) still open. ([Default plugins](/docs/ui/plugins)) | The label survives moves and cold restarts, and every device and the TUI see it, as for the browser (D72). One card per place filled the session with tabs; exploring in one card, with the other two gestures one modifier away, keeps the card the user came from only when asked. | Five kinds with a linked open for every file (the user asked to merge them); the web view's own history for Back (Git's native rows share the card's list); a plugin registry with manifests first; a state file per card; a ⌘K Go to File. |
| D90 | The plugins' content is web pages (CodeMirror 6, `@pierre/diffs`, `@pierre/trees`, markdown-it, pdf.js) bundled into the app by esbuild, one `WKWebView` and one WebContent process per card. The header rows, the toast, Open With and all file and git data stay native, in HerdrKit's `Files` and `Git` over `Exec`. ([How the web cards work](/docs/ui/plugins#how-the-web-cards-work)) | Recognized editors and viewers give syntax colors, word diffs and a fast tree with little app code. Native data keeps saves, hashes and git in one tested place for This Mac and remote machines. The native variant of the same plugins lives on its own branch, so the user can compare. | A framework (React, Svelte); a shared process pool (`WKProcessPool` does nothing); the page running commands itself; a bundle checked into git. |
