Grouped in the order of the sidebar. Each row is a rule that holds now, with a
link to the page that has the mechanism. Earlier choices are in "Rejected".
Numbers are stable: a new decision gets a new number, and the number of a
decision that no longer holds is not used again.

## Source of truth and protocol

| # | Decision | Why | Rejected |
|---|---|---|---|
| D1 | herdr is the source of truth for workspaces, tabs, panes, layout, web addresses and plugin panes. ([Data](/docs/data)) | Clients with their own copy drifted. A fresh device rebuilds from herdr. | App-owned tabs or layout. |
| D2 | Every pane kind reaches its machine through two calls: `run(argv)` and `dial(host, port)`. Closing a run's stdin ends it. ([Run and dial](/docs/talking-to-herdr#run-and-dial)) | One path for local, remote macOS and iOS; herdr's own remote method. A closed stdin ends a child even after an app crash, remote ones too. | A daemon, relay or bridge of our own on the machine; a release message, a global pid list and a kill at exit. |
| D3 | Every remote command goes through a base64 envelope run by `sh`. ([Run and dial](/docs/talking-to-herdr#run-and-dial)) | The login shell may be fish, where POSIX quoting is not safe. | Quoting argv into the login shell. |
| D4 | Control plane = `herdr --session S remote-api-bridge` on every machine, one call per request. ([Requests](/docs/talking-to-herdr#requests)) | One path; no socket lookup; the cost hides behind the snapshot pacing. | A direct local socket; socket forwarding. |
| D5 | Events only mean "read the snapshot again" (no payload is decoded; status events only for agent panes; no focus or `pane.updated` events). Reads are paced per machine: one in flight, plus a read-again flag. ([Events](/docs/talking-to-herdr#events)) | One code path; each status entry costs herdr a poll; a read batches the events that arrive during it. | Applying deltas; subscribing to every pane; polling `session.snapshot` every second; a debounce with a maximum wait. |
| D6 | Snapshots are applied to stable observable objects with hand-written lenient models. Every card is keyed by `(machine, terminal_id)`. ([Reconcile](/docs/talking-to-herdr#reconcile)) | One status change redraws one row. `terminal_id` survives every move; after a cold restart cards are built again from the machine. | One big state value; code generation; plugin cards keyed by instance id. |
| D7 | Terminal plane = `herdr terminal session control/observe` by `terminal_id`, for the selected tab of the selected machine (Mac: plus D46). Text goes on the stream; special keys and Ctrl chords go as `pane.send_keys`. ([Terminal plane](/docs/talking-to-herdr#terminal-plane)) | Public, per pane, works over SSH, survives moves. herdr encodes special keys for the program's input modes. | herdr's private client socket; `terminal attach` in a PTY; polling `pane.read`; encoding special keys in the app. |
| D8 | One control rule: the Mac opens `control` without takeover and watches if refused; iPhone and iPad open `observe`. Any device takes control (`--takeover`) on the first key press, paste, click or tap in the card, or Take back. ([One controller per pane](/docs/talking-to-herdr#one-controller-per-pane)) | One controller and one PTY size per pane. Looking on a phone never resizes the PTY. Looking on a Mac pins it to the card size, which is accepted. | Taking over on open; automatic takeover; `control` on every device. |
| D38 | Refuse herdr older than 0.9.3; the version comes from the snapshot. herdr's install folders are on `PATH`, and every herdr argv carries `--session`. ([herdr on each machine](/docs/talking-to-herdr#herdr-on-each-machine)) | Old herdr lacks what we use; lenient decoding needs nothing for newer protocols; no inherited variable can redirect a command. | A read-only mode; a banner for newer protocols; a herdr lookup step and `--check`. |
| D40 | Every `call()` times out after 10 s ([Requests](/docs/talking-to-herdr#requests)). One health check per machine reads the snapshot every 30 s, every 2 s while it fails; automatic retries never prompt ([Health check](/docs/machines#health-check)). | A dead link must not hang writes. The snapshot carries the version and catches missed events. A retry that prompts would show a dialog every few seconds. | No timeout; a timeout on streams; a separate `ping`, wake check and back-off. |
| D46 | The Mac keeps the `control` streams of recently shown tabs, about 24 terminals, least recently shown first out; hidden ones stop drawing but keep reading. ([What streams](/docs/talking-to-herdr#what-streams)) | Coming back to a tab resizes nothing: no second redraw of a full-screen app while a herdr TUI is also attached. | Releasing on leaving a tab (each return resized the PTY twice); streaming every pane. |
| D49 | A `Multiplexer` Swift protocol, with herdr as its first and only implementation: a deliberate exception to "no abstraction with one implementation". ([The Multiplexer interface](/docs/architecture#the-multiplexer-interface)) | Oriel is a client for terminal multiplexers, herdr first. One named seam keeps herdr's JSON and argv out of the views and plugins. | herdr types used directly by the views; waiting for a second multiplexer before naming the seam. |
| D52 | Web cards reach a remote `localhost` through `dial`, on the same local port when it is free; Tailscale and LAN addresses load directly. The Open :port chip comes from the terminal text the app already streams; the ports list runs on demand. ([Remote localhost](/docs/plugins/web-page#remote-localhost), [Finding ports](/docs/plugins/web-page#finding-ports)) | SSH already does it; nothing to install on the machine; forwards use no SSH session; the same port keeps the page's origin (OAuth callbacks, CORS lists); the chip needs no extra stream. | A server helper of our own now ([Future work](/docs/future-work)); SOCKS (WebKit never proxies loopback); a different local port every time; `pane.output_matched` on a second event stream. |
| D57 | Where things live: anything that takes space in the layout is a multiplexer pane with a label; transient UI is app memory only; per-device settings are app storage. ([Data](/docs/data#where-things-live)) | One rule for every new feature; keeps D1 true; a fresh device rebuilds every layout from the multiplexer. | App-only surfaces in the layout (a second layout system); syncing UI state between devices. |

## Machines

| # | Decision | Why | Rejected |
|---|---|---|---|
| D15 | macOS SSH = system `ssh`, one ControlMaster per host started on purpose, forwarding off, a bundled askpass script. ([macOS](/docs/machines#macos)) | The user's setup works; one prompt per host; no path back to the Mac. | `ControlMaster=auto`; a Swift SSH library on macOS. |
| D17 | iOS uses Citadel with a Secure Enclave key; machines in `UserDefaults`; the Mac via Remote Login. ([iOS](/docs/machines#ios)) | Pure Swift; the key cannot leave the device; no new mechanism. Spike S7 tests the exec channels first. | libssh2 + OpenSSL; a relay. |
| D43 | A machine is one herdr session: one entry in the machine list and one sidebar page; sessions on one host share one SSH connection. The app counts no channels: when the server refuses one, it closes the least recently shown kept stream and tries once more. ([What a machine is](/docs/machines#what-a-machine-is), [SSH sessions](/docs/machines#ssh-sessions)) | herdr's own unit is the session; one connection per host keeps one prompt. The server's refusal is the only true count. | One connection per session; one machine per host; a channel budget with reservations, priorities and a learned limit. |
| D47 | On This Mac the app starts a session's server as a one-shot launchd job in the user's GUI domain, with the CLI's `PATH`, `HOME`, `SSH_AUTH_SOCK` and `XDG_*` variables. A remote server starts with `nohup` over SSH. ([Checks on connect](/docs/machines#checks-on-connect)) | launchd is the server's parent and responsible process, so macOS privacy prompts never name Oriel; the server has its own process group and outlives the app; server and CLI agree on paths. | Never starting the local server; `launchctl submit` (launchd restarted the server after `herdr session stop`); `nohup` or a double fork from the app (the app stays the responsible process); a Terminal window running herdr. |
| D54 | The app keeps its own machine list on macOS and iOS; herdr on the Mac is needed only for This Mac's sessions. On macOS the Add Machine sheet offers herdr's machines, checked while the list is empty. ([The machine list](/docs/machines#the-machine-list), [Add a machine](/docs/ui/add-a-machine)) | One code path on both platforms; remote machines work on a Mac without herdr; the askpass dialog answers ssh's questions. | herdr's machine list as the only list on macOS, with `herdr machine add` in a terminal card; an import at first launch; a second list kept in sync both ways. |

## Layout and terminals

| # | Decision | Why | Rejected |
|---|---|---|---|
| D9 | libghostty-spm draws terminals, as a pinned build with uHerdr's response-suppression patch. ([Dependencies](/docs/platform#dependencies)) | Best quality on both platforms. The patch stops a second answer to terminal queries that herdr already answered. | SwiftTerm as the main renderer (kept as a fallback); xterm.js in a web view. |
| D10 | Layout = herdr's split tree rebuilt from the flat snapshot; resize = `layout.set_split_ratio`. ([Layout and sizing](/docs/layout)) | Ratios live in herdr; no extra calls. | App-owned sizes; `layout.export` per tab. |
| D11 | Zoom is the app's own: the zoomed card fills its tab's page, drawn by the split tree. ([Zoom is the app's own](/docs/layout#zoom-is-the-apps-own)) | `pane.zoom` moves herdr's focus, marks the tab seen and blocks moves. In the split tree, no terminal view changes host and no other PTY resizes. | `pane.zoom`; a separate layer (its terminal view did not come back on restore). |
| D12 | One tab = one page in the strip. ([Swiping](/docs/ui/swiping)) | Matches herdr and Cube. | Panes wider than the window in one long scroller. |
| D13 | The app never calls herdr's focus methods; selection and "seen" are the app's own, per device. ([Selection and "seen"](/docs/layout#selection-and-seen-are-the-apps-own)) | Each focus call moves every attached herdr TUI. | Focusing on click or swipe. |
| D14 | "Finished, not seen" = `completion_seq` not null and different from the seen value; the first sighting counts as seen. ([Selection and "seen"](/docs/layout#selection-and-seen-are-the-apps-own)) | herdr skips `done` when a TUI watches the tab; the counter restarts with herdr. | Waiting for `done`; a "greater than" test. |
| D41 | Closing a pane asks first unless the pane runs only its shell; web and plugin panes close at once. Closing a tab or workspace always asks. ([Writes](/docs/talking-to-herdr#writes-are-herdr-calls)) | A close kills processes on every device and cannot be undone. | Asking only when an agent works; never asking. |
| D42 | Rex-like behavior follows gorex: one tab status slot (× on hover > ▲ > ✓ > ◔), a static ◔, double-click a divider to reset it, ⌃⌘= for equal splits, the window title from the selected tab. ([Main window](/docs/ui/window)) | gorex is a readable Rex copy; a static glyph avoids constant redraws. gorex is not a glass reference. | An animated working glyph; several glyphs per tab. |
| D56 | Image paste into a terminal, agent or chat reply box: write the PNG to a new temporary folder on the pane's machine with `run`, then paste its path. ([Image paste](/docs/plugins/terminal-and-agent#image-paste)) | Works the same on This Mac and over SSH; agents already accept a pasted image path; what uHerdr, collie, termote and roamgate do. | Image bytes through the terminal (herdr's stream and agents do not take them); a server helper; a folder of our own with its own cleanup. |

## Chat and status

| # | Decision | Why | Rejected |
|---|---|---|---|
| D29 | Chat = the agent's transcript tailed on the machine + `agent.prompt`; parsers for pi, Claude Code and Codex; a screen-text chat for every other agent or terminal pane. ([Chat view](/docs/chat-view)) | What every working chat view does; any agent or terminal pane can switch. | Per-agent prompt parsers; parsing the screen into fake messages. |
| D30 | The blocked panel sends a key only if the agent is still blocked and the prompt text is unchanged. ([Sending and answering](/docs/chat-view#sending-and-answering)) | The prompt may have changed on another device. | Sending without a check. |
| D31 | Notifications are made by the app from snapshot changes, `.passive` while the pill shows; no iOS push in v1. ([Notifications](/docs/status#notifications)) | herdr sends its own only to TUI clients; no double alerts; push needs a relay ([Future work](/docs/future-work)). | herdr's private notifications; dropping banners. |
| D32 | Floating pills: one non-activating `NSPanel`, one pill with a glyph per agent, a pill card that is the compact chat view, peeks that never take the keyboard, opaque. ([Floating pills](/docs/ui/pills)) | One proved the shape; never steal a keystroke; glass renders flat in an inactive app. | A pill per agent; a SwiftUI window; glass pills. |
| D50 | Floating panes are not in v1. ([Future work](/docs/future-work)) | v1 needs the strip, splits and chat first; nothing in herdr or the app depends on them. | Building them in v1, as panes in a tab labeled `oriel:float`. |
| D55 | Agent status comes only from the multiplexer's API; under herdr the app never parses OSC 7501. ([Status](/docs/status#status-area-and-notifications)) | herdr's terminal stream is a redrawn screen, so the sequence never reaches the app; one source keeps every device in agreement. | Parsing OSC 7501 in the app's libghostty surfaces under herdr. |

## Look and platform

| # | Decision | Why | Rejected |
|---|---|---|---|
| D44 | Dark theme only, frosted: a dark-tinted behind-window blur, translucent dark pane cards with a hairline border, the sidebar flat on the background; Liquid Glass only on the tab marker, popovers and the palette. ([Theme and accessibility](/docs/ui/theme-and-accessibility)) | The user's reference look (Rex): the desktop shows through softly, and only the cards stand out from it. | An opaque near-black window and opaque cards; glass on the cards; a glass sidebar panel; a light theme in v1. |
| D45 | One title-bar row: sidebar toggle, session picker, then the tab capsules while the sidebar is hidden, ⌘ and + on the right. While the sidebar is shown, tabs are its rows. ([Main window](/docs/ui/window)) | The reference look; tabs show once, where there is room. | A tab bar and a sidebar at the same time; agent rows in the v0 sidebar. |
| D48 | ⌘K (and the title-bar ⌘ button) opens the command palette: tabs, workspaces and running sessions, filtered as you type; card actions join it later. ([Keyboard shortcuts](/docs/ui/theme-and-accessibility#keyboard-shortcuts)) | ⌘K is the palette key in Rex, Slack, Linear and VS Code's quick open; herdr owns the screen, so Terminal's ⌘K (clear) has nothing to clear. | ⇧⌘P; ⌘P. |
| D34 | One multiplatform target, macOS 26 and iOS 26, one main window. ([One codebase](/docs/platform#one-codebase)) | Liquid Glass with no fallbacks; no control fights between windows. | Separate apps; back-deploying; several main windows in v1. |
| D35 | Horizontal gestures belong to the strip; the PaneViewRegistry owns every view. ([Making the strip work](/docs/platform#making-the-strip-work)) | Terminals and web views would eat the swipe; SwiftUI would destroy views. | Each view handling its own scroll. |
| D36 | iPhone shows one pane per page and opens agents in chat. ([iPhone and iPad](/docs/ui/iphone-and-ipad)) | Splits do not fit; chat needs no PTY. | Shrinking splits onto a phone. |

## Pane kinds and plugins

| # | Decision | Why | Rejected |
|---|---|---|---|
| D18 | One picker for every pane kind: Terminal, Agent and Web page are fixed rows; every other kind is a plugin from one registry. ([Pane kinds and plugins](/docs/plugins)) | The three built-in kinds are special everywhere else (streams, chat, labels); one model for the rest. | Native manifests for the built-in kinds (a `native` field, reserved ids); herdr TUI plugins in the picker. |
| D20 | Plugins live in the app, installed from a git URL or a linked folder, already built; the app never runs npm. ([Packages](/docs/plugins/packages)) | One install per device for every machine; no setup on any machine; a simple dev loop. | herdr plugins on each machine; an in-app store. |
| D21 | A web or plugin pane is a herdr pane labeled `oriel:<plugin>[/<pane>]#<iid> <arg>`; the iid names its state file. ([Labels and instance ids](/docs/plugins/labels)) | The label is durable and readable, and survives moves and cold restarts. | Metadata tokens; an app-side pane list. |
| D22 | Bigger plugin state lives in a JSON file on the pane's machine, named by iid; preferences stay per device. The device that closes the pane removes the file; on connect, files older than 30 days go. ([State and restore](/docs/plugins/state)) | Shared by every device, survives reinstalls, no sync service; cleanup needs no snapshot. | Labels for everything; app storage; a daily cleanup checked against current labels. |
| D24 | Plugin API = `run` and `dial` on the card's machine, pane context, `setArg`, instance state, read-only preferences and a signal after each snapshot read, with no data. Links and copy use the web's own APIs. ([Plugin API](/docs/plugins/api)) | Covers diff, git history and Markdown; herdr's schema stays behind the `Multiplexer` seam. | Network from the device, a herdr call API, plugins outside panes in v1; the snapshot's data; bridge calls for toasts, `open` and copy. |
| D25 | Plugin security: each card is bound to its pane's machine; every plugin can `run` and `dial`, said plainly at install; consent keyed by id and source; a This Mac confirm; WebKit enforces a user action for open and copy, and the app never pushes script into a page. ([Plugin security](/docs/plugins/security)) | The user sees exactly what they grant; the app adds no reach beyond `run` on the pane's machine. | A permissions field (v1 has one capability); finer permissions that do not hold; a user-gesture tracker in Swift; claiming a sandbox that `run` cannot give. |
| D26 | iOS v1 ships core plugins only. ([Plugins on iOS](/docs/plugins/ios)) | Downloaded code is an App Store review risk. | User plugins on iOS in v1. |
| D27 | Web page = a built-in pane kind labeled `oriel:web#<iid> <url>`, with one data store per machine. A page the user creates or types loads and approves its origin; a card built from the machine loads by itself only for an approved origin or the safe list, else it asks once. ([Web page](/docs/plugins/web-page#when-a-page-loads-by-itself)) | No request leaves the device for an unknown origin without the user; machines stay apart. | Auto-loading every label; tracking which device created or edited a label; a two-part rule for the saved address. |
| D37 | The agent picker lists the available `integration.list` entries, read when it opens. ([Agent](/docs/plugins/terminal-and-agent#agent)) | One call; herdr checks the `PATH`; a newly installed agent shows at once. | Probing every agent with `command -v`; a list read once on connect. |
| D51 | Web and plugin panes are placeholder panes, created with `layout.apply` (a new tab whose pane starts with its label and an inert command, in one call), then `pane.move` into place; never with a `tab_id`. The app never types into a shell. ([Create](/docs/plugins/labels#create)) | Zero app state and one layout for every device and the herdr TUI; no race with shell startup. | Typing the placeholder into a new shell; app-only plugin UI outside herdr's layout; a placeholder that reports itself as an agent. |
| D53 | A plugin is a small web page in a `WKWebView` in its card, served from the app (`oriel-plugin://<id>/`), with `window.oriel` injected; no build tool, and the same plugins run on iOS. A content rule and a Content Security Policy keep it to its own files and scripts. ([Plugin UI](/docs/plugins/plugin-ui)) | Works on macOS and iOS from day one; any web library; little app code; the UI delegate sees new-window requests. | The TypeScript + React kit drawn as native SwiftUI ([Future work](/docs/future-work) option (a)); SwiftUI `WebPage` (drops `window.open`); React Native; native Swift plugins; ExtensionKit. |
| D58 | Web cards keep the typed address in the label, and the current address and scroll position in the state file `web/<iid>.json`, as plugins do. ([Viewing state on the machine](/docs/plugins/web-page#viewing-state-on-the-machine)) | Coming back to a web card, on any device or after a restart, shows the page where the user left it; one state path for every card. | Rewriting the label on every navigation (a rename per click, visible to every TUI); app-only state per device. |
| D59 | An open card changes only when it is built or on **Refresh**, for its label and its state file; Refresh reads the snapshot first. `oriel.state` is view state; data every device must see live lives in files read with `run`. ([When a card reads its state](/docs/plugins/state#when-a-card-reads-its-state)) | A scroll or rename on one device never moves a card under the user's eyes on another; no extra call per rename. | Following renames and state writes live through a metadata token (`oriel_rev`); live follow for web cards only; separate Reload and Refresh buttons. |
