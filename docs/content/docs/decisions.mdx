Grouped in the order of the sidebar. Each row is a rule that holds now, with a

## Source of truth and protocol

| # | Decision | Why | Rejected |
|---|---|---|---|
| D1 | herdr is the source of truth for workspaces, tabs, panes, layout, web addresses and plugin panes. ([Data](/docs/data)) | Clients with their own copy drifted. A fresh device rebuilds from herdr. | App-owned tabs or layout. |
| D2 | Every pane kind reaches its machine through two calls: `run(argv)` and `dial(host, port)`. Closing a run's stdin ends it. ([Run and dial](/docs/talking-to-herdr#run-and-dial)) | One path for local, remote macOS and iOS; herdr's own remote method. A closed stdin ends a child even after an app crash, remote ones too. | A daemon, relay or bridge of our own on the machine; a release message, a global pid list and a kill at exit. |
| D3 | Every remote command goes through a base64 envelope run by `sh`. ([Run and dial](/docs/talking-to-herdr#run-and-dial)) | The login shell may be fish, where POSIX quoting is not safe. | Quoting argv into the login shell. |
| D4 | Control plane = `herdr --session S remote-api-bridge` on every machine, one call per request. ([Requests](/docs/talking-to-herdr#requests)) | One path; no socket lookup; the cost hides behind the snapshot pacing. | A direct local socket; socket forwarding. |
| D5 | Events only mean "read the snapshot again" (no payload is decoded; status events only for agent panes; no focus events; `pane.updated` only because a terminal title change can pick a pane's program icon). Reads are paced per session: one in flight, plus a read-again flag. ([Events](/docs/talking-to-herdr#events)) | One code path; each status entry costs herdr a poll; a read batches the events that arrive during it. | Applying deltas; subscribing to every pane; polling `session.snapshot` every second; a debounce with a maximum wait. |
| D6 | Snapshots are applied to stable observable objects with hand-written lenient models. Every card is keyed by `(machine, session, terminal_id)`. ([Reconcile](/docs/talking-to-herdr#reconcile)) | One status change redraws one row. `terminal_id` survives every move; after a cold restart cards are built again from the machine. | One big state value; code generation; plugin cards keyed by instance id. |
| D7 | Terminal plane = `herdr terminal session control/observe` by `terminal_id`, for the selected tab in each window (Mac: plus D46). Text goes on the stream; special keys and Ctrl chords go as `pane.send_keys`. ([Terminal plane](/docs/talking-to-herdr#terminal-plane)) | Public, per pane, works over SSH, survives moves. herdr encodes special keys for the program's input modes. | herdr's private client socket; `terminal attach` in a PTY; polling `pane.read`; encoding special keys in the app. |
| D8 | One control rule: the Mac opens `control` without takeover and watches if refused; iPhone and iPad open `observe`. Any device takes control (`--takeover`) on the first key press, paste, click or tap in the card, or Take Back. ([One controller per pane](/docs/talking-to-herdr#one-controller-per-pane)) | One controller and one PTY size per pane. Looking on a phone never resizes the PTY. Looking on a Mac pins it to the card size, which is accepted. | Taking over on open; automatic takeover; `control` on every device. |
| D38 | Refuse herdr older than 0.9.3; the version comes from the snapshot. The machine's login shell finds herdr once (`command -v herdr`), and every call runs that absolute path with `--session`. ([herdr on each machine](/docs/talking-to-herdr#herdr-on-each-machine)) | Old herdr lacks what we use; lenient decoding needs nothing for newer protocols; the app runs the herdr the user's terminal runs, and `PATH` stays the user's own; no inherited variable can redirect a command. | A read-only mode; a banner for newer protocols; herdr's install folders in front of `PATH` (they reordered the `PATH` of the server and every pane, and needed a trim and `env -P`); `--check`. |
| D40 | Every `call()` times out after 10 s ([Requests](/docs/talking-to-herdr#requests)). One health check per session reads the snapshot every 30 s, every 2 s while it fails; automatic retries never prompt ([Health check](/docs/machines#health-check)). | A dead link must not hang writes. The snapshot carries the version and catches missed events. A retry that prompts would show a dialog every few seconds. | No timeout; a timeout on streams; a separate `ping`, wake check and back-off. |
| D46 | The Mac keeps the `control` streams and the surfaces of the shown tabs' terminals plus the 4 most recently shown others, across all windows, least recently shown first out; only shown terminals draw; the rest keep only a purgeable still of their last picture. ([What streams](/docs/talking-to-herdr#what-streams)) | Coming back to a recent tab is at once and resizes nothing; each kept terminal costs three IOSurfaces (52 MB at full window on Retina) and a herdr run, so the rest give them up (phase 25: 1.3 GB with 17 terminals). | Releasing on leaving a tab (each return resized the PTY twice); streaming every pane; about 24 kept terminals with their surfaces. |
| D49 | A `Multiplexer` Swift protocol, with herdr as its first and only implementation: a deliberate exception to "no abstraction with one implementation". ([The Multiplexer interface](/docs/architecture#the-multiplexer-interface)) | Oriel is a client for terminal multiplexers, herdr first. One named seam keeps herdr's JSON and argv out of the views and plugins. | herdr types used directly by the views; waiting for a second multiplexer before naming the seam. |
| D52 | Web cards reach a remote `localhost` through `dial`, on the same local port when it is free; Tailscale and LAN addresses load directly. The Open :port chip comes from the terminal text the app already streams; the ports list runs on demand. ([Remote localhost](/docs/plugins/web-page#remote-localhost), [Finding ports](/docs/plugins/web-page#finding-ports)) | SSH already does it; nothing to install on the machine; forwards use no SSH session; the same port keeps the page's origin (OAuth callbacks, CORS lists); the chip needs no extra stream. | A server helper of our own now ([Future work](/docs/future-work)); SOCKS (WebKit never proxies loopback); a different local port every time; `pane.output_matched` on a second event stream. |
| D57 | Where things live: anything that takes space in the layout is a multiplexer pane with a label; transient UI is app memory only; per-device settings are app storage. ([Data](/docs/data#where-things-live)) | One rule for every new feature; keeps D1 true; a fresh device rebuilds every layout from the multiplexer. | App-only surfaces in the layout (a second layout system); syncing UI state between devices. |
| D66 | Control is per session across windows. When two windows show the same session, the window where the user last typed or clicked in a terminal holds that session's `control` streams; the other opens `observe`, dims its cards a little and shows "Controlled in another window · Take Back". Take Back, or a key press or click in a terminal card there, moves control to that window. Windows on different sessions each control their own. ([Control between windows](/docs/talking-to-herdr#control-between-windows)) | One controller and one PTY size per pane, as in D8. Per session, so one window never mixes controlled and watched cards of one session. | Control per pane between windows; both windows asking for control (they fight over the PTY size); one main window. |

## Machines

| # | Decision | Why | Rejected |
|---|---|---|---|
| D15 | macOS SSH = system `ssh`, one ControlMaster per host started on purpose, forwarding off, a bundled askpass script. ([macOS](/docs/machines#macos)) | The user's setup works; one prompt per host; no path back to the Mac. | `ControlMaster=auto`; a Swift SSH library on macOS. |
| D17 | iOS uses Citadel with a Secure Enclave key; machines in `UserDefaults`; the Mac via Remote Login. ([iOS](/docs/machines#ios)) | Pure Swift; the key cannot leave the device; no new mechanism. Spike S7 tests the exec channels first. | libssh2 + OpenSSL; a relay. |
| D43 | A machine is a host: This Mac now, SSH hosts later, each with its own icon. A window starts with one sidebar page, the machine's `default` session (started if stopped), and the user opens more sessions as pages with Open Session (D68); only open pages have a `HostStore`, snapshot reads and an event stream. Each page keeps the window's own selection in that session (workspace, tab, keyboard card, zoom). Detach Session removes a page from the window and leaves the session running (the UI says "session", never "page"); the last page cannot close. Sessions on one host share one SSH connection. The app counts no channels: when the server refuses one, it closes the least recently shown kept stream and tries once more. ([What a machine is](/docs/machines#what-a-machine-is), [SSH sessions](/docs/machines#ssh-sessions)) | Users think of a computer, not of a herdr server; a page per session keeps herdr's own unit one swipe away. A machine with many sessions costs nothing until the user opens them. One connection per host keeps one prompt. The server's refusal is the only true count. | One machine per herdr session, with its own entry in the machine list and its own page ("This Mac · ‹session›"); every running session loaded as a page by itself; one connection per session; a channel budget with reservations, priorities and a learned limit. |
| D47 | On This Mac the app starts a session's server as a one-shot launchd job in the user's GUI domain, with the CLI's `PATH`, `HOME`, `SSH_AUTH_SOCK` and `XDG_*` variables. A remote server starts with `nohup` over SSH. ([Checks on connect](/docs/machines#checks-on-connect)) | launchd is the server's parent and responsible process, so macOS privacy prompts never name Oriel; the server has its own process group and outlives the app; server and CLI agree on paths. | Never starting the local server; `launchctl submit` (launchd restarted the server after `herdr session stop`); `nohup` or a double fork from the app (the app stays the responsible process); a Terminal window running herdr. |
| D54 | The app keeps its own machine list on macOS and iOS; herdr on the Mac is needed only for This Mac's sessions. On macOS the Add Remote Host sheet offers herdr's machines, checked while the list is empty. ([The machine list](/docs/machines#the-machine-list), [Add a machine](/docs/ui/add-a-machine)) | One code path on both platforms; remote machines work on a Mac without herdr; the askpass dialog answers ssh's questions. | herdr's machine list as the only list on macOS, with `herdr machine add` in a terminal card; an import at first launch; a second list kept in sync both ways. |
| D67 | A workspace row shows git state like herdr's Spaces panel: the branch and ahead and behind counts, no changed-file count. The app runs `git --no-optional-locks -C <root> status --porcelain=v2 --branch --untracked-files=no` on the machine through `Exec.run` (root = `worktree.checkout_path`, else the cwd of the workspace's first pane), for a workspace that is new or whose root changed and every 10 s, one run per workspace, only for the page in view of a visible window. When git is only the `/usr/bin/git` stub without developer tools, the app runs none. A linked git worktree sits indented under its repository's workspace. ([Sidebar](/docs/ui/window#sidebar), [Git status](/docs/talking-to-herdr#git-status)) | herdr's snapshot has no branch. One porcelain run gives the branch and the counts in a stable format; skipping untracked files keeps it fast in a big repository. Runs only for rows that show. The stub would open the "install developer tools" dialog. | A changed-file count; polling every page; a `git` library in the app. |
| D68 | The Open Session panel is the one place to create, start or open a session as a page of the window: a field ("Name a new session, or find one") over a list of New, Running (not open in this window), Stopped, and the sessions already open. Enter or a click on a row takes one path for a new, a running and a stopped session: start the server if it is not running (D47), then open its page last in the window. On an open session it switches to its page. A running session's row has Stop, a stopped one's Delete; both ask first. The footer button, the workspace menu and File ▸ Open Session… (⌥⌘T) open it. ([Open Session](/docs/ui/window#open-session)) | One place and one name for every way to get a session onto a page. | A session picker in the title row; separate New Session and Change Session commands. |

## Layout and terminals

| # | Decision | Why | Rejected |
|---|---|---|---|
| D9 | libghostty-spm draws terminals, as a pinned build with uHerdr's response-suppression patch. ([Dependencies](/docs/platform#dependencies)) | Best quality on both platforms. The patch stops a second answer to terminal queries that herdr already answered. | SwiftTerm as the main renderer (kept as a fallback); xterm.js in a web view. |
| D10 | Layout = herdr's split tree rebuilt from the flat snapshot; resize = `layout.set_split_ratio`. ([Layout and sizing](/docs/layout)) | Ratios live in herdr; no extra calls. | App-owned sizes; `layout.export` per tab. |
| D11 | Zoom is the app's own: the zoomed card fills its tab's page, drawn by the split tree. ([Zoom is the app's own](/docs/layout#zoom-is-the-apps-own)) | `pane.zoom` moves herdr's focus, marks the tab seen and blocks moves. In the split tree, no terminal view changes host and no other PTY resizes. | `pane.zoom`; a separate layer (its terminal view did not come back on restore). |
| D12 | One tab = one page in the strip. ([Swiping](/docs/ui/swiping)) | Matches herdr and Cube. | Panes wider than the window in one long scroller. |
| D13 | The app never calls herdr's focus methods; selection and "seen" are the app's own, per device. ([Selection and "seen"](/docs/layout#selection-and-seen-are-the-apps-own)) | Each focus call moves every attached herdr TUI. | Focusing on click or swipe. |
| D14 | "Finished, not seen" = `completion_seq` not null and different from the seen value; the first sighting counts as seen. Looking at a pane (its tab selected on the page in view of the key window) records it seen. Seen values live in memory in the session's store, shared by its windows. ([Selection and "seen"](/docs/layout#selection-and-seen-are-the-apps-own)) | herdr skips `done` when a TUI watches the tab; the counter restarts with herdr. | Waiting for `done`; a "greater than" test. |
| D41 | Closing a pane asks first unless the pane runs only its shell; web and plugin panes close at once. Closing tabs or a workspace asks only when a pane of them runs a program besides its shell. The dialog names what runs. ([Writes](/docs/talking-to-herdr#writes-are-herdr-calls)) | A close kills processes on every device and cannot be undone; a pane with only its shell loses nothing (user, phase 25). | Asking only when an agent works; always asking for tabs and workspaces; never asking. |
| D42 | Tabs act like Rex's: 220 pt each on a capsule track that scrolls when they do not fit (phase 24), 1 pt dividers, one selection capsule that slides with Rex's spring, and × on the hovered tab only. A working agent shows three dots that animate at 15 fps or less, in step on every tab and still under Reduce Motion, on every tab with a working agent, the selected one too (phase 25; Rex hides them there); needs you (amber) and finished (green) are 7 pt badges on the front program icon. Dividers have a 16 pt hit area and a 36 × 3 pt grip in the muted secondary color on hover and drag; a double-click sets 0.5, ⌥⌘= balances the tab, and every split made in the app evens out its row. ([Main window](/docs/ui/window#tab-bar), [Layout](/docs/layout#dividers)) | Rex is the reference look, now measured from Rex itself; dots show work without a word, and a slow clock-driven animation costs little. gorex stays the readable source for the slot and divider behavior. | A static ◔ glyph in one status slot (× > ▲ > ✓ > ◔); several glyphs per tab; an animation per tab with its own phase. |
| D56 | Image paste into a terminal, agent or chat reply box: write the PNG to a new temporary folder on the pane's machine with `run`, then paste its path. ([Image paste](/docs/plugins/terminal-and-agent#image-paste)) | Works the same on This Mac and over SSH; agents already accept a pasted image path; what uHerdr, collie, termote and roamgate do. | Image bytes through the terminal (herdr's stream and agents do not take them); a server helper; a folder of our own with its own cleanup. |
| D64 | No card fades: every card is drawn at full strength, in key windows and the others. Only the keyboard card's fill and stroke set it apart, and in Glass only a little. A watching window's 0.85 dim (D66) stays. No setting. ([Layout](/docs/layout#the-keyboard-card)) | The user found the faded cards and Glass's darker card fill too far apart from the keyboard card (phase 25) and asked to remove the fade and its setting. | Rex's content fade (0.7 for other cards, 0.5 and 0.8 in a window that is not key) with View ▸ Fade Inactive Panes to turn it off (phases 17–24); a black overlay over unfocused cards. |
| D69 | Drag and drop offers only what herdr allows, and builds the rest from herdr calls: a swap only inside one tab; a move into another tab beside a card; a drop on an edge of a card in the same tab is a move to a new tab, a move back beside the target and, for left or top, a swap. Tabs reorder only inside their workspace. Workspaces reorder with `workspace.move_block` (a workspace with its linked worktrees). A pane moved into a tab gets an equal share of its run of splits, as after a split. Nothing moves between sessions or machines. ([Drag and drop](/docs/ui/drag-and-drop)) | herdr 0.9.5 refuses a swap across tabs (`cross_tab`) and a move into the pane's own tab (`same_tab`), splits only right or down, and moves tabs only inside a workspace. Every step stays a herdr call (D1). | Only swap inside one tab; tabs dropped on another workspace; drops between sessions. |

## Chat and status

| # | Decision | Why | Rejected |
|---|---|---|---|
| D29 | Chat = the agent's transcript tailed on the machine + `agent.prompt`; parsers for pi, Claude Code and Codex; a screen-text chat for every other agent or terminal pane. ([Chat view](/docs/chat-view)) | What every working chat view does; any agent or terminal pane can switch. | Per-agent prompt parsers; parsing the screen into fake messages. |
| D30 | The blocked panel sends a key only if the agent is still blocked and the prompt text is unchanged. ([Sending and answering](/docs/chat-view#sending-and-answering)) | The prompt may have changed on another device. | Sending without a check. |
| D31 | Notifications are made by the app from snapshot changes, for every open page, never for the pane the user is looking at, with no sound; `.passive` while the pill shows; no iOS push in v1. ([Notifications](/docs/status#notifications)) | herdr sends its own only to TUI clients; no double alerts; push needs a relay ([Future work](/docs/future-work)). | herdr's private notifications; dropping banners. |
| D32 | Floating pills: one non-activating `NSPanel`, one pill with a glyph per agent, a pill card that is the compact chat view, peeks that never take the keyboard, opaque. ([Floating pills](/docs/ui/pills)) | One proved the shape; never steal a keystroke; glass renders flat in an inactive app. | A pill per agent; a SwiftUI window; glass pills. |
| D50 | A pane floats in a window of its own, made by Oriel: herdr keeps the pane where it is in its tab, and the window shows its terminal. The window belongs to the main window that floated the pane (its page, its streams), is saved and restored with it, and closes when herdr closes the pane. The pane's card stays in the tab as a placeholder. ([Floating pane](/docs/ui/window#floating-pane)) | The user asked for it (phase 25). herdr 0.9.5 has no floating pane: its popup is not a pane and the API never shows it. Keeping the pane in its tab costs no herdr call, keeps its place in the splits, and leaves every other client unchanged. One window per pane moves and resizes like any Mac window. | A floating card inside the main window; moving the pane into a tab labeled `oriel:float`; SwiftUI restoring the windows on its own (they came back before their page). |
| D55 | Agent status comes only from the multiplexer's API; under herdr the app never parses OSC 7501. ([Status](/docs/status#agents-and-notifications)) | herdr's terminal stream is a redrawn screen, so the sequence never reaches the app; one source keeps every device in agreement. | Parsing OSC 7501 in the app's libghostty surfaces under herdr. |
| D61 | The Agents button (a list of statuses, ⌘.) replaces Activity. Resting the pointer on it for 0.25 s shows a glass panel of the agents of the page in view that need you; a click on one goes to its pane. The panel is drawn in the window. A click on the button, ⌘. or View ▸ Show Agents turns the sidebar page into the Agents view: the agents of that session only, one row per agent pane, sorted by priority or by workspace order, idle agents shown. A click on a row goes to the pane, which records it seen (D14). ([Agents](/docs/status#agents)) | Who needs you is one hover away; the full list takes no room until asked for; one session per page matches the sidebar; an in-window panel leaves the keyboard with the terminal. | An `NSPopover` (its window takes the keyboard from the terminal); the Activity filter on the tab list (the eye button) and its "Show idle agents" toggle; a fixed status area at the bottom of the sidebar; a summary row with counts; one list across all sessions; outline chat bubbles as its icon (until phase 22: they did not fit). |

## Look and platform

| # | Decision | Why | Rejected |
|---|---|---|---|
| D44 | Appearance is Auto, Light or Dark (Dark by default), and the interface style is Glass (a behind-window blur) or Classic (an opaque window); one small token table per style and appearance holds every color, measured against Rex's screenshots (phase 22). Pane cards never get glass; terminals use one light and one dark palette that follow the appearance. ([Theme and accessibility](/docs/ui/theme-and-accessibility#appearance-and-interface-style)) | Rex's two styles cover both tastes: the desktop showing through softly, or a plain window. A fixed token table keeps the look small and checkable. | Dark only; glass on the cards; a glass sidebar panel; Rex's 41 themes, a theme editor, theme import and "Tint with theme"; a compact density. |
| D45 | One title row, always the same: traffic lights, the sidebar toggle (always shown; its icon shows open or closed, with no highlight), the machine button (the machine's icon only), the workspace button while the sidebar is collapsed ("‹session› \| ‹workspace›", with a menu of every workspace grouped by session), the selected workspace's tab bar, then the Agents button, ⌘ and + on the right; 46 pt tall with the traffic lights at Rex's place. The tab bar is always in the title row; the sidebar lists workspaces, never tabs. ([Main window](/docs/ui/window#title-row)) | Tabs stay in one place whether the sidebar is open or not; the sidebar lists workspaces as herdr does; an icon is enough for a machine the user rarely changes. | Tabs as sidebar rows while the sidebar is shown, and the tab bar only while it is hidden; a session picker in the title row (sessions are sidebar pages); the machine's name on the button; a tab placement setting (Rex); agent rows in the v0 sidebar. |
| D48 | ⌘K (and the title-bar ⌘ button) opens the command palette; ⇧⌘P also opens it (Rex's key). It lists every command with its shortcut, tabs, workspaces and the sessions open as pages, fuzzy-matched as you type. Choices and names open sub-pages, and each setting is a command that says what it does ("Turn On Focus Follows Mouse"). ([Main window](/docs/ui/window#command-palette)) | ⌘K is the palette key in Slack, Linear and VS Code's quick open; ⇧⌘P is Rex's. herdr owns the screen, so Terminal's ⌘K (clear) has nothing to clear. One command list feeds the palette and the menu bar, so a title or shortcut is written once. | ⌘P; a palette that only jumps; ⌘K for Change Session as in Rex. |
| D34 | One multiplatform target, macOS 26 and iOS 26. On macOS the user can open several windows (File ▸ New Window, ⌘N). Each window shows one machine and keeps its own selection; windows on one session share its `HostStore`. ([One codebase](/docs/platform#one-codebase)) | Liquid Glass with no fallbacks. Two sessions or two machines side by side; per-session control (D66) keeps one controller per pane. | Separate apps; back-deploying; one main window. |
| D35 | Horizontal gestures belong to the strip (over the sidebar, to the sidebar's pages); the PaneViewRegistry owns every view. ([Making the strip work](/docs/platform#making-the-strip-work)) | Terminals and web views would eat the swipe; SwiftUI would destroy views. | Each view handling its own scroll. |
| D36 | iPhone shows one pane per page and opens agents in chat. ([iPhone and iPad](/docs/ui/iphone-and-ipad)) | Splits do not fit; chat needs no PTY. | Shrinking splits onto a phone. |
| D60 | Program icons come from our own catalog of open-license SVGs (`resources/icons/`). A pane's icon is matched in this order: herdr's agent, the foreground process, the terminal title, then the shell; the app asks herdr for the process once for every pane when it first appears in a snapshot, when it shows in a card, 1 s after Return in its card and when its title or agent changes, never on a timer. ([Program icons](/docs/ui/program-icons)) | A tab shows what runs in it at a glance, as in Rex. Asking only on these events costs one call each and catches almost every program change. | Rex's icon art; one `>_` tile for every pane; polling `pane.process_info`. |
| D62 | No Settings window yet: the few settings live in the menu bar (View ▸ Appearance, Interface Style, Increase, Decrease and Reset Font Size, and the pane toggles), each one key in app storage per device; everything else uses the defaults on the Settings page. A Settings window comes after its mock-ups, once phases 10–21 are done. ([Settings](/docs/ui/settings)) | The user dropped the first window (a stock tabbed form looked old-school) and wants it designed with mock-ups first; the menu bar covers what users switch often. | A stock `Settings` scene with grouped forms (built in phase 11, then removed); Rex's long settings list; custom shortcuts; settings synced between devices or kept in herdr. |
| D63 | Resting the pointer 0.25 s on a title-bar tab or an Agents row shows the hover card: the tab title and one row per pane (its split minimap went in phase 22, its live tab preview in phase 27: the overview shows live tabs); a click on a row goes to that pane. For a pane that needs you it shows the last 3 lines of its screen, read with `pane.read` when the card opens, because herdr 0.9.5 sends no blocked message. ([Hover card](/docs/ui/window#hover-card)) | See what runs in a tab, and why an agent waits, without leaving the current tab. One read per blocked pane, only on demand. | Live tab thumbnails ([Future work](/docs/future-work)); Rex's blocked message (herdr has none); reading screens before the card opens. |
| D65 | When a tab's herdr label is herdr's default (a bare number), the app shows the keyboard card's program and its folder's name as the tab title ("zsh ~", "pi oriel"). The app never writes that title to herdr. ([Main window](/docs/ui/window#tab-bar)) | A number says nothing; the program and folder do, as in Rex. Writing it would rename the tab for every device and herdr TUI. | Showing the bare number; renaming the tab in herdr by itself. |

## Pane kinds and plugins

| # | Decision | Why | Rejected |
|---|---|---|---|
| D18 | One picker for every pane kind: Terminal, Agent and Web page are fixed rows; every other kind is a plugin from one registry. ([Pane kinds and plugins](/docs/plugins)) | The three built-in kinds are special everywhere else (streams, chat, labels); one model for the rest. | Native manifests for the built-in kinds (a `native` field, reserved ids); herdr TUI plugins in the picker. |
| D20 | Plugins live in the app, installed from a git URL or a linked folder, already built; the app never runs npm. ([Packages](/docs/plugins/packages)) | One install per device for every machine; no setup on any machine; a simple dev loop. | herdr plugins on each machine; an in-app store. |
| D21 | A web or plugin pane is a herdr pane labeled `oriel:<plugin>[/<pane>]#<iid> <arg>`; the iid names its state file. ([Labels and instance ids](/docs/plugins/labels)) | The label is durable and readable, and survives moves and cold restarts. | Metadata tokens; an app-side pane list. |
| D22 | Bigger plugin state lives in a JSON file on the pane's machine, named by iid; preferences stay per device. The device that closes the pane removes the file; on connect, files older than 30 days go. ([State and restore](/docs/plugins/state)) | Shared by every device, survives reinstalls, no sync service; cleanup needs no snapshot. | Labels for everything; app storage; a daily cleanup checked against current labels. |
| D24 | Plugin API = `run` and `dial` on the card's machine, pane context, `setArg`, instance state, read-only preferences and a signal after each snapshot read, with no data.
