A call goes from the views to `HostStore` (one per open session), to
`HerdrClient` (the `Multiplexer`), to the machine's `Exec`: `ProcessExec` on
This Mac, `SSHExec` and the relay on a remote machine. There it runs herdr's
API bridge, a `terminal session` per streamed pane, and the event stream.

## Pieces

| Piece | Job |
|---|---|
| `HerdrKit` (Swift package) | `Exec`, the `Multiplexer` interface and its herdr implementation: `call()`, the event stream, snapshot decoding, the split-tree rebuild, the remote command envelope and the relay; `Files` and `Git`, the plugin cards' file and git data over `Exec`; `PluginManifest`, `PluginCalls` (the plugin API's calls on a machine) and `PluginPackages` (plugin sources and installs) |
| `ProcessExec` | `Process` with pipes, for This Mac |
| `SSHExec` | a remote machine: its ControlMaster, the askpass prompts and the relay that carries every run |
| `HostStore` | the app's live model of one open session: snapshot, events, streams, seen state, git state, and which window controls it. One per session, shared by every window that shows it |
| Window state | one per window: its machine, its open pages and its selection (page, workspace, tab, keyboard card, zoom, sidebar view and width), restored with `@SceneStorage` |
| `PaneViewRegistry` | owns terminal, browser and plugin views by terminal id, so scrolling never destroys them |
| Plugin cards | `Registry` (the browser's manifest and every package's), `Plugin` and its `WebCard` (one web view and the `oriel-plugin://` scheme), `Bridge` (the plugin API, one per card), `Header`, and the installs, builds, defaults and trust; the API's runtime and types in `web/oriel/`, the default plugins and the template in `plugins/` ([Plugins](/docs/plugins)) |
| Views | title row, sidebar pages, Agents view, tab bar, strip, cards, overview, floating panes, panels and dialogs |

`Exec` and `Multiplexer` are the only protocols. `HerdrKit` is a separate
package, so its single test target runs with `swift test`.

## The Multiplexer interface

`Multiplexer` is the Swift
protocol that every multiplexer implements (D49). herdr is the first and only
implementation. Rex ([superlogical.com](https://www.superlogical.com)) and tmux
are candidates ([Future work](/docs/future-work)). The views use only this
interface and the app's own model types, never herdr's JSON or argv.

| Part | What it gives the app | herdr implementation |
|---|---|---|
| Machine connection | one session on one machine, through that machine's `Exec` | [herdr on each machine](/docs/talking-to-herdr#herdr-on-each-machine), [Checks on connect](/docs/machines#checks-on-connect), [Health check](/docs/machines#health-check) |
| Snapshot | every workspace, tab, pane, label and split tree, in the app's model types | `session.snapshot`, [Reconcile](/docs/talking-to-herdr#reconcile), [Layout](/docs/layout) |
| Events | "the state changed, read the snapshot again" | `events.subscribe`, [Events](/docs/talking-to-herdr#events) |
| Terminal streams | one pane's screen as ANSI frames; keys, resize, scroll and mouse back; control or watch | `terminal session control/observe`, [Terminal plane](/docs/talking-to-herdr#terminal-plane) |
| Actions | create, split, move, swap, close, rename, resize; read a pane's text | [Writes are herdr calls](/docs/talking-to-herdr#writes-are-herdr-calls) |
| Agent status | per agent pane: working, needs you, idle, and a finish counter | `agent_status`, `completion_seq`, [Status](/docs/status) |

Agent status comes only from the interface, never from escape sequences in
the app's terminal surfaces (D55, [Status](/docs/status#agents-and-notifications)).

`Multiplexer` lives in `HerdrKit/Multiplexer.swift` next to `HerdrClient`,
its only conformer, and has only the methods the app uses. The machine
connection is not a method: `HostStore` makes the `HerdrClient` (the one place
that names herdr) with the path from the machine's `Exec.herdr()`
([herdr on each machine](/docs/talking-to-herdr#herdr-on-each-machine)). The
model types (`Snapshot`, `Session`, `HerdrError`, ...) stay in `HerdrKit` until
a second multiplexer needs its own.

Simpler choice: the interface has the shape of herdr's features. A second
implementation reshapes it where that multiplexer differs.
