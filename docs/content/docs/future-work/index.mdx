The pages in this section keep the designs for parts that are not built yet,
so the work starts from them when it is picked up. Each page says at the top
what of it is built. Smaller deferrals are marked "Simpler choice" on their
own pages.

The designs follow the rules of the app as it is built: herdr is the source of
truth, the app reaches each machine through `run` (over the relay on a remote
machine)
([Running commands](/docs/talking-to-herdr#running-commands)), and the app
never calls herdr's focus methods. A design gets decision numbers on the
[Decisions](/docs/decisions) page when it is built.

## Smaller items

- **A Settings window** (⌘,), designed with mock-ups first. It holds the
  settings that have no menu item today: the terminal font, the cursor style
  and blink, Option as Alt, copy on select, and the notification switches
  ([Settings](/docs/ui/settings)). It must meet the design bar; a stock tabbed
  form is too plain (D62).
- **herdr's machines in Add Remote Host.** When herdr is on the Mac, the
  dialog lists the targets of the enabled entries of
  `herdr machine list --json` (`{id, label, target, session, enabled}`) that
  are not in the app's list, each with a checkbox. While the app's list is
  empty, they start checked. The app never writes herdr's list
  ([The machine list](/docs/machines#the-machine-list)).
- **Reorder the machines** in the machine menu.
- **Bundling herdr** with the app, so a Mac without herdr can still show its
  own sessions.
- **A notarized Developer ID download** outside the App Store (signed ad hoc
  now: [Platform](/docs/platform)).
- **Local Network privacy** (macOS 15 and later). An `ssh` that the app starts
  counts as the app, so a target on the local network fails with "No route to
  host" today. The plan: the app declares `NSLocalNetworkUsageDescription`,
  resolves the target with `ssh -G`, and opens an `NWConnection` to a local
  address before the first SSH connection, so the system asks once. If the
  user says no, the page shows "Allow Local Network access for Oriel in System
  Settings › Privacy & Security". Tailscale addresses are not affected.
- **VoiceOver reads the terminal.** A terminal card gives VoiceOver its screen
  text, read with `pane.read {source:"visible", format:"text"}` when
  VoiceOver asks for it, and announces new output politely (it does not
  interrupt speech). Today the card gives only its grid size.
- **tmux** as one more implementation of the
  [`Multiplexer` interface](/docs/architecture#the-multiplexer-interface),
  after Rex. Research:
  [`tmux.md`](https://github.com/hkandala/oriel/blob/main/resources/research/multiplexers/tmux.md).
- **A swipe preview** for a card never shown, from
  `pane.read {source:"visible"}`, instead of an empty card.
- **Jump to the next agent that needs you** with one key, in the Agents
  view's priority order. It selects workspace, tab and card in the app and
  never calls herdr's focus methods.
- **Faster git state:** stat `HEAD`, `index` and the branch ref each second,
  and run `git status` only on a change or an agent status change
  ([Git status](/docs/talking-to-herdr#git-status)). On a remote machine each
  stat is a round trip, so batch them in one `stat` run, or keep today's poll
  there.
- **The rest of the browser pane** ([Browser](/docs/ui/browser)):
  - Find in the page: ⌘F, with `WKWebView`'s find in the same find bar.
  - ⌥-click on a terminal link opens it in a browser pane beside the card.
  - "Open in Browser" as the palette's top row when the query is an address.
  - The Web Inspector button lit (the accent on an accent circle at 0.07, as
    Zoom's Restore) while the inspector shows.
  - An "Open :‹port›" chip on a terminal card whose screen shows a
    `localhost` address.
  - **Refresh**, and the approvals and the safe list in the Settings window,
    where the user can edit them.
  - "‹machine› does not allow port forwarding": an `ssh -W` probe after a
    refusal tells it from a closed port.
- **The rest of the chat view** ([Chat view](/docs/ui/chat-view)):
  - A host for the pill card: the chat at 360 pt at the Replies level, built
    when the [floating pills](/docs/future-work/pills) land.
  - Subagent rows: Claude Code's and Codex's subagents, OpenCode's child
    sessions.
  - OpenCode 2.x, with its shared service and `/api/*` routes.
  - A Codex fork with its parent's lines up to the fork
    (`forked_from_ordinal_exclusive`). Today it shows only its own lines.
- **Agents use a browser card.** Today an agent can open a browser pane and
  change its address, nothing more. An agent that needs to drive a page runs
  its own browser on its machine (Playwright, chrome-devtools-mcp).
  WKWebView has no automation protocol. A later design lets an agent ask the
  app, through a pane metadata token, to read, run script in or capture one
  browser card it is allowed to, with the result written back to a file on
  the machine. It needs its own consent design.
- **Terminal keys to check against libghostty** (herdr-gpui's defaults,
  [research](https://github.com/hkandala/oriel/blob/main/resources/research/clients/herdr-gpui.md)):
  ⇧↩ sent as Esc and CR, because herdr sends a bare CR for Shift-Enter to a
  program without kitty keys, which submits an agent's prompt. Option as Alt
  "auto": the left Option key is Alt on US and ABC layouts, and the right one
  types accents. First check what the app sends today.
- **Back and Forward through the panes** the keyboard visited, and ⇧⌘T to
  reopen the last closed tab (a new tab in its folder: its programs ended
  with it). Back and Forward need their own keys: ⌘[ and ⌘] step panes here.
- **herdr plugin values.** herdr's TUI shows what herdr plugins report:
  `agents[].tokens`, `state_labels` and `tab_bar_right`. The app shows them
  too, read only, where herdr's TUI does. It never writes herdr's shared
  `config.toml`.
- **A remote home shown as `~`** in card headers, and Go to Directory on a
  remote machine.
- **A bigger server helper.** The relay already carries every run of a remote
  machine on one SSH session
  ([The SSH connection](/docs/machines#the-ssh-connection)). A helper of our
  own with more to do (a file watcher, a port forwarder) would sit behind the
  same `run` and `dial` calls. Build it only when one of these is real:
  1. **Latency:** a plugin needs many small calls (a file tree, search), and
     users on slow links feel it.
  2. **File watching:** a plugin needs pushed file changes, not reads again
     on each snapshot.
  3. **`AllowTcpForwarding no`:** a server refuses the port forwards that
     [browser panes](/docs/ui/browser#remote-localhost) and `dial` use.
  4. **Windows servers:** herdr supports them; the `sh` envelope does not.

  Plugins, labels and state files stay the same when it comes. Research:
  [`plugins.md`](https://github.com/hkandala/oriel/blob/main/resources/research/plugins/plugins.md#how-plugins-reach-a-remote-machine).

## Waiting on herdr

- **herdr's popup in a floating window.** On herdr 0.9.5, `plugin.pane.open`
  with `placement: "popup"` answers only `ok`. The popup's terminal runs in
  the server, but it has no pane or terminal id in the reply, the snapshot or
  `pane.list`, and opening or closing it (`popup.close`) sends no event. The
  `plugin_pane_opened` reply comes only for the other placements, which are
  normal panes. The ask: the popup (its terminal id and size) in
  `session.snapshot`, events when it opens and closes, and a close by id
  (`popup.close` takes no parameters). Oriel then streams it by that id in a
  [floating window](/docs/ui/window#floating-pane), as it does a floated pane.
- **Panes started with a command after a cold restart** come back as plain
  shells, with their label. The ask: restore them with their `launch_argv`,
  opt-in ([discussion #1367](https://github.com/herdrdev/herdr/discussions/1367)).
  Web and plugin panes work anyway, because the label is the truth
  ([Labels and instance ids](/docs/future-work/plugins/labels)).
- **Clipboard writes on the terminal stream.** herdr 0.9.5 gives a pane's
  OSC 52 write (`ServerMessage::Clipboard`) only to its foreground TUI
  client, and `terminal session control` prints only frames and the close.
  The ask: a `terminal.clipboard` event on the control stream, sent to the
  client that streams the pane. Then the app puts it on the clipboard, and
  every program's copy works from a remote machine, as pi-hkandala's
  [copy requests](/docs/talking-to-herdr#copy-requests) do today
  ([Scrolling, queries and links](/docs/talking-to-herdr#scrolling-queries-and-links)).
- **Named keys on the terminal stream.** The ask: herdr accepts named keys on
  `terminal.input` (`{"type":"terminal.input","keys":["up"]}`), encoded as
  `pane.send_keys` does. Then all input takes one path, with no bridge call
  per key burst, which matters over SSH
  ([Terminal plane](/docs/talking-to-herdr#terminal-plane)).
- **Claude Code's transcript path.** herdr's Claude hook sends
  `transcript_path`, but herdr 0.9.5 keeps a path in `agent_session` only for
  pi and omp. The ask: keep it for Claude Code. Then the
  [chat view](/docs/ui/chat-view) could take the path from herdr
  instead of its own SessionStart hook.
- **Blocked for menus, and forks.** herdr 0.9.5 reports `idle` while an
  agent shows a picker (Claude Code, Codex and opencode model and session
  pickers) or a pi extension dialog, and keeps the old `agent_session` after
  Claude Code's `/branch` and Codex's `/fork`. The ask: `blocked` for those,
  and the new session after a fork. Then the
  [chat view](/docs/ui/chat-view#codexs-screen-check) needs no
  screen check for Codex before a send.
- **OSC 7501**, the Program Status Protocol: a terminal escape sequence that a
  program sends to report its status
  ([spec](https://www.superlogical.com/rex/docs/build/program-status)). herdr
  does not support it yet. Draft PR
  [#5172](https://github.com/herdrdev/herdr/pull/5172) adds `program_status`
  to `pane.get` and `pane.list`, and a change to it alone sends no event. Once
  herdr ships it, the app shows its `message` on needs-you and finished rows
  and in notifications, and says "failed" for `error`. Another multiplexer may
  report it through its own API ([Rex](/docs/future-work/rex-backend#agent-status)).

## Left out on purpose

- Tearing a tab off into a new window: a tab belongs to its herdr workspace,
  and a window shows pages, not single tabs.
- Key sequences and custom shortcuts: macOS menus hold the shortcuts.
- Traffic lights inside the tab bar: needs private API
  (`setCustomTitlebarHeight:`).
- Jump to prompt: needs OSC 133 marks, and herdr's frames carry none.
- A font size per pane (one text size for the app), paste confirmation
  (small; on request), an installer for agent integrations (herdr's own
  installer writes the agents' config files; it belongs with the Settings
  window).
- Many themes and a theme editor: the user wants only light, dark, Glass and
  Classic. A compact density: the user dropped it.
- A menu bar status item: the floating pills would cover it.
- Sparkle updates and a diagnostics window: not interface work.
- Decorations with a GPU cost (Rex's melt transition, selection pulse).
- Rex's theme, material or decompiled files in the repo: Oriel copies looks
  by measuring, never Rex's files or icon art.
