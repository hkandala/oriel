description: "Proposed: manifest.json says who a plugin is, what it opens, how it shows, its header row and what it can do"

Proposed ([Pane kinds and plugins](/docs/future-work/plugins)). Every plugin
folder has a `manifest.json`. The app reads it before any of the plugin's
code runs. So the chooser, ⌘K, Open With, the card's header row and the
placeholder in herdr's TUI show at once, and the page only fills them in.

## An example

```json
{
  "id": "csv-table",
  "name": "CSV Table",
  "version": "0.1.0",
  "api": 1,
  "main": "main.ts",
  "icon": "tablecells",
  "description": "A CSV or TSV file as a table you can sort.",
  "opens": { "files": ["*.csv", "*.tsv", "public.comma-separated-values-text"] },
  "header": [
    { "id": "rows", "type": "text", "style": "dim" },
    { "type": "spacer" },
    { "id": "first-row", "type": "toggle", "symbol": "tablecells.badge.ellipsis",
      "title": "First Row Is Header", "value": true },
    { "id": "reload", "type": "button", "symbol": "arrow.clockwise", "title": "Reload" }
  ],
  "permissions": ["files:read"]
}
```

## Fields

| Field | Required | Value |
|---|---|---|
| `id` | yes | `^[a-z0-9][a-z0-9-]{0,63}$`. The label's plugin id (`oriel:<id>#…`). Unique: a user plugin with the id of a plugin inside the app does not load, and its cards show why. |
| `name` | yes | What the user reads: the tab's first part ("CSV Table data.csv"), the placeholder's title, Open With, ⌘K. |
| `version` | yes | The plugin's own version, shown in the trust prompt and the log. |
| `api` | yes | The API version the plugin is written for, an integer ([Versions](/docs/future-work/plugins/api#versions)). |
| `main` | yes | The entry file, relative to the folder. `.ts`, `.tsx`, `.js` or `.jsx`. |
| `icon` | yes | An SF Symbol name: the card's, the tab's and the chooser's icon, on the neutral tile. |
| `description` | no | One line, shown in the trust prompt. |
| `opens` | no | What the card shows, and so what its label's argument is ([What a plugin opens](#what-a-plugin-opens)). No `opens`: the argument is empty and the card uses the pane's folder. |
| `chooser` | no | A row title for the [New pane](/docs/ui/new-pane) chooser and the command "Open ‹title› Here" ([How it shows](#how-it-shows)). |
| `header` | no | The controls of the card's second header row ([Header](#header)). No `header`: the card has one header row. |
| `commands` | no | Menu bar and ⌘K commands of the card, with keys ([Commands](#commands)). |
| `handles` | no | The app's own commands that the card takes: `save` (⌘S), `find` (⌘F, ⌘G, ⇧⌘G). |
| `permissions` | no | What the page can ask the app to do ([Permissions](#permissions)). No `permissions`: the page can only draw, keep state and open other cards. |

The app reads the manifest leniently. An unknown field is ignored, so a
manifest written for a newer app still loads. A missing required field or a
wrong value shows in the card, with the field's name
([Errors in the card](/docs/future-work/plugins/building#errors-in-the-card)).

## What a plugin opens

`opens` has one of these keys, and `priority`. The key sets what the label's
argument holds, and the card's title.

| Key | The argument | The title | Example |
|---|---|---|---|
| `files` | a file's absolute path | the file's name | `{ "files": ["*.csv", "public.comma-separated-values-text"] }` |
| `folders` | a folder: the root of its git repository, else the folder | the folder's name | `{ "folders": true }` |
| `git` | a repository's root, then `uncommitted` or a commit hash | `Changes`, or the short hash | `{ "git": true }` |
| `urls` | a URL | its host | `{ "urls": ["https://github.com/*/*/pull/*"] }` |

`files` is a list of patterns. Each is a name glob (`*.csv`, `Makefile`) or
a uniform type identifier (`public.image`). A type matches its subtypes, as
`UTType.conforms(to:)` says. A name the system does not know (a dynamic
type, such as `.rs`) matches no type, only a glob or `*`.

`priority` sits next to the key: `"default"` (the default) or `"option"`.
An option plugin opens a file only when the user picks it in Open With.

### Which plugin opens a file

A link in a card, a double-click in Files and the agent's open
([Agent control](/docs/future-work/agent-control)) open a file with its
default plugin. The app picks it by the file's name alone, so a remote file
is not read first:
1. Only `default` plugins whose patterns match take part.
2. The most specific pattern wins: an exact name (`Makefile`), then an
   extension glob (`*.md`), then a type, a subtype before its supertype
   (`public.text` before `public.data`), then `*`.
3. On a tie, a user plugin wins over a plugin inside the app. Then the
   lower id in alphabetical order wins.

The default plugins declare today's rule
([Ways in](/docs/ui/plugins#ways-in)) as patterns:

| Plugin | `files` |
|---|---|
| Markdown | `*.md`, `*.markdown`, `*.mdx` |
| Preview | `public.image`, `com.adobe.pdf`, `public.audiovisual-content`, `public.data` |
| File | `*.ts`, `*.mts`, `*.cts`, `*.plist`, `public.text`, `*` |

So a CSV plugin with `*.csv` takes `.csv` files from File, whose match is
the type `public.text`. `.ts` stays text, because File's glob beats
Preview's type (`.ts` is also an MPEG-2 stream).

## How it shows

| Place | What shows | From |
|---|---|---|
| [New pane](/docs/ui/new-pane) chooser | a row under Browser, with the icon and the `chooser` title, user plugins after the ones inside the app | `chooser`; only for `folders`, `git` or no `opens`, because a file needs a path |
| ⌘K, the File menu, the card's menu | "Open ‹chooser› Here" | `chooser` |
| Open With ▾ (second row of a file card) | after the Mac's apps, a divider and every plugin whose patterns match the file, defaults first, each with its icon and name; a pick turns this card into that plugin's card | `opens.files` |
| the card's first row, the tab, the floating window | "‹name› ‹title›", the icon | `name`, `icon`, `opens` |
| the placeholder in herdr's TUI | the name and the argument | `name` |

- Open With lists the Mac's apps only on This Mac. The plugins show on every
  machine.
- A pick in Open With renames the pane to the other plugin's label with the
  same iid. The card is built again as that plugin.
- The Files card's file context menu gets the same Open With submenu.
- What an agent can list and open is in
  [Agent control](/docs/future-work/agent-control): the manifest's `id`,
  `name`, `opens` and `chooser`.

## Header

`header` lists the controls of row 2, left to right
([The card](/docs/ui/plugins#the-card)). The app draws them natively: 32 pt
tall, 22 × 22 pt buttons in the card buttons' color, 6 pt apart, the row
ending where row 1 does. They show before the page loads. The page changes
them later with `oriel.controls.set` and hears them with `oriel.on("control")`
([Plugin API](/docs/future-work/plugins/api#header-controls-and-commands)).

| `type` | Fields | Draws | The page hears |
|---|---|---|---|
| `button` | `id`, `symbol`, `title` | an icon button; `title` is its help and its VoiceOver label | `{ id }` on a click |
| `toggle` | `id`, `symbol`, `title`, `value` (boolean) | an icon button, in the accent while on | `{ id, value }` |
| `segmented` | `id`, `options` (`[{ "value", "title" }]`), `value` | a small segmented control | `{ id, value }` |
| `menu` | `id`, `title`, `items` (`[{ "value", "title" }]` or `"-"` for a divider), `value` | a borderless pop-up showing the picked item's title, else `title` | `{ id, value }` |
| `field` | `id`, `placeholder`, `value` | a search field ("Filter") that takes the free width | `{ id, value }` on each change, and `{ id, value, submit: true }` on Return |
| `text` | `id`, `value`, `style` (`plain`, `dim` or `path`) | text cut in the middle; `path` draws a list of parts with `›` between them, the first part dim | nothing |
| `spacer` | none | free space | nothing |

- Every control also takes `hidden` and `enabled` (booleans).
- A control's `id` is unique in the plugin. It is also the end of its
  accessibility identifier: `pane.<paneID>.<id>`.
- The app keeps each control's value in the card's native state
  ([State](/docs/future-work/plugins/api#state)). A card loaded again, or
  shown again after it was dropped, gets the same values.
- File plugins get **Open With ▾** at the end of the row by themselves.

## Commands

`commands` puts a card's commands in the menu bar and ⌘K, with their keys,
only while that card has the keyboard. Elsewhere the item is gone, so it
swallows no key (D93).

```json
"commands": [
  { "id": "edit-mode", "title": "Edit Mode", "menu": "view", "key": "cmd+e",
    "symbol": "pencil", "checked": false }
]
```

- `menu` is `file`, `edit` or `view`. `key` is a ⌘ chord (`cmd+e`,
  `cmd+shift+k`). A key that the app already uses is ignored, and the log
  says so.
- A pick sends `{ id }` to `oriel.on("control")`, as a header button does.
  `oriel.controls.set` changes `checked`, `enabled` and `title`.
- `handles: ["save"]` gives the card ⌘S (File ▸ Save), `handles: ["find"]`
  gives it ⌘F, ⌘G and ⇧⌘G. The page hears `save`, `find`, `findNext` and
  `findPrevious`.

## Permissions

Each permission opens a part of the bridge. A call outside the manifest's
permissions fails with the error `denied`, and the log names the missing
permission.

| Permission | Allows | Words in the trust prompt |
|---|---|---|
| `files:read` | `oriel.files.read`, `info`, `list`, `paths`, `watch` | "read files and folders" |
| `files:write` | `oriel.files.write` | "change and create files" |
| `git` | `oriel.git` (root, status, log, diff) | "read git history and changes" |
| `run` | `oriel.run`: any command | "run any command as you" |
| `clipboard` | `oriel.clipboard.write` | "put text on the clipboard" |

Every permission reaches only the card's machine, but any path there that
you can reach. The prompt says "on the machine of each card you open". What
the prompt looks like and when it asks:
[Plugin security](/docs/future-work/plugins/security#the-trust-prompt).

## Options

### The manifest format

| Option | Pros | Cons |
|---|---|---|
| `manifest.json` (Obsidian, Figma, WebExtensions) | read by Swift with no JavaScript; a JSON schema can check it in the editor; an agent writes it easily | no comments; no shared values from code |
| A TypeScript export, `export const plugin = definePlugin({...})` | one file; typed; values can come from code | the app must build and run code to read the header and patterns; a broken build hides the plugin from Open With |
| An `oriel` field in `package.json` (VS Code, Raycast) | one file with the dependencies | a `package.json` for plugins with no dependencies; npm fields mixed with ours |

Recommended: `manifest.json`. The app reads it before any code runs, also
when the code does not build.

### Header controls

| Option | Pros | Cons |
|---|---|---|
| Declared in the manifest, values set from code (VS Code's editor title menus) | native controls that look like every other card; the row draws before the page loads and never moves; keys and VoiceOver come free | a fixed set of control types |
| Drawn by the page (Obsidian's `addAction`, any web toolbar) | any control the author wants | the row looks unlike the native cards; it draws only after the page loads, and a dropped card has no row |
| Both: declared controls plus a page-drawn area | covers every case | two ways to do one thing; more code in the app and in plugins |

Recommended: declared in the manifest. The user asked for the native second
row, and the six control types cover the five default plugins.

### Which plugin opens a file

| Option | Pros | Cons |
|---|---|---|
| Patterns with `default` or `option` (VS Code's custom editors) | decided by the name alone, so a remote file is not read; the order is a fixed rule | a plugin cannot look inside the file |
| A function in the plugin that says yes or no | exact | runs every plugin's code to fill Open With |

Recommended: patterns with a priority.

### Permissions

| Option | Pros | Cons |
|---|---|---|
| A few named permissions (`files:read`, `run`, …) | plain words in the prompt; a read-only plugin cannot write or run commands | not a real limit for a plugin that has `run` |
| Scopes with paths and command patterns (Zed, Tauri) | fine control | `git -c alias.x='!sh'` and similar make command scopes leak; more to write and to read |
| None: every plugin can do everything | the least code | a bug or a bad dependency in a viewer can change files |

Recommended: a few named permissions
([Plugin security](/docs/future-work/plugins/security#options)).
