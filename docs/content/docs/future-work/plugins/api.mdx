description: "Proposed: the typed oriel object a plugin's page calls, its state, its versions, and the Swift side behind it"
---

Proposed ([Pane kinds and plugins](/docs/future-work/plugins)). A plugin's
entry file exports one function. The app calls it with the `oriel` object
when the page loads. Everything the page asks of the app goes through that
object. The default plugins use exactly this API.

```ts
import type { Oriel } from "oriel"

export default async function main(oriel: Oriel) {
  const { text } = await oriel.files.read(oriel.card.arg)
  document.body.textContent = text
}
```

- The types come from `oriel.d.ts`, which the app keeps in
  `~/.config/oriel/plugins/` with a `tsconfig.json` that includes it. The
  `import type` line goes away in the build, so nothing is bundled for it.
- The card is ready when `main` returns (or its promise settles). Until then
  the card shows its loader, or its still after a drop. An error thrown from
  `main` shows in the card
  ([Errors in the card](/docs/future-work/plugins/building#errors-in-the-card)).
- Every call works only on the card's own machine and only within the
  manifest's permissions ([Permissions](/docs/future-work/plugins/manifest#permissions)).

## The types

```ts
declare module "oriel" {
  /** The object `main` gets. API version 1. */
  export interface Oriel {
    /** The API version the app gives this page: the manifest's `api`. */
    readonly api: number
    readonly card: Card
    readonly files: Files
    readonly git: Git
    readonly state: State
    readonly controls: Controls
    readonly theme: Theme
    readonly clipboard: { write(text: string): Promise<void> }

    /** Runs argv on the card's machine, in the pane's folder unless `cwd` says otherwise. Needs `run`. */
    run(argv: string[], options?: { cwd?: string; stdin?: string; timeout?: number }): Promise<RunResult>
    /** A card of another plugin (or the browser) in a new tab after this card's tab. */
    open(target: { plugin?: string; arg: string; at?: string }): Promise<void>
    /** One line on glass at the top of the card. Resolves with the button picked, or undefined. */
    toast(text: string, buttons?: [other: string, main: string]): Promise<string | undefined>

    on(event: "control", fn: (e: { id: string; value?: string | boolean; submit?: boolean }) => void): Off
    on(event: "save" | "find" | "findNext" | "findPrevious", fn: () => void): Off
    on(event: "visible" | "keyboard", fn: (yes: boolean) => void): Off
    on(event: "theme", fn: (theme: Theme) => void): Off
  }

  export type Off = () => void

  export interface Card {
    /** The instance id from the label: stable for the pane's life. */
    readonly id: string
    readonly plugin: { id: string; version: string }
    readonly machine: { id: string; name: string; remote: boolean }
    /** The label's argument: a path, a root, "<root> <source>", a URL, or "". */
    readonly arg: string
    /** The pane's folder on its machine. */
    readonly cwd: string
    /** A linked open's landing, on the first load only: a 1-based line, or a file of a diff. */
    readonly at?: string
    readonly visible: boolean
    readonly keyboard: boolean
    /** Renames the pane's label with this argument. The page loads again with it; the state stays. */
    setArg(arg: string): Promise<void>
    /** The dot after the title. A dirty card is never dropped, and ⌘W and hot reload ask first. */
    setDirty(dirty: boolean): void
  }

  export interface Files {
    /** UTF-8 text up to 16 MB. `hash` is what `write` checks. `writable` is false over 4 MiB on a remote machine. */
    read(path: string): Promise<{ text: string; hash: string; writable: boolean }>
    /** Bytes up to 16 MB, with the MIME type from the name. */
    readBytes(path: string): Promise<{ data: Uint8Array; type: string; hash: string }>
    /** The info view's facts: the system's icon is a PNG data URL. */
    info(path: string): Promise<{ name: string; size: number; kind: string; icon: string; folder: boolean }>
    list(folder: string): Promise<{ name: string; folder: boolean; ignored: boolean }[]>
    /** Every path under the root: the files git does not ignore in a repository, else every file, up to 8 MB of names. */
    paths(root: string): Promise<string[]>
    /** Writes a new file beside the old one and moves it over. With `over`, fails with `changed` if the file's hash differs. Needs `files:write`. */
    write(path: string, data: string | Uint8Array, options?: { over?: string }): Promise<{ hash: string }>
    /** Calls fn after a change under path, only while the card shows; once on showing again if something changed meanwhile. */
    watch(path: string, fn: () => void): Off
  }

  export interface Git {
    /** The repository's root of a folder, or null. */
    root(folder: string): Promise<string | null>
    status(root: string): Promise<{ letter: "M" | "A" | "D" | "R" | "?"; path: string }[]>
    /** Commits of HEAD, newest first, with the graph's lanes when asked. */
    log(root: string, options?: { limit?: number; graph?: boolean }): Promise<Commit[]>
    /** The patch as git prints it: "uncommitted" (staged, unstaged and untracked against HEAD) or a commit against its first parent. Up to 16 MB. */
    diff(root: string, source: string): Promise<string>
  }

  export interface Commit {
    hash: string
    subject: string
    /** Milliseconds since 1970. */
    date: number
    lane?: number
    children?: number[]
    parents?: number[]
    through?: number[]
  }

  export interface RunResult { code: number; stdout: string; stderr: string; truncated: boolean }

  export interface State {
    /** The card's state as last set: given at load, also after a drop, a hot reload or a relaunch. */
    get<T>(): T | undefined
    /** JSON, at most 256 KiB. Kept at once in the app; written to the machine 500 ms after the last set. */
    set<T>(value: T): void
  }

  export interface Controls {
    /** A header control's or a command's current value. */
    get(id: string): string | boolean | undefined
    set(id: string, change: {
      value?: string | boolean | string[]
      title?: string
      items?: ({ value: string; title: string } | "-")[]
      hidden?: boolean
      enabled?: boolean
      checked?: boolean
    }): void
  }

  export interface Theme {
    dark: boolean
    style: "glass" | "classic"
    /** The app's text size in points (⌘+ ⌘− ⌘0). */
    textSize: number
    /** The app's tokens as CSS colors; the same as the CSS variables. */
    colors: Record<"text" | "dim" | "divider" | "accent" | "working" | "needs-you" | "finished" | "error", string>
  }

  /** What every failed call rejects with. */
  export interface OrielError extends Error {
    code: "denied" | "notFound" | "notText" | "tooLarge" | "changed" | "timeout" | "closed" | "failed"
  }
}
```

## What each part does

| Part | What it does | Behind it (Swift) |
|---|---|---|
| `card` | who the card is: its iid, machine, argument, folder and landing | the label and the pane in the snapshot |
| `files` | read, list, write and watch on the card's machine | HerdrKit's `Files` (`read`, `list`, `paths`, `save` by hash, `watch`) over the machine's `Exec` |
| `git` | the repository's root, status, history with lanes, and patches | HerdrKit's `Git` and the diff's patch read (`DiffPatch.swift`); on This Mac only when `gitRuns()` |
| `run` | any command on the card's machine | `Exec.run` inside the envelope: argv only, no shell; 30 s timeout by default, 4 MiB per stream, then `truncated`; two at a time per card |
| `state` | the card's state for drops, reloads and relaunches | [State](#state) |
| `controls` | the header row and the card's commands | the native header view ([Header](/docs/future-work/plugins/manifest#header)) |
| `theme` | colors, light or dark, glass or classic, the text size | the `Look` tokens |
| `open` | an open: in this card, a new tab right after this card's tab, or a pane to its side | `Page.open(_:arg:at:from:how:)` as today; no `plugin` picks the default plugin for a file, and the browser for an `http` or `https` URL |
| `toast` | the card's toast | `Toast` and its view, as today |
| `clipboard.write` | text on the clipboard | `NSPasteboard`; needs `clipboard` |
| `console` | logs | each `console` line and every uncaught error go to the Web Inspector and to `~/Library/Logs/Oriel/plugins/<id>.log` |

- **Events** go from the app to the page (`callAsyncJavaScript` into the
  runtime). `on` returns a function that stops the handler. Every handler and
  watch ends with the page, so a reload needs no cleanup code.
- **Keyboard and focus.** `keyboard` is true while the card has the keyboard.
  The page focuses its own field then (an editor puts its caret back). Keys
  that no menu item takes reach the page. A plugin cannot take the app's ⌘
  keys: the menu goes first (D93). Its own keys go in `commands`.
- **Theme.** Before the first paint, the runtime sets the colors as CSS
  variables on the root (`--text`, `--dim`, `--divider`, `--accent`,
  `--working`, `--needs-you`, `--finished`, `--error`), `--app-text-size`,
  and `color-scheme`. It sets them again on a change and then sends
  `theme`. The app's `card.css` (system fonts, a clear background) loads
  before the plugin's CSS.
- **Visible.** A card that is not on screen gets `visible` false. Its watches
  stop. Its `run` calls go on, but a plugin must not start new work while
  hidden.

## State

Each card has one state value, which the plugin sets. Use it for what the
user misses after a reload: the sort, the selected row, the scroll.
Data that every device must see belongs in files on the machine.

- **In the app:** `set` keeps the value in the card's native state at once,
  next to the header controls' values. A drop, a hot reload or a new
  argument gives the page the same value in `get`.
- **On the machine:** 500 ms after the last `set`, the app writes the value
  to the instance state file, as the browser does today:
  `$HOME/.local/state/oriel/<session>/<plugin-id>/<iid>.json`. A relaunch,
  another device or a cold restart of herdr reads it when the card is built.
  A missing file means no state.
- **The file's rules** stay as built for the browser: written atomically
  over stdin, at most 256 KiB, last writer wins; the device that closes the
  pane removes it; on connect the app removes files not touched for 30 days.
- The header controls' values go in the same file, under `"controls"`. The
  plugin's value goes under `"state"`.

```json
{ "controls": { "layout": "split", "list": false }, "state": { "viewed": ["Sources/App.swift"] } }
```

- **An open card changes only when it is built.** Another device's write
  does not move it. A card is built on a relaunch, a new device, a show after
  a drop, a hot reload and a new argument.

## Versions

- The manifest's `api` is the version the plugin was written for, an
  integer. This page is version 1.
- Each change of the API raises the number, also an addition. `oriel.d.ts`
  marks each member with the version that added it (`@since 2`).
- The app runs a plugin whose `api` is at most its own, and gives the page
  that version's behavior. A change that breaks an older plugin keeps
  the old behavior for plugins with the older `api`. So a plugin never breaks
  on an app update.
- A plugin whose `api` is newer than the app's shows "‹name› needs a newer
  Oriel" in its card.
- The bridge messages are the app's own and are not part of the API. Only
  the `oriel` object is.

## The Swift side

The parts, in the app:

```swift
/// manifest.json, decoded leniently: only the fields the app uses.
struct PluginManifest: Decodable, Sendable {
    let id, name, version, icon: String
    let api: Int
    /// The entry file; nil for a kind with native content (the browser).
    let main: String?
    let opens: Opens?
    let chooser: String?
    let header: [Control]
    let commands: [Command]
    let handles: Set<String>
    let permissions: Set<Permission>
}

enum Permission: String, Decodable, Sendable { case read = "files:read", write = "files:write", git, run, clipboard }

/// Every plugin: the app's own from Resources/plugins, then ~/.config/oriel/plugins, watched.
@MainActor @Observable
final class PluginRegistry {
    private(set) var manifests: [String: PluginManifest]
    /// The plugins that open this file, the default first (manifest#which-plugin-opens-a-file).
    func opening(_ path: String) -> [PluginManifest]
    /// The page's folder for oriel-plugin://<id>/: built with esbuild, or the error text.
    func build(_ id: String) async -> Result<URL, BuildError>
}
```

- `PluginKind` goes. A label's plugin id names a manifest in the registry,
  and the browser is a manifest too
  ([Browser and native kinds](/docs/future-work/plugins/browser-and-native)).
- `WebCard` becomes the card of any plugin. Its `answer(_:)` handles the
  API's messages. Each case checks the permission first, then calls `Files`,
  `Git` or `Exec` with the card's own machine:

  ```swift
  case "files.read":
      try need(.read)
      let file = try await Files.read(path, exec: exec)
  ```
- One message handler per card (`WKScriptMessageHandlerWithReply`), behind a
  weak relay as built. The card is bound to its machine, session, plugin and
  permissions when it is made. No message carries a machine or a card.
- A plugin's per-card native state (`Plugin`): the label, the controls'
  values, the state value, the dirty flag and the still. It outlives the web
  view, so a dropped card keeps it.
- `PluginHeader`, one SwiftUI view, draws any manifest's header. It replaces
  `DiffToolbar`, `GitBar`, `JumpBar`, `PreviewBar`, `MarkdownBar` and `FilesBar`.
- The runtime (`web/runtime/oriel.ts`, built into the app) is the `oriel`
  object. The app adds it to each page at document start, with the card's
  context, before the plugin's code runs.

## Options

### How the page reaches the app

| Option | Pros | Cons |
|---|---|---|
| A default export that gets a typed `oriel` object (pi, OpenCode) | the types document the API; the app knows when the card is ready (when `main` returns); helpers get the object as a parameter | one more line than a global |
| A global `oriel` that the app puts in the page | nothing to import | no ready signal; helpers reach a global |
| An imported module, `import { files } from "oriel"` | reads like any library | the build must map `oriel` to the app's runtime, and the runtime gets baked into each build |
| Raw messages (`postMessage`, as Figma and VS Code webviews) | no API code in the app | untyped; every plugin writes its own wrappers |

Recommended: the default export with a typed object.

### Calls and events

| Option | Pros | Cons |
|---|---|---|
| Promises for asks, `on(event)` for what the app sends | an ask reads as one line (`await oriel.files.read`); events come only when there is something to say | two styles |
| Everything as events, answers included | one style | every ask needs an id and a handler |
| Everything as promises, events as long-poll asks | one style | a waiting call per event kind |

Recommended: promises for asks, `on` for events.

### Where state lives

| Option | Pros | Cons |
|---|---|---|
| In the app at once, then in the instance state file on the machine | a drop or reload restores with no read; a relaunch or another device finds it | two copies, but the app's copy is only memory |
| Only in the page (`localStorage`) | nothing to build | lost when a dropped card's process ends; one store for all cards of a plugin |
| Only in app storage | survives relaunches | another device does not see it |

Recommended: the app, then the state file, as the browser does today.

### Versions

| Option | Pros | Cons |
|---|---|---|
| One integer `api`, raised on every change; old behavior kept for old numbers (Figma) | one check; a plugin never breaks on an update | the app keeps old paths when a change breaks |
| A semver range (`engines`, as VS Code and bb) | familiar | ranges are easy to get wrong; still needs old paths |
| A minimum app version (Obsidian's `minAppVersion`) | simple | ties plugins to app releases, not to the API |

Recommended: one integer.

Not in version 1: network from the page (`fetch` reaches only the plugin's
own files), streams from `run`, clipboard read, file pickers, plugin
settings, the herdr snapshot as an event.
