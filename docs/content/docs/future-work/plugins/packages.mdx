## Manifest

A normal `package.json` with one `oriel` field.
```jsonc
{
  "name": "git-history",                       // plugin id: ^[a-z0-9][a-z0-9._-]{0,63}$
  "version": "0.3.0",
  "repository": "https://github.com/me/oriel-git-history",
  "oriel": {
    "api": 1,                                  // highest API version used
    "title": "Git history",
    "icon": "arrow.triangle.branch",           // SF Symbol, or an asset path
    "panes": [
      { "name": "history", "title": "Git history", "entry": "dist/history.html",
        "arg": { "title": "Ref or path", "placeholder": "HEAD",
                 "required": false } }
    ],
    "preferences": [
      { "name": "maxCommits", "type": "textfield",
        "title": "Commits to load", "default": "500" }
    ]
  }
}
```
- One plugin can declare several pane kinds. The id `browser` is taken by the
  browser's label.
- An id resolves in this order: core, then a linked folder, then an installed
  plugin, so a plugin cannot replace a core one. One install per id.
- `arg.required` makes the app ask for the argument before creating the
  pane. Otherwise the plugin starts empty and can call `setArg`.
- Preference types: `textfield`, `password` (Keychain), `checkbox`,
  `dropdown`.

## Where plugins live

In the app, not on machines:
`~/Library/Application Support/Oriel/plugins/<id>/` with
`package.json`, the page files and a source record (URL, ref, commit).
- **Install from a git URL** (Plugins › Add in the Settings window ([Future work](/docs/future-work#smaller-items))): shallow clone,
  require `package.json` and every pane's `entry` file, already built (the app
  never runs npm, node or a bundler),
  validate, show the consent sheet ([Plugin security](/docs/future-work/plugins/security)), move into place.
- **Link a local folder (dev mode):** the app loads straight from the folder,
  watches it and reloads that plugin's cards on change. Cards come back
  in place because their argument and state live outside the page ([State and restore](/docs/future-work/plugins/state)).
  Dev plugins get Safari Web Inspector and a "DEV" badge.
- **Updates:** at most once a day the app checks the remote ref and shows
  "Update available"; the user presses Update.
- **API version:** the app injects the API. A plugin whose
  `api` is newer than the app shows "needs a newer Oriel". API changes
  within a version are additive.

## Card lifecycle

1. A plugin pane enters the selected tab: the
   card is created, keyed by `(machine, session, terminal_id)`.
2. The app creates the web page, injects `window.oriel` and the stylesheet,
   and loads the pane's entry file.
3. When the card leaves the screen, its `run` calls pause and its events stop.
   It resumes on return.
4. Live web views are capped ([Plugin UI](/docs/future-work/plugins/plugin-ui)), and
   fewer on a memory warning. An evicted card keeps an image of its last
   frame.
5. When the pane leaves the snapshot, the card is destroyed.

## Preferences

Preferences are per device, keyed by plugin id and source: values in
`UserDefaults`, passwords in the Keychain, a form generated from the manifest in the Settings window and in the card's
menu. A required preference with no value shows a "Set up ‹title›" view.
