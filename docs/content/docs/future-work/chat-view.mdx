Not built. This page is the design of the chat view: an agent pane drawn as
messages with a reply box, instead of its terminal. The agent keeps running
in its herdr pane; the chat is a second way to look at the same process, so
switching ends nothing, and it works the same on remote machines. It covers
Claude Code, Codex, pi and opencode. The research behind it is in
`resources/research/ui/chat-view.md` and `resources/research/agents/`.

## Which panes have it

- Only agents that the [New pane](/docs/ui/new-pane#agent) chooser or Start
  Agent Here started, with Oriel's flags (below). Their header has the
  chat|term switch.
- The app recognizes such a pane by a marker in its launch line, read from
  `pane.process_info`. This also works after the app relaunches, with no
  state kept in the app.
- Every other pane shows only its terminal and no switch: plain terminals,
  agents started by hand or from herdr's TUI, and agents that herdr restored
  after a restart (herdr runs them again without Oriel's flags). So does the
  company's opencode build, which ignores the flags.

## Launch flags

The chooser adds these to the agent's command. The launch line goes to herdr
as one argument, never through another layer of shell quoting. Nothing is
installed beyond the files named here, written with one run on the pane's
machine before the first launch.

| Agent | Written first | Added to the command | Marker |
|---|---|---|---|
| Claude Code | nothing | `--session-id T --settings '<json>'`: a SessionStart hook that appends the session id and transcript path to `/tmp/oriel-chat/T/hooks.jsonl`, and a PermissionRequest hook for AskUserQuestion only (below) | `--session-id T` |
| Codex | nothing | `-c hooks.SessionStart=[…]` that appends to `/tmp/oriel-T/hooks.jsonl`, and `-c hooks.state={…}` with that hook's trust hash, so Codex asks nothing | `/tmp/oriel-T` |
| pi | `~/.cache/oriel/pi-<hash>.ts`, a 31-line extension | `-e <that file> --oriel ~/.cache/oriel/state/<uuid>.jsonl` | `--oriel` |
| opencode | `~/.cache/oriel/opencode/oriel-tui.js` (a 20-line TUI plugin), its `tui.json`, a password file per pane (0600) | `--port 0 --hostname 127.0.0.1`, with `OPENCODE_TUI_CONFIG` and `OPENCODE_SERVER_PASSWORD` read from the file | the state file's `pid` equals the pane's |

- `T` is a new id per launch. The user's own settings, hooks, plugins and
  extensions keep working; the flags write no user config.
- The pi extension appends a line when the session changes (with its file),
  when an extension dialog opens or closes, on `/tree`, and when pi starts or
  stops working. It also tells herdr's pi integration that pi is blocked, so
  `agent.prompt` refuses while a dialog is open.
- The opencode plugin appends the server's address, the session and whether
  a dialog is open. The password keeps other local programs off the port; it
  never shows in the command line or the scrollback.

## Where messages come from

| Agent | History | How the app follows it |
|---|---|---|
| Claude Code | the `transcript_path` of the last SessionStart line | `tail -c +N -F` |
| Codex | the `transcript_path` of the last SessionStart line that has one | `tail -c +N -F` |
| pi | the `path` of the last `session` line; `tree` lines move the branch | `tail -c +N -F` |
| opencode | `GET /session/<id>/message` for the session in the last state line | `curl -N /event` (opencode writes no transcript file) |

- The app follows the side file (`hooks.jsonl` or the state file) and the
  history as two line streams, on This Mac and over the relay. A new session
  line (`/new`, `/clear`, a fork, a resume) restarts the history stream.
- A message shows when it is on disk, 0.1–2 s after the TUI draws it. There
  is no text word by word. While the agent works, the last row says
  "Working".
- On open the app reads the last 256 KiB and drops the first partial line.
- **Parse:** a small, lenient parser per agent. The core is user text,
  assistant text, tool calls paired with their results, and the end of a
  turn. Thinking rows, subagents, plans and todos, compaction and the model
  are extras. Anything else is skipped.
- **Markdown:** `AttributedString(markdown:)` with the `.full` syntax option,
  split into blocks. Code blocks are monospaced and scroll sideways.

## Ready, working, waiting

Each adapter says whether the agent is ready for a message, working, or
waiting for the user.

| Agent | Waiting | Ready |
|---|---|---|
| Claude Code | `status` in `~/.claude/sessions/<pid>.json` is `waiting` (dialogs, questions and pickers) | `status` is `idle` |
| Codex | herdr's `agent_status` is `blocked` | herdr says idle or working, and the screen's last rows show Codex's input box above its status row |
| pi | the last state line is `blocked` | the last state line is not `blocked` or `shutdown`, and herdr says idle or working |
| opencode | a pending request, `dialog:true`, or herdr's `blocked` | `dialog:false` and herdr is not `blocked` |

Claude Code's session record is undocumented. If it is missing, the app uses
herdr's `agent_status` instead.

## Sending and answering

- **Send:** `agent.prompt {target: pane_id, text}`, only when the adapter says
  ready. herdr pastes with bracketed paste and presses Enter. While the agent
  works, Send stays on: Claude Code and opencode queue the text, and Codex and
  pi steer the running turn with it.
- **Sent** means the user entry showed up in the history. Until then the
  bubble shows as sending. After 5 s it shows "Not sent" with **Show
  Terminal**, and the draft comes back.
- Text that starts with `/` is not sent. The card flips to the terminal and
  the text is typed there.
- Drafts are kept in memory per pane and shared with the pill card.
- **Stop** sends the agent's interrupt: Esc (opencode: Esc twice), and only
  while it works. Never ctrl+c.
- **Waiting on something the chat can answer:** a card in the chat.
  - Claude Code's questions (AskUserQuestion): the hook writes the question
    to `hooks.jsonl` and waits for a decision file. The card's buttons write
    the answer. If the user answers in the TUI first, the app removes the
    request and the hook exits.
  - opencode's permissions and questions: from the event stream (or
    `GET /permission`), answered with `POST /permission/<id>/reply` and
    `POST /question/<id>/reply`. A request already answered in the TUI
    returns 404, and the card goes.
- **Waiting on anything else** (tool approvals of Claude Code and Codex,
  Codex's questions, pi's extension dialogs, every picker): the lower part of
  the card becomes the live terminal, in place of the reply box, and it gets
  the keyboard. The terminal stream is open only while it shows. When the
  agent works or is idle again, it slides away and the reply box comes back.
  **Open Terminal** flips the whole card.
- **The chat cannot read the session** (no history yet after 10 s, a parse
  failure, or a turn of entries it does not know): one row says so, with
  **Show Terminal**.

## Detail levels

One setting for the app, a segmented control in the card header:
**Replies**, **Steps** and **All**.

- **Replies:** the user's messages, and each turn's last reply. The work in
  between is one quiet line: "Worked 1m 48s · 2 files edited · 3 commands".
- **Steps:** adds the replies in between, thinking rows ("Thought for 6s"),
  plans and todos, subagents, and each run of tool calls between two replies
  as one stacked card. The card's front shows a summary ("Edited 2 files, ran
  1 command, 1 failed") and the latest call; one or two edges under it show
  that more calls are inside. A running call shows a spinner and its time.
- **All:** every stack open, one row per call (the tool, its target, its
  result, its time), with edits showing their diff, as pi-content-layout
  does.
- Clicking a stack opens or closes it at any level.

## What it looks like

- As in Messages: the user's messages are bubbles in the accent color on the
  right; replies are plain text on the left. Tool cards and the reply box
  are glass.
- The card keeps its header, with the level control and the chat|term
  switch. The messages scroll, newest at the bottom; the reply box is a glass
  capsule at the bottom, with the model in small text, read only, and Send or
  Stop.
- A zoomed or floated card centers the messages in a reading column.
- The header's state capsule follows the agent: Working, Needs you, Done,
  Error, in the status colors.
- The [floating pills](/docs/future-work/pills)' pill card is the same view at
  360 pt, at the Replies level.

## Switching views

- Agent cards started with Oriel's flags have a chat|term switch. It is a
  segmented control in the card header, not a swipe, because sideways swipes
  belong to the strip.
- The choice is kept in memory per pane. The Mac and the phone can show the
  same pane differently.
- The switch changes only what the card draws: the agent, its turn and its
  pane go on. While the chat view is shown, that pane's terminal stream is
  closed, except while the live terminal shows at the bottom.

## Choices

- **The agent's own history, followed on its machine, plus `agent.prompt`,
  for agents Oriel starts.** Rejected: a chat for every pane from its screen
  text (screen readers break with each agent release; other apps gave it up).
- **A small core, and the live terminal for the rest.** Rejected: in-chat
  answers for tool approvals. In Claude Code a company hook that allows beats
  Oriel's deny, and a waiting hook keeps prompts open that would close by
  themselves. In Codex a waiting hook runs before its reviewer and hides the
  TUI's prompt.
- **Hooks and small plugins passed at launch.** Rejected: restarting the agent
  in a structured mode (`codex --remote` with an app-server, `pi --mode rpc`,
  ACP, the Agent SDK). Without live text they add a second process or a server
  for nothing the hooks do not give, and `pi --mode rpc` on the TUI's file
  split its session tree. Rejected: writing hooks into the user's settings,
  as some apps do.
