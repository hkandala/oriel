A native Apple client for terminal multiplexers: programs that keep
terminals alive in workspaces, tabs and panes. [herdr](https://github.com/herdrdev/herdr)
comes first and is the only backend for now. The multiplexer stays the
backend: it owns every workspace, tab, pane, terminal and agent. The app
draws them, drives them, and keeps as little state of its own as it can.

- Name: **Oriel**. These pages are the design. v0 is built: This Mac only
  ([Build order](/docs/build-order#build-order)).
- Targets: herdr 0.9.3 (protocol 22) or newer on each machine, macOS 26, iOS
  and iPadOS 26. The Mac needs herdr only for its own sessions.
- See it: the [interactive overview](/overview/index.html) has working
  mock-ups of the main screens on one page.
- Evidence for the claims is in the repository's
  [`resources/research/`](https://github.com/hkandala/oriel/tree/main/resources/research)
  and [`resources/inspirations/`](https://github.com/hkandala/oriel/tree/main/resources/inspirations)
  folders (see [Sources](/docs/reference/sources)).

## The problem

People run many coding agents (Claude Code, Codex, pi) at once, often on
several machines. herdr keeps those agents alive in panes on each machine and
knows when each one is working, blocked or done (the app shows these as
working, needs you and finished). But herdr's interface is a terminal UI: one
machine at a time, keyboard-first, and nothing when you are away from the
terminal.

## What we build

One app for Mac, iPad and iPhone that shows every herdr machine at once:
- a sidebar of machines and workspaces with every agent's status, and an
  Activity view of the agents that need you;
- a strip of tabs you swipe through, with resizable panes;
- panes for terminals, agents, web pages and plugins;
- a chat view for any agent or terminal pane;
- floating status pills on the Mac screen edge when you are in another app;
- light and dark, Glass and Classic, with program icons and Rex's tab bar.

On iPhone, v1 shows status while the app is open. Alerts while the app is
closed need push notifications ([Future work](/docs/future-work)).

## Principles

1. **The multiplexer is the source of truth.** If it can hold a piece of
   state, it holds it: anything that takes space in the layout is one of its
   panes, with a label. A fresh app on a new device rebuilds everything from
   it. Everything the app keeps for itself is listed in
   [Data: app vs herdr](/docs/data).
2. **Use what exists.** herdr's API and CLI, OpenSSH, Apple's frameworks. On
   each machine the app only runs commands and opens TCP streams over SSH. No
   daemon, relay or server of our own.
3. **One picker for every pane kind.** Terminal, agent and web page are built
   in. Every other pane kind is a plugin: a small web page in a native web
   view, yours included.
4. **The simplest thing that works.** Each shortcut we take on purpose is
   marked "Simpler choice" and says when to revisit it.
