## What a machine is

- A **machine** is a host: a computer that runs herdr (D43). This Mac now,
  SSH hosts later. Each machine has its own icon, because the title row's
  machine button shows only the icon ([Machine button](/docs/ui/window#machine-button)).
- A machine runs several herdr **sessions** (`default`, `pi-herd`, …), each
  one herdr server. The sessions of one machine share one SSH connection
  (ControlMaster) and nothing else: each session has its own events, streams
  and state folder.
- A window shows one machine. Sessions open as pages: its sidebar has one
  page per session the user opened in that window
  ([Sidebar](/docs/ui/window#sidebar)). A new window opens one page, the
  `default` session.

## The machine list

- **The app keeps its own list of remote machines**, on macOS and iOS alike
  (D54): name, SSH target, icon and id, in `UserDefaults`. One code path on
  both platforms. Remote machines come after This Mac.
- **This Mac** is always in the list, with a laptop icon when the Mac has an
  internal battery, else a desktop icon.
- **A machine's sessions** come from `herdr session list --json`, run on that
  machine. The Open Session sheet lists them
  ([Open Session](/docs/ui/window#open-session)). herdr on the Mac is needed
  only for This Mac's sessions, not for remote machines.
- **herdr's machines (macOS):** when herdr is on the Mac, the Add Remote Host
  sheet lists the targets of the enabled entries of `herdr machine list --json`
  (`{id, label, target, session, enabled}`) that are not in the app's list,
  each with a checkbox. While the app's list is empty, they start checked.
  The app never writes herdr's list.

## macOS
- **SSH is the system `ssh`.** The user's `~/.ssh/config`, agent, keys,
  `ProxyJump`, YubiKey and Tailscale SSH work unchanged.
- **One ControlMaster per host,** started on purpose, once:
  ```sh
  ssh -M -N -f -o ControlPersist=10m -o ServerAliveInterval=20 \
      -o ForwardAgent=no -o ForwardX11=no -o ClearAllForwardings=yes \
      -S ~/Library/Caches/oriel/<h8> <target>
  ssh -S ~/Library/Caches/oriel/<h8> -O check <target>   # wait until this succeeds
  ```
  - Later runs use `-F /dev/null -o ControlMaster=no -o BatchMode=yes
    -o ProxyCommand=/usr/bin/false -S ~/Library/Caches/oriel/<h8>`. Without a
    master they fail at once instead of opening their own connection and
    prompting again. They send none of the user's configured forwards to the
    master.
  - Starting the master first means one password, OTP or key prompt per host.
    With `ControlMaster=auto`, parallel first calls each prompt.
  - `<h8>` is 8 hex characters of a hash of the SSH target. The folder is per
    user, mode 0700, with no spaces. The path stays under the 104-byte socket
    limit for user names up to 50 characters, with ssh's 17-character
    temporary suffix.
  - Forwarding is off, so a machine cannot reach the Mac's SSH agent or ports
    through the app's long-lived connection. The app's own `-O forward` calls
    still work.
  - `-O check` only asks whether the master process lives. A dead link is
    found by the [health check](#health-check).
  - On quit the app runs `ssh -S <ctl> -O exit <target>` for each master.
- **Password and OTP prompts:** `SSH_ASKPASS` points at a one-file script in
  the app's `Contents/Resources`, with `SSH_ASKPASS_REQUIRE=force`. It shows
  an `osascript` dialog with the prompt passed as an argument (never pasted
  into the script). It hides the answer only for password, passphrase or PIN
  prompts.
- **Local Network privacy (macOS 15+):** an `ssh` started by the app counts as
  the app. The app declares `NSLocalNetworkUsageDescription`, resolves the
  target with `ssh -G`, and opens an `NWConnection` to a LAN address before
  the first SSH, so the system asks once. Tailscale addresses are not
  affected.

## iOS

- One Citadel SSH connection per host, with exec channels on it.
- The key is a Secure Enclave P-256 key (`ecdsa-sha2-nistp256`). It cannot
  leave the device. The add-machine sheet shows its public line to copy into
  `authorized_keys`.
- The first connect shows the host key's SHA256 fingerprint and asks. After
  that the key is pinned, and a changed key blocks the connection.
- The phone reaches the Mac like any SSH machine: turn on System Settings ›
  General › Sharing › Remote Login, then add the Mac by its Tailscale or LAN
  name.
- Reachability is the user's network (LAN or Tailscale). There is no relay.
  Jump hosts come later (Citadel has `jump(to:)`).
- Citadel has no keepalive; the [health check](#health-check) finds dead
  links.
- When the app goes to the background, it closes its terminal streams. iOS
  then gives about 30 s. The app holds its other connections with
  `beginBackgroundTask`, closes them when that time ends, and reconnects and
  reads the snapshot again on return.
- [Spike S7](/docs/build-order#s7-ios-transport) tests Citadel's exec
  channels before the iOS work starts.

## Open sessions

- A session is open while it has a page in at least one window. Each open
  session has one `HostStore`, shared by every window that shows it
  ([Architecture](/docs/architecture#pieces)). The app keeps one registry of
  them, by session name; a page takes its session's store from it, made on
  first use. Close Page disconnects the store.
- An open session keeps its control plane open (one event stream plus short
  calls), so notifications, the Dock and pills cover every open session in
  every window. The Agents button covers the page in view.
- A session with no page has no store, no snapshot reads and no event stream.
  A machine with many sessions costs nothing until the user opens them.
- Terminals stream only for the tabs shown in a window
  ([What streams](/docs/talking-to-herdr#what-streams)).

## Health check

One loop per open session checks that it answers.
- The check is `session.snapshot`, the read the app needs anyway. It carries
  herdr's version and catches any event the app missed.
- It runs every 30 s while the session is healthy. A failed read switches it
  to every 2 s, so a session started again comes back at once.
- A session counts as live only while the check answers. While it fails, its
  cards gray out.
- On a remote machine a failed check also restarts the connection: on macOS
  `ssh -O exit`, then a new ControlMaster; on iOS a new Citadel connection.
- **Automatic retries never prompt.** On macOS they run with
  `BatchMode=yes`. A host that needs a password, an OTP or a key prompt shows
  **Reconnect** and stops retrying; only that button may prompt.
- When a check succeeds after a failure, the app opens the event stream and
  the terminal streams again: the same path as the first connect
  ([Checks on connect](#checks-on-connect)).

## SSH sessions

- OpenSSH allows 10 sessions per connection by default (`MaxSessions`).
  The sessions of one machine share its connection, so they share that limit.
  This Mac uses no SSH and has no limit.
- The app opens a channel when it needs one: a call, a stream, a chat tail,
  a plugin `run`.
- When the server refuses one, the app closes the least recently shown kept
  stream (D46, [What streams](/docs/talking-to-herdr#what-streams)) and tries
  once more. If nothing is left to close, or the second try fails too, the
  card shows its last image and **Retry**.
- Port forwards for web pages use no session: `MaxSessions` counts only
  sessions.

## Checks on connect

1. `session.snapshot`. Its errors say what is wrong: herdr missing (the
   install command), herdr too old, or the server not running
   ([herdr on each machine](/docs/talking-to-herdr#herdr-on-each-machine)). If
   the server is not running:
   - **This Mac:** a **Start** button. A new window's first page starts its
     session this way when it is stopped. In the Open Session sheet, a stopped
     session or a new name starts the same way. A server the app started gets
     its first workspace in `$HOME`; a server that already runs is left
     alone. The app starts the
     server as a one-shot launchd job (D47). launchd, not the app, is the
     server's parent and "responsible process": macOS privacy prompts never
     name Oriel, the server has its own process group, and it outlives the app.
     - `launchctl bootstrap gui/<uid>` (the user's GUI domain) loads the job
       `dev.hkandala.oriel.herdr.<S>`, which runs
       `<herdr path> --session <S> server` (the path from the login shell).
     - `RunAtLoad` without `KeepAlive`: once `herdr session stop` ends the
       server, launchd never runs it again (`launchctl submit` restarted it).
     - `ProcessType Interactive`: launchd's default throttles the CPU and I/O
       of the server and every agent in it.
     - stderr goes to `~/Library/Logs/Oriel/<S>.log`.
     - The job gets the user's environment keys from the login shell (`PATH`,
       `HOME`, `SSH_AUTH_SOCK`, `XDG_*`;
       [herdr on each machine](/docs/talking-to-herdr#herdr-on-each-machine),
       D47), so the server and the CLI agree on paths.
     - An older job of the label is booted out first (a label loads only
       once). A running server, one that answers a snapshot, is never booted
       out: the app uses it.
   - **A remote machine:** a **Start herdr** button runs
     `sh -c 'nohup <herdr path> --session S server </dev/null >/dev/null 2>&1 &'`
     over SSH and polls `session.snapshot` for up to 5 s.
2. Open the event stream. Its `subscription_started` reply counts as an
   event, so the app reads the snapshot once more and misses nothing between
   the two steps.

The agent picker reads `integration.list` when it opens
([Agent](/docs/plugins/terminal-and-agent#agent)).
