Oriel

A native Apple client for terminal multiplexers: herdr first, and the only backend for now. The multiplexer stays the backend: it owns every workspace, tab, pane, terminal and agent. The app draws them, drives them, and keeps as little state of its own as it can.

This page is a summary. The full design is in the design docs.

The problem

People run many coding agents at once, often on several machines. herdr keeps them alive and knows when each one is working, blocked or done. But its interface is a terminal UI: one machine at a time, keyboard-first, and nothing when you are away from the terminal or on your phone.

What we build

One app for Mac, iPad and iPhone that shows every herdr machine at once: a sidebar of machines and agents, a swipeable strip of tabs with resizable panes, terminal, agent, web and plugin panes, a chat view for agents and terminals, and status pills on the Mac screen edge. Terminal, agent and web page are built in; every other pane kind is a plugin, a small web page.

The multiplexer is the source of truthIf herdr can hold a piece of state, herdr holds it. A fresh device rebuilds everything from it.
⇄

7UI details

How each part looks and behaves. The sections after this one explain how it works.

Window, sidebar and tab bar
  • Title-bar row: the sidebar toggle, the session button (the session's name; it opens the list of sessions, grouped by machine), the tabs while the sidebar is hidden, ⌘ (the palette) and + (new tab).
  • Sidebar: flat on the window background, with no panel. The machine pages (swiped sideways, each headed by the machine's name in a small line), fixed page dots, the fixed status area, and at the bottom a Filter field, New Workspace and Add Machine. A machine page for a non-default local session is named "This Mac · ‹session›".
  • Machine page: herdr's workspaces in herdr's order, as section headers, with their tabs as rows (icon tile, label, status glyph). The selected tab is a raised pill. Later a workspace also lists its agent panes (icon, name, glyph and word). Clicking a workspace selects it in the app only.
  • Tab bar: while the sidebar is hidden, the title-bar row shows one capsule per herdr tab, and one glass marker follows the strip as it scrolls. Each capsule has the icon of the pane last selected in it and the tab label (folder part dimmed). One status slot per capsule shows one glyph by priority: × on hover, then ▲, then ✓, then ◔. The ◔ glyph is static (no animation). When tabs overflow, they shrink and their labels fade out. + makes a new tab. The window title follows the selected tab.
  • Strip: one page per tab. Cards follow herdr's split tree, with an 8 pt gap between cards that is the divider. Double-click a divider to reset it to 0.5; ⌃⌘= equalizes the tab's splits. Each card header has the kind icon, title, view switch (chat|term on agents and terminals, plugin|term on plugin panes, none on web pages), split, zoom and close. Plugin and web cards also have Refresh, which loads the card again from the machine. Controls show on hover on macOS and always on iOS; every action is also in the context menu, the menu bar and ⌘K. Unfocused cards are slightly dimmed.
  • Swiping: two fingers on a trackpad, one finger on iOS; pages snap. First visit to a machine shows herdr's focused workspace; later visits show the last one picked.
  • Keys: ⌃⌥1…9 machines, ⌘1…9 tabs, ⇧⌘[ ] step, ⌘T new tab, ⌘D split, ⌘W close the pane, ⇧⌘W the window, ⇧⌘↩ zoom, ⌃⌘ + arrow resize, ⌃⌘= equalize, ⌘K the palette (tabs, workspaces, sessions).
  • Closing: closing a pane asks first unless the pane runs only its shell (no foreground program). Closing a tab or workspace always asks.

Add a machine, theme and accessibility
  • Add a machine: the app saves the SSH target in its own list, on the Mac and on iOS. 8Architecture

The two calls and the remote command envelope 
protocol Exec {
  func run(_ argv: [String]) async throws -> Channel
  func dial(host: String, port: Int) async throws -> Channel
}

# every remote command, whatever the login shell (bash, zsh, fish):
sh -c 'eval "$(printf %s "$1" | base64 -d)"' sh <BASE64 of the POSIX command>
  • This Mac: Process, with PATH, SSH_AUTH_SOCK and XDG_* read once from $SHELL -lic (3 s timeout, parsed after a marker). HERDR_* is removed from children. herdr's usual install folders are in front of PATH, so the app never looks for herdr: a missing herdr fails the first call and the app shows the install command.
  • Remote on macOS: ssh -F /dev/null -o ControlMaster=no -o BatchMode=yes -o ProxyCommand=/usr/bin/false -S <ctl> <target> --, which never opens a second connection. iOS: a Citadel exec channel.
  • Base64 passes through every shell unchanged, so no data is ever pasted into a shell string.
  • Ending a child = closing its stdin. control exits at once and frees the pane; the bridge exits in about 100 ms. If the app crashes, the kernel closes the pipes and every child ends itself, remote ones too. Commands that ignore the end of stdin (observe, tail -F) always run inside sh -c '<cmd> & c=$!; cat >/dev/null; kill $c', on This Mac too. If a child still runs about 1 s after the close, its channel kills it by pid (never by process group).
  • Every call() has a 10 s timeout. Long-lived streams have none; the health check covers them.
  • herdr older than 0.9.1 has no remote-api-bridge, so the first call fails and the app says "No answer from herdr". A snapshot that reports a version below 0.9.3 shows "herdr 0.9.3 or newer is needed"; a newer protocol needs nothing. Every herdr argv carries --session.
Requests and events
  • call() runs herdr --session S remote-api-bridge, writes one JSON line, reads one reply (herdr answers one request per connection). 18 ms median, 130 ms p95 locally, plus network.
  • One long-lived bridge per machine carries events.subscribe: workspace, tab, pane and layout events listed explicitly (no wildcards), status events only for agent panes, no focus events.
  • Any event means "read the snapshot again"; the app decodes no event payload. One session.snapshot is in flight per machine. An event during a read sets a read-again flag, so one more read follows. The event stream stays; polling was rejected.
  • The stream is reopened, then a snapshot read, when agent panes change, on events_lost and on pane_not_found.
  • One health check per machine: the snapshot read is the heartbeat. It carries herdr's version and catches missed events. Every 30 s while healthy, every 2 s while failing. Automatic retries use BatchMode and never prompt; a host that needs a password or a one-time code shows Reconnect.
  • Snapshots are applied to stable observable objects. Ids are scoped by machine.

Streaming rules and how a stream ends
  • Streams: the selected tab's panes on the selected machine; the Mac keeps those of recently shown tabs too (about 24 terminals). Channels open when needed: when the machine refuses one, the app closes the least recently shown kept stream and tries once more; then the card shows Retry. During a swipe, neighbor tabs show each card's last image; their streams start when the swipe stops.
  • The Mac opens control without takeover and watches if refused. iPhone and iPad open observe. Any device takes control (--takeover) on the first key press, paste or tap in the card, or Take back. Nothing else takes control: a watcher stays a watcher until its user acts.
  • A Mac that becomes inactive keeps its streams. iOS closes its streams when the app goes to the background. A device also closes a stream when it leaves the terminal view (the card leaves the selected tab, or switches to chat).
  • Typed text goes through terminal.input; special keys and Ctrl chords go through pane.send_keys. Asking herdr to accept keys on terminal.input, for one path, is future work.
  • Card size ÷ cell size gives cols × rows; the old frame stays until herdr's full frame at the new size arrives. Streams are opened by terminal_id, so they survive moves.
  • An iPhone watches at a fixed 160×50, scaled to fit, because herdr does not report PTY columns.
  • Terminal queries: herdr already answers them, so libghostty must not. The app uses a pinned libghostty-spm build with the response-suppression patch (uHerdr's suppressesTerminalResponses).

10Machines and SSH

The app keeps its own machine list, on the Mac and on iOS. On the Mac, SSH is the system ssh; on iOS it is Citadel.

macOS

The app's own machine list, as on iOS. When herdr is installed on this Mac, the Add Machine sheet lists its herdr machine list entries not added yet, checked when the app's list is empty. herdr on the Mac is needed only for This Mac's sessions (herdr session list). One ControlMaster per host, started on purpose, so there is one prompt per host. Agent and X11 forwarding are off; dial adds port forwards when needed. A bundled askpass script shows password prompts.

iOS

Machines in UserDefaults. A Secure Enclave key that cannot leave the phone. Host keys pinned on first use. The Mac is reached like any machine through Remote Login, over LAN or Tailscale.

A machine is one herdr session, so it is one entry in the machine list. Two sessions on one host share one SSH connection (ControlMaster), its channel limit, and nothing else: each session has its own events, streams and plugin state cleanup. A non-default local session is named "This Mac · ‹session›".

ssh -M -N -f -o ControlPersist=10m -o ServerAliveInterval=20 -o ForwardAgent=no -o ForwardX11=no \
    -o ClearAllForwardings=yes -S ~/Library/Caches/oriel/<h8> devbox          # start once
ssh -S ~/Library/Caches/oriel/<h8> -O check devbox                            # wait for it
ssh -F /dev/null -o ControlMaster=no -o BatchMode=yes -o ProxyCommand=/usr/bin/false \
    -S ~/Library/Caches/oriel/<h8> devbox -- sh -c '…' sh <BASE64>   # later runs: no fallback, no forwards
Details
  • <h8> is 8 hex characters of a hash of the SSH target, so the socket path stays under the 104-byte socket limit for user names up to 50 characters, with ssh's 17-character temporary suffix. The folder is per user, mode 0700.
  • Local Network privacy (macOS 15+): the app declares the usage string and opens an NWConnection to a LAN address first, so the system asks once.
  • All machines keep their control plane open; only the selected machine streams terminals. OpenSSH allows 10 sessions per connection (MaxSessions). The app opens channels when needed and counts none: when the server refuses one, it closes the least recently shown kept stream and tries once more; else the card shows Retry.
  • Health check: one per machine. The snapshot read is the heartbeat: every 30 s while healthy, every 2 s while failing. Automatic retries use BatchMode and never prompt, so a host that needs a password or a one-time code shows Reconnect.
  • Checks on connect, two steps: the snapshot (it carries herdr's version), then events. integration.list runs when the picker opens. If the server is not running: on a remote machine, Start herdr runs nohup herdr --session S server & over SSH. On This Mac, Start runs the server as a one-shot launchd job, so launchd, not the app, is its parent and its "responsible process" (macOS privacy prompts never name Oriel). The job gets the environment the app's herdr calls see (with the user's own PATH order), so server and CLI agree on paths.
  • iOS closes its terminal streams when the app goes to the background. It keeps the connection for about 30 s, then reconnects and re-reads the snapshot on return.

11Layout and sizing

herdr owns the split tree and its ratios. The app rebuilds the tree from the snapshot, draws it, and sends a new ratio when you let go of a divider. The app stores no sizes.

split right 0.55

Zoom, PTY size, selection and "seen"
  • If the rebuilt tree's leaf count differs from the pane count, the app falls back to layout.export.
  • Zoom is the app's own: herdr's pane.zoom moves herdr's focus, marks the tab seen and blocks moves.

Web page and remote localhost
  • The pane label oriel:web#<iid> <url> is the marker: it has no length limit, and it survives moves and restarts. A placeholder process holds the slot. The label keeps the address the user typed; the address after in-card navigation and the scroll position go in the machine's state file (web/<iid>.json), as for plugins. Header: Back, Refresh, Open in browser, Edit address.
  • When a page loads: a page you create or type loads at once and approves its origin for that machine. A card built from the machine (a fresh start, another device, a card an agent or the herdr TUI made) loads by itself if its origin is approved for that machine or on the safe list. Otherwise it shows Open ‹url›? once, and Open approves the origin.
  • Approvals and the safe list are a per-device setting, per machine. The safe list: the machine's own localhost and 127.0.0.1 on any port (always), and built in github.com, gitlab.com, bitbucket.org, developer.apple.com, developer.mozilla.org, docs.github.com, vercel.com, *.vercel.app, *.netlify.app. You can view and edit approvals and the list in Settings.
  • A remote localhost:P goes through dial. On the Mac: ssh -O forward -L on the ControlMaster, on the same port when it is free, so the page's origin is exactly localhost:P. On iOS: an in-app listener on 127.0.0.1:P pipes each connection into a Citadel direct-tcpip channel (a TCP stream through the SSH connection). Tailscale addresses load directly.
  • Open :P: when a terminal prints a local address (the app finds it in the terminal text it already streams for the selected tab), its card shows a chip that opens the address in a web card. The picker's web page entry also lists the machine's listening ports (ss or lsof), on demand.
  • One WebKit data store per machine. Loopback is blocked except that machine's own forwards.
The bridge 
oriel.run(argv)          → runs a command on the pane's machine
oriel.dial(host, port)   → a TCP stream to host:port, as seen from that machine

Also on window.oriel: the pane context, setArg, instance state, on("snapshot"), a signal after each snapshot read, with no data (a plugin that needs herdr data runs herdr with run), and preferences. The app never pushes into the page: it sends events only as replies to the page's own bridge calls (oriel.on waits on a pending call for the next signal). To open a link, a plugin uses a normal target=_blank link or window.open on a click, and the app asks first; to copy, it uses navigator.clipboard.writeText. Every pane kind uses the same two calls: the web page's localhost is a dial, Git history is a run of git. Full detail → Plugin API.

Security
  • One web view per card, bound to its pane's machine. run and dial go only there. A content rule and a Content Security Policy keep the page to its own files and scripts (no inline script, no eval; inline styles are allowed). Plugin code runs only while its card is alive; off screen, its calls pause.
  • Honest about run: a plugin with it can do anything you can do on that machine, including network tools and programs that keep running. The consent sheet says so.
  • Open and copy go through WebKit. A target=_blank click or a window.open from a click reaches the app, which shows a confirm sheet and opens the address itself; without a click WebKit blocks window.open. WebKit allows navigator.clipboard.writeText only during a click or key press. The app never runs script in a plugin page, because WebKit treats such script as a user action.
  • Every plugin gets run and dial. Finer rules ("only git") would not hold, so none are offered.
  • Consent at install, keyed by plugin id and source, in plain words: the plugin can run any command as you on the machine of every one of its panes (including ones others created), use the network from there and leave programs running; on This Mac that includes your files, SSH keys and connections to other machines. One more confirm on a plugin's first run or dial on This Mac, also keyed by id and source. The sheet is headed by the plugin id and source URL, not only the plugin's own title.
  • An id resolves core first, then a linked folder, then an installed plugin, so a plugin cannot replace a core one. The id web is taken by the web page's label.
  • A machine can write labels, so it can open any installed plugin on itself, which gives it only what the plugin does on that machine.
  • iOS v1 ships only the core plugins (terminal, agent, web, Git history, Diff, Markdown). Your own plugins on iOS are future work.

14Status, notifications and pills

The status area, notifications and pills all read the same snapshot. "Finished" comes from herdr's completion_seq, so the app sees a finish even when a herdr TUI watches the tab. Finishes that happen while the app is closed are not shown.

Finished, not seen = completion_seq != null && completion_seq != seen. herdr sets completion_seq when an agent goes from working or blocked to idle, and clears it to null on every other status change, so a finish shows only until the agent works again. herdr's own done is skipped when a herdr TUI is already looking at the tab, and the counter restarts at 0 with herdr.

Status comes only from herdr's API. herdr does not support OSC 7501 (a program status protocol) yet (draft PR herdr#5172), and under herdr the app never sees that sequence. Another multiplexer, where the app owns the terminal bytes, may use it.

Notifications
  • Blocked: "codex needs you · infra". Finished: "pi finished · api-server", unless you are looking at that pane. The first snapshot after connecting never notifies. A newer notification replaces the older one; seeing the pane removes it.
  • macOS: local notifications, and a Dock badge with the number of agents that need you. While the pill shows they are posted as .passive, except with VoiceOver or Switch Control.
  • iPhone and iPad: no push in v1. Status shows while the app is open, and in its ~30 s background time. A small stateless relay that forwards encrypted payloads to Apple's push service is Future work.

16Platform and code

One multiplatform SwiftUI target for macOS 26 and iOS 26, one main window, and three platform problems solved up front.

① Swipes get eaten

Terminal and web views take every scroll. A macOS NSEvent monitor locks the axis per gesture and gives horizontal motion to the strip; on iOS the terminal yields horizontal pans.

② Lazy views get destroyed

The PaneViewRegistry owns every terminal view, web page and plugin card; only the newest container may hold a view. Caps: ~24 terminals, 6 web views for web pages and plugin cards (2 on iPhone).

③ Shortcuts get eaten

libghostty binds ⌘T, ⌘W and ⌘D. Every surface gets keybind = clear, and keys go to the main menu first.

Tab bar, glass, signing, dependencies, tests
  • Tab bar: a row in the hidden title bar's line, holding a ScrollView of capsules. The marker is one glassEffect capsule that follows the strip's scroll offset; lit tabs come from the same number. gorex is the reference for how the tabs behave (sizes, overflow, status slot, window title), not for glass or SwiftUI: it draws with its own Metal renderer.
  • Frosted window: one behind-window NSVisualEffectView under a dark tint. Pane cards are translucent with a hairline border. Liquid Glass only on the tab marker, popovers and the palette. Pills are opaque.
  • macOS: Sandbox off, Hardened Runtime on, notarized Developer ID download. iOS: App Store.
