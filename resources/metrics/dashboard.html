What the phase agents said

Phase 10
  • Four rounds because each round's fixes (accessibility leaf, clipping, pill) surfaced the next should. Whole-suite e2e by the E2E reviewer was the decisive check; verifiers never found anything. A pre-existing test broke from other agents' stopped herdr sessions on this Mac. Glass colors depend on the wallpaper, so measurements needed the same desktop.
Phase 11
  • The scope changed twice mid-phase: the Settings window was built (round 1), redesigned at the user's request, then dropped; the phase became 'Font size and menus'. Most time went to a CI-only failure of the ⌘= step, chased through three wrong causes before CI logs (a debug PR) and a frame-by-frame read showed CI's 1x display rounds 14 and 15 pt to the same column count. osascript keys landed in the user's browser and Raycast once; the user then asked a reviewer to stop driving the Mac. The final full make e2e (37/37) ran at 44867ce; the last commit only changed the test and the monitor's key set and was checked on CI. CI run 39740270219 at e2465e1: green (lint, build, test-e2e).
  • Find the exact failing step and its values in the CI result bundle before guessing a cause. I read a CI failure as '⌘= is lost' when the frames showed the grid after ⌘+; three fixes (stale button, German layout, ⌘+ as ⇧⌘=) chased wrong causes. CI's display is 1x, so a 1 pt font step can keep the column count: grid tests must allow one side to stay.
  • Never send keys with osascript/System Events; Oriel lost focus and my keys landed in the user's browser and Raycast, and global hotkeys (⌥⇧B, ⌥.) broke a test far from the cause. Use XCUITest only, and avoid ⌥⇧ chords in tests.
  • Show a new window to the orchestrator as one screenshot before reviews: the Settings window took a full review round, a redesign and a removal. Build the non-window parts (font size, menus, defaults) first; they survived every change.
